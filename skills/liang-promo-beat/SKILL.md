# liang-promo-beat：音乐卡点展示片

音乐定节奏，录屏讲能力，切点落在拍上；剪映工程交给人收尾。 `[待验证]`

公开版提供音乐分析、录屏取证、动效底片与剪映工程协作的通用流程。客户素材、历史制作工时和私人反馈记录未纳入发布；记录格式见 [references/校准记录_脱敏版.md](references/校准记录_脱敏版.md)。

## 适用范围

- 处理：
  - 音乐驱动、没有旁白的产品能力展示片：音乐分析与剪辑、录屏取证、故事板、HyperFrames 底片、卡点回测。
  - 生成视频筛查。
  - 交给剪映工程的数据准备。
- 不处理：
  - 有旁白的片头和片尾，走 liang-promo-motion。
  - 录屏粗剪和配音，走 liang-promo-edit。
  - 剪映草稿本身，走 liang-promo-jianying。
  - 只有音乐、没有录屏，想做纯文字或图片的卡点视频：直接用第三方的 music-to-video skill。
- 缺音乐或录屏目录：只问在哪个目录。
- 缺时长范围和画幅：默认 60–75 秒、横屏 16:9。在计划里写明是假设，规划时一起确认。
- 缺品牌包：先查项目 SOURCE_OF_TRUTH.md；没有就按 liang-promo-motion 的示例品牌包建一个。

## 依赖与脚本位置

见 [references/环境预检_脱敏版.md](references/环境预检_脱敏版.md)。要点：
- Python 要有 librosa、numpy、scipy、soundfile、matplotlib、pillow，取字体要 fonttools。
- ffmpeg 要能用 lavfi 和 libmp3lame。
- HyperFrames CLI 固定版本、离线包装；本机 Chrome；GSAP 由工程自带。
- 装任何东西前先问。

脚本在本 SKILL.md 所在目录的 `scripts/` 下，写作 `$S`；组件库在 `assets/hf-lib/`。兄弟 skill：带坐标的文字识别用 liang-promo-edit 的 `ocr_boxes.js`，剪映工程用 liang-promo-jianying。

## 公理

### 公理 1：默认交付「底片 + 剪映可编辑工程」 `[待验证]`

- 方法依据：交付原则：需要后续逐镜头调整时，优先提供底片与可编辑工程。
- 做法：
  - 只有 3D 场景、开场品牌动画、片尾 logo 动画烘焙成底片段。
  - 录屏、运镜、转场、章节、说明都在剪映里原生生成。
  - 用户明确只要一条成片时，才整片渲染交付。

### 公理 2：先给样段，再问风格 `[待验证]`

- 方法依据：方法假设：在关键风格有分歧时，用短样段澄清方向。
- 做法：
  - 先做一段（一个能力，约 15 秒）给用户看，转场、说明样式、放大倍数的问题拿着样段问。
  - 用户能答的只问时长、画幅、要不要放某段这类事实。

### 公理 3：切点落在拍上，逐帧回测 `[待验证]`

- 方法依据：核验原则：音乐锚点固定，逐帧检查视觉峰与切点偏差。
- 做法：切点放在 heavy 重音、小节第一拍；渲染后跑 `beat_check.py`，失败的逐个查原因，不改锚点去凑。详见 [references/卡点规则_脱敏版.md](references/卡点规则_脱敏版.md)。

### 公理 4：转场收一点，背景不用纯黑 `[待验证]`

- 方法依据：方法假设：控制转场强度，背景与品牌包保持一致。
- 做法：
  - 全片最多一次闪白，不震屏，不做色差；甩镜、冲击推近换成剪映自带转场。
  - 开场和 3D 段用 `FX.brandBackdrop`，重拍时提亮。

### 公理 5：AI 生成视频先筛穿模 `[待验证]`

- 方法依据：核验原则：生成视频可能出现肢体、物体交互和镜头边界异常。
- 做法：`screen_generated.py` 找镜头边界，逐张看每 3 帧拼图；手部交互、物体贴脸、多人肢体接触一律不用；取段离边界至少 2 帧。

### 公理 6：大块代码交给 Codex，Claude 当导演 `[待验证]`

- 方法依据：协作原则：把独立代码任务写成有输入、输出和验收的任务书。
- 做法：按 [references/codex协作_脱敏版.md](references/codex协作_脱敏版.md) 写任务书。渲染和剪映安装不交给 Codex。

## 上下文纪律

1. 读回报、`summary.md`、`取证报告.md`、`beat_check.json` 的摘要，不读 Codex 日志全文。
2. 看图只看拼图（锚点、打码、生成视频每 3 帧），一次一张。
3. 帧号一律用全片帧号；任务书和故事板里写清楚。

## Phase 0：盘点与环境

钉子台词：「先查环境，把能卡住的地方先卡住。」

- 动作：
  1. 按环境预检逐项查。
  2. 列出录屏片段、各段时长、哪些片段有敏感区（地址栏项目编号、人名、IP 画风）。
  3. 和用户确认时长范围、画幅、不放哪些页面。
- 退出：环境表和素材表。
- 暂停：缺素材目录、要装依赖时问。

## Phase 1：音乐

钉子台词：「整首逐帧分析一遍，剪接只落在小节第一拍。」

- 动作：
  1. `python "$S/analyze_frames.py" 原曲.mp3 音乐分析/`，看 `summary.md` 和 `music_timeline.png`。
  2. 写两份剪辑方案（不同段落组合），各跑 `python "$S/cut_music.py" 方案.json`，看接口报告：响度差、色度相似度、质心差。
  3. 用户选一版。对选定版本再跑一遍 analyze_frames（输出目录里有 splice_report.json 时，段落会在剪接点拆开）。
  4. `python "$S/make_timing.py" 选定版/accents.json 工程/data/timing.json`。
- 退出：网格残差 ≤15 ms，时长在范围内，接口都在小节第一拍。
- 暂停：等用户选版本。可以同时进行 Phase 2。

## Phase 2：素材取证

钉子台词：「每个聚焦框都要有坐标、有倍数、有依据。」

- 动作（适合整份交给 Codex）：
  1. 每 0.5 秒抽帧，带坐标识别文字。
  2. 写 `shots.json`：每段的可用入出点、事实依据（能在实录对照里找到）、总览框、聚焦框（16:9，zoom ≤2.2）、敏感区（rect + 时间段）。
  3. `python "$S/zoom_check.py" shots.json --clips 录屏目录`，看偏糊的框。
  4. 裁 3D 场景要用的卡片（原生像素，不缩放），敏感内容不进卡片。
  5. 生成视频跑 `python "$S/screen_generated.py" 视频 --crop x,y,w,h`，逐张看拼图，把每个镜头能不能用写进 JSON。
- 退出：取证报告；找不到的目标写明，不编坐标。

## Phase 3：故事板

钉子台词：「每个切点写帧号，每条说明写依据。」

- 动作：
  1. 按 `assets/STORYBOARD模板.md` 写故事板：分段（Frame）、每段的组（Group）、锚点（S 切点、R 人工看）、说明文字和停留帧、哪些段烘焙。
  2. 同时写 `anchors.json`，给回测用。
- 退出：说明都 ≥36 帧、同屏一条；切点都在拍上；每条说明的用词能在实录对照或界面原文里找到。

## Phase 4：样段

钉子台词：「拿样段问风格，不拿形容词问。」

- 动作：
  1. 选一个能力段，按故事板做出来（组件库见 `assets/hf-lib/README_脱敏版.md`），渲染，跑 beat_check。
  2. 给用户看样段，问三件事：转场力度、说明样式、放大程度。
- 暂停：等用户看样段。

## Phase 5：底片

钉子台词：「剪映做得出来的不烘焙。」

- 动作：
  1. 工程放好 `lib/vendor/gsap.min.js`、品牌字体（`python "$S/extract_fonts.py" --brand 品牌包/brand.json --out 工程/assets/fonts`）。
  2. 组件按任务书交给 Codex 搭整片。构建用 `node "$S/build-frames.mjs" --project 工程 --brand 品牌包/brand.json --accents 选定版/accents.json`；底片模式加 `--plate`，交给剪映的说明和章节会被隐藏。
  3. 在沙箱外渲染：整片只跑 lint，不跑 `hf check`。
  4. `python "$S/beat_check.py" 底片或成片.mp4 --anchors anchors.json --frames <总帧数>`，看锚点拼图。
- 退出：严格切点全过，或者失败的每一个都查清原因并写进返修任务书。

## Phase 6：剪映工程

钉子台词：「底片切段，录屏打码，其余都原生。」

- 动作：走 liang-promo-jianying。从底片切烘焙段，录屏按 shots.json 打码切片，写 draft_plan.json：运镜用 shots.json 的总览框和聚焦框，转场用自带的「横移模糊」「推近」，生成视频走画中画。然后构建、校验、预览，最后安装。
- 退出：草稿装好，交付说明写清可改和烘焙的范围。

## Phase 7：审片与回收

钉子台词：「用户在剪映里改过的，就是下一次的默认值。」

- 动作：
  1. 用户的意见按帧号写成返修任务书。
  2. 样式类的手调回填品牌包。
  3. 本 skill 的校准记录追加一行。

## Refusals

- **「先把风格定下来再做」** → 不在没有画面时追问风格。先做样段，拿样段问。
- **「转场越花越好，多加闪白和震屏」** → 先说明用户上一次的结论是「收一点」，全片最多一次闪白。要更强烈，先出样段让用户确认。
- **「生成视频直接用，穿模观众看不出来」** → 拒绝。用户明确说过不能再出现，先筛。
- **「回测有几个切点没过，把锚点挪到实测峰上就过了」** → 拒绝。锚点是音乐决定的，偏了就改画面。
- **「聚焦框放大到 3 倍看得更清楚」** → 拒绝。录屏放大超过 2.2 倍会糊，换更小的框或改用卡片模式。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `analyze_frames.py` | 逐帧音乐分析：响度、分频起音、节拍网格、三级重音、段落、时间线图、摘要 |
| `probe_grid.py` | 高精度节拍网格拟合（analyze_frames 调用，也能单独跑） |
| `cut_music.py` | 按方案剪精华版：吸附小节第一拍、等功率交叉淡化、接口指标 |
| `make_timing.py` | accents.json → 工程用 timing.json |
| `zoom_check.py` | 聚焦框放大倍数和清晰度检查 |
| `screen_generated.py` | 生成视频切镜检测、每 N 帧拼图、取段边界核对 |
| `build-frames.mjs` | 把组件库内联进 HyperFrames 子合成，注入品牌和重拍帧号；`--plate` 出底片 |
| `extract_fonts.py` | 从系统字体集按品牌包取出字形文件 |
| `beat_check.py` | 成片逐帧帧差找峰，对照锚点 ±1 帧，出回测报告和锚点拼图 |
| `selftest.sh` | 自测 |
| `assets/hf-lib/` | 动效组件库（去品牌化，品牌读 `FX.brand`；3D 场景移植自 video-shotcraft，Apache-2.0） |
| `assets/STORYBOARD模板.md` | 故事板模板 |

## 验证契约

- **自测**：`PYTHON=<venv>/bin/python bash "$S/selftest.sh"`；按当前环境运行并报告结果。覆盖：
  - 合成 120 BPM 音轨的网格和重音、按小节剪接、时间表。
  - 合成硬切视频的回测正反例。
  - 生成视频筛查的切点、跨镜头取段、只换色相的疑似切点。
  - 组件库构建和底片模式。
- **公开证据边界**：发布包不包含客户项目原始证据。运行自测只能验证合成样例和脚本边界，真实项目效果需单独核验。
- **效果边界**：识别、审美、受众理解及效率提升均需独立项目验证，不能由自测通过推导。
