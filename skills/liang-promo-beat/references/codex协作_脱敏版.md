# 和 Codex 协作

卡点片可拆成音乐分析、取证、组件、合成和剪映导出等独立任务。主代理负责方案、验收与协作，执行任务的代理按任务书实现和自测；模型及权限以当前宿主为准。

## 什么时候交给 Codex

- 交：一个脚本超过一百行、要读大量源码规范（HyperFrames、shotcraft 参考）、要跑很多轮静态测试的活。
- 自己做：要看图判断的、要问用户的、改一两处参数的、渲染和安装（Codex 沙箱拦 Chrome，也不该碰剪映注册表）。

## 调用

```bash
cd <制作过程目录>
npx -y @openai/codex@0.163.0 exec --skip-git-repo-check -s workspace-write -C . \
  -o <任务目录>/codex_NN_回报.md "按 <任务目录>/任务书_NN_<名字>.md 完成任务。先完整阅读任务书和其中提到的参考文件再动手。" \
  < /dev/null > <任务目录>/codex_NN_日志.txt 2>&1
```

- 用后台运行，等完成通知，不轮询。
- 两个任务可以并行，但可写目录不能重叠，并在提示里写「另一个进程正在 X 下工作，不要碰」。
- 如果现有 CLI 与配置不兼容，先核对版本及宿主支持的调用方式。全局升级要用户同意。

## 任务书模板

```markdown
# 任务书 NN：<一句话>

工作目录：`<绝对路径>`（下称「制作过程」）。
- 可写：`<目录>/`
- 只读：`<目录>/`、`<目录>/`；原曲、原片、外置盘一律只读

## 背景
<为什么做这一步，上一步产出了什么。帧号都是全片帧号，30 fps，总长 N 帧。>
<用户已经确认的决定，逐条列出，例如：转场收一点；放大倍数保持；说明放下三分之一。>

## 环境
- Python：`.venv/bin/python`（已装 …）；ffmpeg：`…`；没有的东西不要装，沙箱不能联网。
- HyperFrames CLI：`tools/bin/hf`（离线、禁用遥测）。
- 沙箱会拦 Chrome：不要绕过。写好代码，让 `--static-only` 检查在沙箱里通过，渲染命令写进脚本，汇报里说明由我在沙箱外执行。

## 必读
<规范文件、参考实现、上一步的回报，列绝对路径>

## 要做的事
### 1. …
<具体到文件名、参数、帧号、坐标；用表格列段表、镜头表、转场表>

## 验收
- <可以机器检查的条件：帧数、lint 0 错误、哈希、数量>
- 最后用中文简短汇报：做了什么、哪一项没做到及原因、需要我在沙箱外执行的命令。不要粘贴大段代码和数据。
```

写法要点：
- 用户原话和帧号直接写进任务书，Codex 不知道对话上下文。
- 返修任务书按「现象（第几帧、看到什么）→ 改法 → 同时检查哪些同类位置」写，一条一个编号。
- 不确定能否实现的要求，写「做不到的写进汇报」，不要让 Codex 硬凑数字过验收。

## 审片循环

1. Codex 回报后，读回报和任务里的验收产物，不读全部日志（日志动辄 1–2 MB）。
2. 在沙箱外跑渲染命令。
3. 跑 `beat_check.py` 出卡点回测和锚点拼图，逐张看拼图。用户只看结果，不看过程。
4. 把发现的问题按帧号写进下一份返修任务书。

## 常见问题

| 坑 | 做法 |
|---|---|
| 沙箱拦 Chrome，`hf check`、`hf render` 都跑不了 | Codex 只保证 `--static-only` 通过；渲染在沙箱外 |
| `hf check` 整片在运行时检查超时（采样精简到 53 个、`--timeout 30000` 仍超时） | 整片只跑 lint，直接渲染，卡点用 `beat_check.py` 回测 |
| 排版审计把 3D 场景正常的前后遮挡报成错误 | 只给 3D 层和遮罩层加 `data-layout-allow-*`，二维文字不豁免 |
| Codex 剪的音乐接口落在 3 小节乐句上、色度相似度只有 0.80 | 接口吸附到 4 小节乐句起点，换剪接位置让相似度到 0.90 |
| 甩镜实测峰比锚点早 10 帧 | 组件约定峰帧语义，主要位移集中在锚点帧；见组件库 README |
