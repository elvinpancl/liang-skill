# 发布前检查

要检查两次：粗剪切完以后对单镜头片段查一次，剪映导出成片以后再查一次。「必须处理」那一栏清空以后才能发布。

## 自动检查（`qa_export.py`）

| 类别 | 内容 | 处理 |
|---|---|---|
| 必须打码 | API 密钥、邮箱、手机号、身份证号、本机用户路径。规则来自 liang-promo-footage 的 `scan_sensitive.py` | 在台本打码列补上坐标，重切这一段；或在剪映里遮挡，再重新导出 |
| 可选打码 | 编号（UUID，常见于租户 ID）、网址 | 看是不是内部地址，再决定要不要打码 |
| 画面瑕疵 | 输入法候选栏露出 | 裁掉、加速，或遮挡 |
| 字幕 | 产品名写法不统一、错字表里的错字、禁用词、超过 16 字的长句 | 改字幕；配音读错的地方，用备用写法重新生成配音 |
| 技术 | 时长和上限、分辨率、帧率、编码、响度、0.3 秒以上的黑场、1.5 秒以上的静音 | 对照包装规范 |

常用命令：

```bash
# 粗剪切完，先查单镜头片段
python3 "$S/qa_export.py" 粗剪/*.mp4 --out 制作过程/粗剪检查.md

# 剪映导出以后，查成片；剪映导出的 SRT 和成片放在一起，用同一个文件名
python3 "$S/qa_export.py" 成片.mp4 --out 发布前检查.md --cap 180 --term "<产品名标准写法>" --glossary 错字表.txt --strict
```

## 人工检查

- 报告里标出来的时间点，逐个看画面确认。打完码重新导出，重新跑检查，直到「必须处理」那一栏是空的。
- 没被标出来的画面也要整体过一遍。字号很小、截断的长串、斜体，都可能识别不出来。
- 每句能力说法都要能在画面里找到。旁白里有和事实不符的说法，要改掉，例如把「所有公司」说成了「全公司」。
- 每次换身份，旁白都点到了。
- 结尾预告的下一篇确实存在。
- 已经发布的视频如果漏了密钥：先作废密钥、换新的，再重新导出、替换视频。光替换视频不够，因为视频可能已经被下载或转存。
