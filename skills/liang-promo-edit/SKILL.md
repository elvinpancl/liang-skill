# liang-promo-edit：品宣剪辑

画面定了再写旁白。AI 负责找、切、写、查，精剪留给人。 `[待验证]`

公开版提供镜头索引、粗剪、旁白排时、成片检查与复盘的通用流程。客户原片、成片、项目指标与私人反馈不随 Skill 发布；默认参数和记录格式见 [references/校准记录_脱敏版.md](references/校准记录_脱敏版.md)。

## 适用范围

- 处理：软件产品演示类品宣片，从「录完、取证完」到「成片发布」这一段。包括镜头索引、剪辑台本、粗剪、旁白字幕、开头结尾、包装清单、发布前检查、复盘校准。
- 不处理：
  - 拍前规划，走 liang-promo-plan。录屏核对和配图，走 liang-promo-footage。品宣文章，走 liang-promo-article。
  - 剪映里的精剪：放大关键帧、转场、音效、选配音音色由人做，本 skill 只提供片段、字幕和清单。
  - 口播类视频（原片自带人声），剪辑逻辑在逐字稿里，不归本 skill。
  - 已经被剪映打开过的工程文件，一律不改（加密）。要把粗剪、字幕、章节直接落进一个新的剪映草稿，交给 liang-promo-jianying 生成。
  - 动画化的开头、结尾、叠加动画，走 liang-promo-motion；音乐卡点片走 liang-promo-beat。
- 缺原片目录：暂停，只问「原片在哪个目录」。
- 缺篇目或时长上限：默认每篇不超过 3 分钟，开场 27 秒、解法页 12 秒，在台本开头写明这个假设。
- 没有取证结果（实录对照）：照常做索引。台本里每个镜头能不能用，靠识别文字自己判断，交付时说明。

## 依赖与脚本位置

- **ffmpeg**：2018 年的版本也能用。时长和分辨率从 `ffmpeg -i` 的输出读，不需要 ffprobe。旧版 ffmpeg 的 fps 滤镜接在 setpts 后面会让加速失效，所以脚本统一用 `-r` 定帧率。
- **macOS**：文字识别用 osascript 调系统 Vision，脚本是 `ocr_boxes.js`，输出带坐标。在其他系统上，索引只算画面变化（`--no-ocr`），发布前检查跑不了。
- **Python 3**：只用标准库。
- **liang-promo-footage**：打码规则复用它的 `scan_sensitive.py`。按「同一安装根目录下的兄弟 skill」去找，找不到会提示先安装。

脚本在本 SKILL.md 所在目录的 `scripts/` 下，下文写作 `$S`，路径里有空格时记得加引号。

## 公理

### 公理 1：画面定了再写旁白 `[待验证]`

- 方法依据：方法假设：先确认画面与结果，再写旁白，可降低文案和素材不匹配的风险。
- 反例：纯动画或纯 PPT 的片子，画面是照着稿子做的，可以先写稿。
- 复核：每个项目都看旁白沿用率，连续两个项目低于 50%，就重新审视旁白写法。

### 公理 2：人在文字上把关，不在视频上返工 `[待验证]`

- 方法依据：方法假设：优先在台本和旁白阶段校对，避免渲染后才发现结构错误。
- 做法：前三个项目都先确认台本，再切粗剪。镜头覆盖率连续两次达到 70% 以后，可以关掉这道确认。
- 反例：制作人明确说「先切出来再看」。
- 复核：每个项目记下台本改了几行、粗剪重切了几次。

### 公理 3：AI 的产出只当可选输入 `[待验证]`

- 方法依据：技术边界：烧录进视频的运镜和转场难以局部修改；已被剪映打开的工程可能加密，应保留可重建的计划。
- 做法：
  - 单镜头片段保持干净，只把打码烧进去。
  - 放大另外出一份备选，转场只做进预览片。
  - AI 选错的镜头，制作人照索引自己找。最坏的情况也只是回到原来的手工流程，不会更慢。
- 可编辑交付：通过 liang-promo-jianying 生成新的明文草稿，运镜、转场、章节和说明尽量保留为剪映原生图层：
  - 台本定稿后，可以把粗剪片段、字幕、章节、放大关键帧直接生成一个新草稿，人在剪映里只做精剪。
  - 这条路还没在录屏品宣片上跑过，标 `[待验证]`，先在一篇上试，对比剪映编辑时长。
- 复核：复盘时问制作人哪些产出没用上。连续两个项目都没用上的产出，就不再生成。

### 公理 4：成片发布前必须逐秒扫打码 `[待验证]`

- 方法依据：核验原则：打码需要在粗剪后和成片导出后分别检查，不能只依赖计划中的承诺。
- 反例：无。
- 复核：每个项目记下扫出几处、人工补查又发现几处。

### 公理 5：规则只在复盘时集中改，并设止损线 `[待验证]`

- 方法依据：方法假设：用镜头覆盖、旁白沿用和编辑时长观察流程是否有帮助。
- 做法：
  - 每个项目做完复盘一次，把差异写进 references，不在单条视频里来回调规则。
  - 每次复盘打三个分：镜头覆盖率、旁白沿用率、剪映编辑时长。
  - 某一步连续两个项目低于 50%，或者编辑时长没有下降，这一步就降级成「只出建议」。止损表在校准记录里。
- 复核：每次复盘看一遍止损表。

## 上下文纪律

1. **读识别文字和索引，不整批看图。** 需要看画面时，用 ffmpeg 的 tile 滤镜拼成缩略图总览，一次不超过 20 张。例如：`ffmpeg -i 粗剪预览.mp4 -vf "fps=1/2,scale=384:-2,tile=5x5" -frames:v 1 总览.jpg`。
2. **识别会漏字，抽帧会漏画面。** 台本要用的结论在索引里找不到时，回原片按时间点导一帧核对，不凭印象写。
3. **产物放哪**：见「产出位置」。

## Phase 0：盘点接力

钉子台词：「先算清每篇能放多少秒，再挑镜头。」

- 输入：
  - liang-promo-footage 的交接：实录对照、身份、不可用段。
  - 计划：篇目、时长上限、贯穿案例。
  - 开头结尾素材：PPT 或放映录屏。
  - 术语表。
- 动作：
  1. 每篇算正文预算：上限减去开场加桥接（默认 27 秒），再减去解法页（默认 12 秒），默认值见校准记录。
  2. 正文能写的字数，约等于预算秒数 × 4。
  3. 列出每篇的段落，每段写一句观众问题。
  4. 不在这一步写逐镜头配音稿。
- 退出：每篇都有段落表和秒数预算。
- 暂停：缺原片目录时问一句；外置盘未挂载时提示接入；其余不暂停。

## Phase 1：镜头索引

钉子台词：「先让机器把五十分钟看一遍，人只看它挑出来的几十秒。」

- 输入：要用的原片目录。不可用的段可以不放进来。
- 动作：运行 `python3 "$S/index_clips.py" <原片目录>... --out 制作过程/索引 --jobs 3`。
  - 每段原片会切成一串动作段，每个动作段写明：起止时间、之后静止多久、有没有等待或打字、哪里要打码（带坐标）、新出现了哪些文字，以及建议保留的区间。
  - 静止段和等待段就是可以剪掉的部分，合计时长写在索引开头。
- 退出：生成 `镜头索引.md`。
- 暂停：不暂停。

## Phase 2：剪辑台本

钉子台词：「台本是文字，改十遍也比重剪一遍快。」

- 输入：镜头索引、实录对照、Phase 0 的预算。
- 动作：按 [references/剪辑台本模板.md](references/剪辑台本模板.md) 写 `剪辑台本.md`，每个镜头一行。
  - 只用实录对照里标「可用」的段。报错、空数据、看不到结果的段不用。
  - 每个操作保留「动作开始，到结果出现后再停 2–3 秒」。从索引的建议保留区间起步。
  - 静止和等待剪掉，用叠化接上。打字用 3–4 倍速，或者只留最终状态。
  - 换身份的地方标闪黑。索引里标了要打码的段，把坐标抄进打码列。
  - 放大列写放大区域，音效列写点击、键盘、翻页、唰。旁白列先空着。
  - 合计时长超过预算时，先删段落，不要压缩每个镜头里结果停留的时间。
- 退出：台本每行都有原片和出入点，合计时长在预算以内。
- 暂停：前三个项目要停一次。把台本摘要（段落、镜头数、合计时长、删了什么）交给制作人确认，确认意见改进台本。之后按止损线决定要不要保留这一步。

## Phase 3：粗剪

钉子台词：「切片交给脚本，人只挑和调。」

- 输入：剪辑台本。
- 动作：
  1. 运行 `python3 "$S/build_roughcut.py" 剪辑台本.md --src <原片根目录> --out <本篇目录>`，输出：
     - `粗剪/NN_段落.mp4`：去掉声音、统一 60 帧、已加速、已打码。
     - `粗剪/放大备选/`：静态放大或推近的版本。
     - `粗剪预览.mp4`：960×540，带叠化和闪黑，用来看节奏。
     - `制作过程/粗剪索引.json`：每段在预览片里的起止时间。
     - 只改了几行台本时，加 `--only 3,5,8` 只重切这几段。
  2. 对单镜头片段跑一遍检查：`python3 "$S/qa_export.py" 粗剪/*.mp4 --out 制作过程/粗剪检查.md`。
     - 「必须处理」不为空时，补上打码坐标，用 `--only` 重切，直到清空。
     - 打码框的坐标来自取样帧。页面滚动或弹窗消失时，框可能盖偏，抽几帧看一眼。
- 退出：粗剪检查的「必须处理」为空，预览片时长在预算以内。
- 暂停：不暂停。

## Phase 4：旁白与字幕

钉子台词：「对着画面写，一句一行，念完正好切走。」

- 输入：粗剪预览、粗剪索引、[references/旁白写法_脱敏版.md](references/旁白写法_脱敏版.md)。
- 动作：
  1. 对着预览片和台本，逐个镜头在旁白列写句子，句与句之间用「／」隔开。写法按旁白写法：8 到 14 字一句，跟着画面，先操作、再结果、再价值，去掉数字和细节，换身份时点一句。
  2. 运行 `python3 "$S/make_subtitles.py" --index 制作过程/粗剪索引.json --script 剪辑台本.md --out <本篇目录> --cap 180 --fixed 39 --chapter "<章节标签>"`。
  3. 根据报告调整：
     - 报「旁白超出画面」：删字，或者把出点往后挪。挪了出点要用 `--only` 重切这一段。
     - 报「画面比旁白多」超过 1.5 秒：补一句，或者剪短画面。
     - 退出码是 2 说明还有超出，改完再跑，直到退出码为 0。
- 退出：退出码为 0，生成 `字幕.srt`、`文本朗读稿.txt`、`读音检查表.md` 和 `包装清单.md`。
- 暂停：把旁白和预览片一起交给制作人修改。制作人直接改台本的旁白列，改完重跑第 2 步。

## Phase 5：开头结尾与包装

钉子台词：「卡片什么时候亮，由那句旁白什么时候念决定。」

- 输入：PPT 每个动画状态导出的图（或者放映录屏），以及开场、桥接、结尾的旁白。
- 动作：
  1. 写一张对照表，三列：状态图、旁白、最短停留。运行 `python3 "$S/render_slides.py" 对照表.md --out 开头.mp4`，结尾同理。
  2. 制作人想自己录放映时，照 `制作过程/开头_排时.md` 里「亮起」一列的时间翻页。
  3. 只有放映录屏、没有逐张导出的状态图时，先运行 `python3 "$S/render_slides.py" --from-video 放映录屏.mp4 --states 制作过程/状态图 --dedupe`。它会取出每个停住的状态，并写好一张状态表；给要用的行填上旁白，再按第 1 步渲染。
  4. 系列共用开场只做一次。完整版去掉后面各篇的开场和桥接。
  5. 包装清单在 Phase 4 已经生成，按 [references/包装规范_脱敏版.md](references/包装规范_脱敏版.md) 在剪映里完成精剪。
  6. 开头要做成动画（人物演痛点、品牌开场、界面依次点亮），不是 PPT 状态翻页时，交给 liang-promo-motion：同样按旁白时间表排时、出 SRT，品牌从项目品牌包取。
- 退出：开头、结尾的视频和 SRT 都已生成，包装清单齐全。
- 暂停：不暂停。

## Phase 6：发布前检查

钉子台词：「一个密钥漏出去，前面省下的时间全赔进去。」

- 输入：剪映导出的成片，同名的 SRT 放在旁边。
- 动作：
  1. 运行 `python3 "$S/qa_export.py" 成片.mp4 --out 发布前检查.md --cap 180 --term "<产品名标准写法>" --glossary 错字表.txt --strict`。
  2. 按 [references/发布前检查_脱敏版.md](references/发布前检查_脱敏版.md) 做人工检查。
- 退出：「必须处理」为空，人工检查做完。
- 暂停：有必须处理的项时，把时间点清单交给制作人。制作人回剪映处理、重新导出后，再跑一遍。

## Phase 7：复盘校准

钉子台词：「这次怎么改的，下次就不用再改。」

- 输入：剪辑台本、字幕.srt、成片和剪映导出的成片 SRT、剪映工程目录、镜头索引。
- 动作：
  1. 比旁白：运行 `python3 "$S/retro_compare.py" --ai 剪辑台本.md --final 成片.srt --skip-until "<桥接句里的几个字>" --video 成片.mp4 --draft <剪映工程目录> --out 复盘数据.md --json 制作过程/复盘数据.json`。
  2. 比镜头：运行 `python3 "$S/reverse_edl.py" 成片.mp4 --index 制作过程/索引 --script 剪辑台本.md --from <开场结束时间> --to <解法页开始时间> --out 制作过程/逆向剪辑表.md`。
  3. 在 [references/校准记录_脱敏版.md](references/校准记录_脱敏版.md) 追加一行，对照止损线打分。
  4. 写规则修改提案，交给制作人：
     - 新写的句子按类型归类。
     - 被删掉的句子找出共同点。
     - 镜头选择上的差别：成片用了哪些台本没选的段，又删了哪些台本选了的段。
     - 制作人同意以后，再改旁白写法、包装规范和剪辑台本模板。
- 退出：校准记录追加了一行，规则修改提案有了答复。
- 暂停：规则改动要等制作人确认；数字直接记录。

## 产出位置

每篇一个目录。人直接打开的放在顶层，工具读写的放在 `制作过程/`。

`<篇名>/` 不放在本机内容项目里，按项目 SOURCE_OF_TRUTH.md 的外置盘位置放，例如 `产品素材/<产品>/粗剪片段/<批次>/`。动手前先用 `diskutil info <Volume UUID>` 确认盘已挂载，再拼出路径；不能只看盘名，也不能在本机建同名目录代替。盘不在时，不依赖盘的文字工作照常做，到读写视频这一步再提示接入。项目还没有位置记录的，先看它在盘上现有的分类，定下位置后写进索引。

```
<篇名>/
├─ 剪辑台本.md
├─ 粗剪/NN_段落.mp4，粗剪/放大备选/
├─ 粗剪预览.mp4
├─ 字幕.srt，文本朗读稿.txt，读音检查表.md，包装清单.md
├─ 开头.mp4，开头.srt，结尾.mp4，结尾.srt
├─ 发布前检查.md，复盘数据.md
└─ 制作过程/：索引、粗剪索引.json、排时报告.md、预览片段、粗剪检查、对照表、逆向剪辑表
```

## 交接

从 liang-promo-footage 只读这几项：`fact_base`（实录对照）、`ocr_dir`、`roles`、`unusable`。识别原文里的邮箱、手机号这类个人信息不往下传。

成片发布以后，如果还要写文章，交给 liang-promo-article：

```yaml
liang_handoff:
  from: liang-promo-edit
  final_video: <成片路径>
  final_subtitles: <成片 SRT>
  script: <剪辑台本路径>
  qa_report: <发布前检查路径>
  evidence_level: 结果已验证
  next: liang-promo-article
```

## Refusals

- **「先发了，打码回头再说」** → 拒绝跳过发布前检查。敏感信息一旦被转存，替换视频无法撤回已传播副本；应先完成检查和必要打码。
- **「直接改剪映工程文件，把台本灌进去」** → 已有的工程拒绝改：被剪映打开过就是加密的，改坏了会打不开，只读 `draft_settings` 和 `key_value.json`。要把台本落进时间线，用 liang-promo-jianying 按台本生成一个新名字的草稿，旧工程不动。
- **「这段回答失败了，剪掉报错的部分当成功的用」** → 拒绝。品宣片是对外的，一句对不上画面的话就是事故。要么重录，要么在台本里删掉这段。
- **「把剪映素材库里的音效导出来，混进片段里」** → 拒绝。素材库音效的授权只限在剪映里使用。音效只出时间点清单；制作人提供有授权的本地音效文件时，再考虑混进片段。
- **「几百帧都给我过一遍」** → 拒绝整批看图。上下文装不下，早先看过的图会被清掉，结论反而不可靠。按上下文纪律读识别文字，必要时拼成缩略图总览。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `index_clips.py` | 镜头索引：动作段和静止段、等待、打字、要打码的坐标、新出现的文字、建议保留区间 |
| `ocr_boxes.js` | JXA 调 Vision 识别中英文，输出坐标 |
| `build_roughcut.py` | 按台本切单镜头片段（加速、打码），出放大备选和带转场的预览片 |
| `make_subtitles.py` | 旁白排时：出 SRT、文本朗读稿、读音检查表和包装清单，报超出和空档 |
| `render_slides.py` | 把状态图按旁白渲染成开头结尾，同时出 SRT 和翻页排时表；也能从放映录屏里取出每个状态的图 |
| `qa_export.py` | 发布前检查：逐秒识别找打码项，检查字幕写法和技术参数 |
| `retro_compare.py` | 复盘：旁白沿用率、语速、字数变化、剪映编辑时长 |
| `reverse_edl.py` | 逆向剪辑表：成片对应的原片区间、各段原片用量、镜头覆盖率 |
| `_common.py` | 共用工具：探测时长、时间格式、识别、表格解析、带转场的拼接、读校准记录里的默认值 |
| `selftest.sh` | 自测 |

## 验证契约

- **自测**：`bash "$S/selftest.sh"`；按当前环境运行并报告结果。没有 ffmpeg 或不是 macOS 时，相关项会跳过。
- **公开证据边界**：发布包不包含客户项目原始证据。运行自测只能验证合成样例和脚本边界，真实项目效果需单独核验。
- **效果边界**：识别、审美、受众理解及效率提升均需独立项目验证，不能由自测通过推导。
