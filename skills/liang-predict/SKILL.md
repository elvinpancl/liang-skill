# /liang-predict — 打分与立卡

不敢在发布前白纸黑字写下预测的判断，都是马后炮。这里把「我感觉能火」变成一张赖不掉的卡。

## 跨宿主执行能力

以下适配只用于本文件原生轻量流程，不改写所引用的第三方完整工作流。Task、Agent、Read、AskUserQuestion 在本轻量流程中是能力名称，不要求某一宿主的同名工具。Claude Code 使用可用的 Task/Agent；Codex 使用可用的子代理接口，例如 `collaboration.spawn_agent`。盲评分必须创建不继承父对话的干净上下文（该接口显式设 `fork_turns="none"`），只传本文件规定的白名单材料；默认继承当前模型，不擅自降级或指定其他模型。等价工具可用时照常完成，不因缺少名为 Task 的工具中止。只有所有可用接口都无法满足干净上下文和输入隔离时，才按原有降级规则处理，绝不把受污染的主对话评分写进校准池。

路径或参数已在本任务上下文中明确时直接使用并核验，不重复询问。已授权目标持续有效；依赖用户裁定的部分暂停时，继续完成不依赖该裁定的准备与验证。

## 完整模式分流

先检查 `.liang-content-state.json`：

- 存在：读取并执行 [完整校准工作流](references/full-calibration-workflow.md)，本文件后续的轻量流程不再重复执行。
- 不存在：继续本文件的 liang v1 轻量流程。

完整模式仍受本文件两条更严格的边界约束：

1. `liang_handoff` 只允许消费 `draft`、`platform`、`structure_id`、`selected_version`；证据等级、案例实绩、倍率和 `structures_脱敏版.md` 不得进入盲评分器。
2. 所有预测写入 `bets/`，并由 `tools/seal-guard.sh` 保护封存段。完整工作流里若出现更宽松的改写规则，以 seal-guard 的行为测试为准。

## 第一步 查档

在当前目录跑 `test -f scorecard.md && echo 有 || echo 无`：

- 有：只读入评分卡这一份，ledger.md 现在不开（为什么，见第二步），直接进第二步。老档案只有 scorecard.md 没有 ledger.md 的，按文末模板补建 ledger.md，把 scorecard.md 里残留的基线行和观察段搬过去再继续。
- 无：首次建档。问两件事（允许答「不知道」）：
  1. 做的是什么内容（视频 / 文章 / 播客 / 图文）？发在哪？
  2. 最近 5-10 篇的典型数据量级是多少（播放 / 阅读）？拿它的中位数当基线；一篇没发过就写「未定基线」。
  然后创建 `scorecard.md`、`ledger.md`（模板都在文末）和 `bets/` 目录，基线答案写进 ledger.md。若当前目录是 git 仓库，提醒 `bets/` 值得入库（预测史是资产），基线等敏感数字自己斟酌。再提醒一句：本 skill 自带 seal-guard hook，能把封存段的不可改从自律升级成机器强制，注册方法见本 skill `tools/` 目录和 README；不装也能用，只是封存全靠自觉。

## 第二步 打分

读成稿（参数没给路径就问）。主对话全程只许开两个文件：稿子和 scorecard.md。ledger.md 和 bets/ 里全是实绩的影子，打分前看了它们，分数就从「这稿子值多少」变成「上次考了多少」。赌档位要用的基线，等分数落定再去拿。

若上一步带来 `liang_handoff`，主对话只消费 `draft`、`platform`、`structure_id` 和 `selected_version` 做稿件定位与版本核对。`evidence_level`、案例实绩、基线倍率和 `structures_脱敏版.md` 内容不得进入子代理 prompt；handoff 不是评分输入。定位完成后，子代理仍然只收到稿子内容和评分卡维度。

主对话先按评分卡逐维在心里估一份分，不念出来也不落盘，只用于下面的分歧对照。

打分本身交给一个干净上下文的子代理。为什么：主对话在长对话里可能已经听用户提过实绩、夸过某篇、抱怨过数据，这种污染纪律挡不住，隔离才挡得住。用 Task 起子代理，prompt 里只放三样：

1. 稿子路径，明说只许 Read 这一个文件
2. 评分卡当前版本的维度定义与权重，用通用语言写全，不让子代理去读 scorecard.md
3. 输出格式：每维 0-5 整数分配一句具体到稿子内容的理由（不写「还行」「不错」这种空话），附加权综合分（保留一位小数）

同时明确告诉它：禁止读 bets/、ledger.md、scorecard.md、structures_脱敏版.md 和项目里任何其他文件，禁止提问。发出前把 prompt 自查一遍，不许含播放量、倍率、档位、爆款、哑火、证据等级这类实绩或历史标签。

分回来后逐维对照主对话的心估：

- 每维差距都小于 2：直接采用子代理的分。
- 任一维差 ≥ 2：把分歧维度列成表弹给用户裁——信子代理（隔离干净但没有对话上下文）、信主对话（上下文多但可能被污染）、还是用户自己给分。

落盘的永远是子代理的分或裁定后的分，主对话的心估不落盘。有裁定时预测段记一行：`分歧裁定：<维度> 子代理 X / 主对话 Y → 取 Z（<子代理|主对话|用户>定）`；无分歧不记。

没有任何可满足上述隔离条件的子代理接口时才明说：本次退化为控制台打分（主对话自己打，只输出不写文件），不立卡不进校准池。没有别的降级路径，校准池里的分必须是盲的。

用户如果先透露了这篇的实际数据（已经发过了），赌注的盲性已破，本次只打分不立卡，明说原因。

## 第三步 赌档位

分数落定，这时才打开 ledger.md 拿基线。档位赌的是相对自己基线的倍数，不赌绝对数：

| 档位 | 含义 |
|---|---|
| 哑火 | 不到基线一半 |
| 常规 | 基线上下（0.5-2 倍） |
| 出圈 | 基线 2-10 倍 |
| 爆款 | 基线 10 倍以上 |

押分布前先找锚点：翻 bets/ 里「已复盘」的卡，取综合分和本篇最接近的一两张（差 0.5 以内优先，没有就取最近的），把它们当时的综合分和实际落点摆在眼前——同分的卡上次落在哪，就是这次分布最硬的参照。一张已复盘的卡都没有就跳过，卡上锚点行写「无」。

给四个档各押一个概率，加总必须是 100；赌的档位就是概率最高的那一档。概率是逼自己诚实的工具：最高档通常落在 40 到 65 之间，四档摊平等于承认没有判断，最高档给到 90 以上必须说出硬理由，说不出就压回 65 以内。

再给一个中枢：最高档内部的点估计，写成基线的倍数（基线有具体数字就顺手换算成量级）。复盘算偏差幅度就靠它。

「未定基线」时不做分布和中枢，只赌方向（高于 / 低于自己前几篇）加信心（低 / 中 / 高），并注明基线待定。

最后是一句话赌注：说清楚这个分数和这个分布之间的推理，特别是哪个维度是胜负手。

赌注之外再写两行反事实：若实际比赌的高一档，说明哪个判断被推翻；若低一档，又是哪个。这两行是事前留给复盘的把柄——事前不写，事后就只剩编故事。

有锚点就再押一个对照赌注：本篇实际结果是锚点卡的几倍，写清差到多少算输、输了推翻哪个判断。档位有半档宽的余地可以赖，对一张具体旧卡押倍数赖不掉。无锚点不押。

- 立卡日：YYYY-MM-DD

- 发布链接：
- 发布时间：
- 复盘到期：

## 预测（封存段：落笔即封，只许整段追加 v2，不许改动一字）

| 维度 | 分 | 一句理由 |
|---|---|---|
| … | … | … |

综合分：X.X（评分卡 vN，子代理盲打）
分歧裁定：<维度> 子代理 X / 主对话 Y → 取 Z（<谁>定）（无分歧则不写本行）

## 同稿重预测

同一份稿子已有预测卡、稿子又改过：先走 /liang-drift 算两版漂移分。

- 绿区（0-15）：原卡继续有效，不重打。
- 黄区（16-40）：核对胜负手维度有没有变，变了才追加 v2。
- 红区（41-100）：基本是新稿，在原卡追加 `## 预测 v2` 整段重打。v1 原文一字不动。

## Refusals

- **先说数据再要预测** →「先告诉你实际播放，你反推个预测」直接拒。马后炮进不了校准池。
- **改封存段** → 预测段写完不许改，理由再好也只许追加 v2。写错了也留着，写错本身就是校准数据。
- **迎合期望分** →「你把钩子那项打高点」拒。分数是评分卡给的，对评分卡不满走 /liang-bump。
- **打分前先看账本** →「先看看基线和之前的观察再打」拒。基线是赌档位用的，观察是 bump 用的，都不是打分的输入。打分只认稿子和评分卡。锚点旧卡同理，分数落定前不翻。
- **跳过子代理** →「别起子代理了，你直接打」可以打，但只输出不落盘不立卡。校准池只收盲分，主对话的分做不到盲。
- **分布凑不齐 100** → 概率加总不是 100 不落盘，改到加总 100 为止。
- **只给档位不给分布** → 拒。单押一个档位赖得掉，四档各押多少赖不掉，分布就是为了赖不掉。
- **张口就是 95%** → 最高档超过 90 必须给硬理由，给不出就压回 65 以内。每张卡都「非常确定」，等于每张卡都没想。
- **只想打分不立卡** → 可以，控制台输出完整打分但不写文件，明说这次不进校准池。
