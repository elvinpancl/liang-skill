# /liang-status — 预测看板

闭环最怕的死法是卡立了没人回来对。看板存在的意义就一个：把「该复盘了」怼到你眼前。

## 完整模式分流

`.liang-content-state.json` 存在时，读取并执行 [完整状态看板工作流](references/full-calibration-workflow.md)，展示 mode、rubric、buffer、候选池、迁移提示和 adapter 健康度；完成后不再重复执行下方轻量流程。状态文件不存在时继续下方 liang v1 流程。

两种模式都只读，不修改状态或补登记。

## 流程

只读。当前目录没有 scorecard.md 就指去 /liang-predict 首建，别的什么都不说。有 scorecard.md 没 ledger.md 的老档案，提一句去 /liang-predict 补建账本。

1. 读 scorecard.md（版本、复盘窗口、升级门槛）和 ledger.md（基线、观察条数）。
2. Glob `bets/*.md`，逐张读 header 的状态和日期行。
3. 今天的日期用 `date +%F` 取，算每张「已发布」卡到没到复盘到期。
4. 「已复盘」的卡再读复盘段的「事前概率」行，取均值当押注成色。一张带分布的卡都没有（全是老卡）就不算、不显示这行。

## 输出

```
评分卡：vN | 基线 <数字或未定> | 观察攒了 N 条

卡池：共 N 张
  已预测 X ｜ 已拍 X ｜ 已发布 X ｜ 已复盘 X

⏰ 待复盘（按到期先后）：
  <卡名> 到期 MM-DD（已过 N 天 / 还差 N 天）
  （没有就写：无，很干净）

命中率：已复盘 N 张，档位赌对 X 张（X/N）
  高估 X 次 ｜ 低估 X 次
  押注成色：实际档位的事前概率均值 X%（带分布的 M 张；全是老卡则无本行）

下一步：<按情况给一句>
```

「下一步」的判法，从上往下取第一个命中的：

- 有过期未复盘的卡 → 喊「复盘 <最早那张>」
- 「已拍」的卡积了 3 张以上 → 该发了，拍而不发攒不出校准
- 已复盘数够升级门槛且观察 ≥ 3 条 → 可以考虑 /liang-bump
- 卡池全空 → 拿最新成稿走 /liang-predict
- 都没有 → 继续写稿，闭环很健康

## Refusals

- **只读**：不改状态、不补登记、不代跑复盘。看板顺手想改什么，指到对应 skill 去。
- **不算命**：看板只报事实和计数，不在这里给「下一篇会不会爆」的判断，那是 /liang-predict 的事。
