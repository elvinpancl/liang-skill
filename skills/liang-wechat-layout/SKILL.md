# liang-wechat-layout：公众号排版

样式固定下来，每篇只花心思挑哪几句标橙。 `[待验证]`

默认版式取自一篇公众号文章（https://mp.weixin.qq.com/s/60GDijbHktEFMI6ptp-pdw ），卡片版式取自一篇企业号文章的配色和组件，都在 2026-10-22 抓取原文 HTML 实测，规格见 [references/样式规格.md](references/样式规格.md)。还没有在公众号后台真实粘贴验证过，所以粘贴后哪些样式能保留标待验证。

## 适用范围

- 处理：把定稿（Markdown 或纯文本）排成这套样式，给预览页和一键复制。
- 不处理：
  - 写稿、改稿、润色。写品宣文章走 liang-promo-article，其他稿子走已装的写作类 skill。
  - 别的版式风格（杂志、文档、课程讲义等），走 dbs-wechat-html。
  - 标题、封面和开头的打磨，交给已装的对应 skill。
  - 登录公众号后台、上传图片、发布。
- 缺稿件：只问一句「稿子在哪」。

## 公理

### 公理 1：只加标记，不改字 `[待验证]`

- 来源：用户全局规则，排版整理只转换格式，不改原文字词、标点和顺序。
  - 挑重点只加 `**`。
  - 稿里没有小节标题时不自创，列建议标题让用户选。
- 反例：用户明确要求顺手改稿时，先出 `*_改写版.md`，定稿后再排。
- 复核：交付前把标记稿去掉 `**` 后和原稿 diff，必须一致。

### 公理 2：橙色只给少数句子 `[待验证]`

- 来源：参考文章的用法观察。每节 2 到 4 处，落在小节首句的论点、转折句、小节收束句和全文最后一句。
- 规则：高亮段落不超过全文段落的三成，脚本超过时给提示。
- 反例：不到 8 段的短文，1 到 2 处就够。
- 复核：发布后看留言和转发截图引用的句子，是否落在橙色句上。

### 公理 3：粘贴进后台的只有行内样式 `[待验证]`

- 来源：dbs-wechat-html 记录的兼容规则，复制网页时 `<style>` 和 class 会丢。本 skill 的片段全部是行内样式，没有 class、id 和脚本。
- 待验证：斜角（transform）和 flex 并排在后台粘贴后是否保留。被清掉时退化为直角色块或上下排列，仍然可读。
- 旁证：卡片版式参考的那篇已发布文章，正文 HTML 里渐变底、左边框、圆角和 inline-block 都在。那篇不是用本 skill 的片段粘的，只能算旁证，卡片版式本身没有斜角和 flex。
- 待验证：嵌在正文里的图片（base64）粘贴后后台能否收下。社区记录是能显示，本机还没在后台实测；收不下就用 `--no-embed` 出占位框，改为手动插图。
- 复核：第一次真实粘贴后，在 [references/样式规格.md](references/样式规格.md) 的「粘贴验证记录」登记结果。

## 稿件写法

| 写法 | 排出来 |
|---|---|
| 第一个非空行 `# 标题` | 只当标题，不进正文，填到后台标题栏 |
| 一行一段，空行可有可无 | 正文段落；第一个小节之前的是导语，行高更紧 |
| `## 小节名` | 编号小节标题，01、02 按顺序自动编；标题自带的「01」「一、」「1.」会去掉 |
| `### 小标题` | 蓝色加粗短标题 |
| `**整句**` 或 `**半句**` | 橙色加粗重点 |
| 单独一行 `![说明](https://…)` | 通栏图片 |
| 单独一行 `![说明](配图/01.png)` | 路径相对稿件所在目录。嵌进页面（宽度超过 1440 的缩到 1440，格式不变，截图用 PNG），随正文一起复制；找不到文件或加 `--no-embed` 时出灰色占位框 |
| `> 引用`（可连续几行） | 左侧蓝线的引用块 |
| `- 列表项` | 带「·」的普通段落 |
| `---` | 一处空行 |

卡片版式（`--theme card`，或主题里写 `"layout": "card"`）和上表不同的地方：

| 写法 | 卡片版式排出来 |
|---|---|
| `# 标题` | 照样填后台标题栏，正文开头另有一张标题卡：浅色渐变底，每个分句一行，最后一句用强调色 |
| `## 小节名` | 小号「01」在上，标题在最靠中间的逗号处断两行，后一行用强调色 |
| 整段 `**……**` | 浅色底、左侧色条的提示框，黑色加粗 |
| 全文最后一段整段 `**……**` | 收尾卡：和提示框同一种淡色底，强调色字居中，不带左侧色条 |
| `**半句**` | 强调色加粗 |
| 连续的 `- 列表项` | 合进一个底色框，每项前面一个「▸」 |
| `> 引用` | 底色框，14px |

## Phase 1：收稿

钉子台词：「标题进标题栏，正文从导语开始。」

- 输入：定稿路径，或贴进来的正文。贴进来的先存成 `<项目目录>/制作过程/<稿名>_原稿.md`。
- 动作：
  1. 确认第一行是 `# 标题`。没有就用文件名当标题，交付时提醒。
  2. 数一下 `##` 小节、`**` 重点和配图行。
- 退出：知道标题、小节数，以及有没有重点标记。
- 暂停：不暂停。

## Phase 2：标记

钉子台词：「只加星号，不动一个字。」

- 输入：Phase 1 的稿件。
- 动作：
  1. 稿里已经有 `**`：照用，不增删。
  2. 没有 `**`：按公理 2 挑重点句。把原稿复制成 `制作过程/<稿名>_标记稿.md`，只在这份上加 `**`。
  3. 没有 `##` 且全文超过 1500 字：列 3 到 5 个建议小节标题和插入位置，问一次要不要加。不加就按无小节排，全文用正文样式。
  4. 配图：本地图片保留 `![说明](路径)`，渲染时嵌进页面；已经有公网地址的写 https 地址。
  5. 打码：图片会随正文直接发出去。项目有打码清单的，逐张核对；密钥、token、IP 和地址、手机号、邮箱、真实用户名先打码。原图移到同目录的 `原图/` 保留，打码图放回原路径，稿件不用改。清单以外拿不准的（公司名、非演示数据），列出来问用户。
- 退出：标记稿去掉 `**` 后和原稿一致，用 diff 核对；必打码的图都处理完。
- 暂停：第 3 步需要用户选；第 5 步拿不准的项问用户，不阻塞排版。

## Phase 3：渲染

钉子台词：「静态检查不过，不交付。」

脚本在本 SKILL.md 所在目录的 `scripts/` 下。不确定装在哪时，查 `~/.claude/skills/liang-wechat-layout/scripts/`，下文写作 `$S`。

1. 跑 `python3 "$S/render_wechat.py" <标记稿或原稿> --open`。
   - 输入在 `制作过程/` 里时，预览页写到上一级目录，名为 `<稿名>_公众号排版.html`，去掉「_标记稿」。其他情况写在稿件旁边，或用 `--out` 指定。
   - 换版式：加 `--theme card` 用卡片版式。
   - 换品牌色：新建一个主题 JSON，只写要改的键（例如 `accent`），其余沿用默认；要卡片版式就再写 `"layout": "card"`，没写的键沿用 `themes/card.json`。用 `--theme <路径>` 指定。某个账号专用的主题放在项目目录里，不放进 skill。
   - 标题卡上方的标签行（账号名、系列名）写在主题的 `title_card_label`，空着就不出。
2. 改到输出「静态检查：通过」为止。检查项包括没有 `<style>`、class、id、脚本，每块都有字号和行高，图片都是公网地址，小节编号连续，`**` 没有残留。
3. 脚本提示重点超过三成时，回 Phase 2 减。

## Phase 4：交付

钉子台词：「点一下按钮，去后台粘贴。」

预览页是单个 HTML 文件，图片在里面，可以直接转给发布的人。正文栏和公众号网页版一样宽（最宽 677px 居中，白底），两侧衬微信界面的底灰，电脑上看到的就是读者在网页版看到的正文；窗口拉窄到手机宽度，就是手机上的样子。两个复制按钮固定在顶栏，滚到哪都能点。

要边改边看时加 `--watch`：脚本起一个本机预览服务（默认 http://127.0.0.1:8765/ ，被占就换一个），稿件、主题或配图一保存就重排，打开的页面自动刷新并停在原来的位置。磁盘上的预览页同时更新，不带刷新脚本，照常转给别人。别人手里的文件不会跟着变，改完要重新发。

告诉用户这几件事：
1. 预览页路径（已打开）。也可以让我加 `--copy` 直接把正文写进剪贴板（仅限 macOS，脚本会回读核对）。
2. 公众号后台新建图文，点 ① 复制标题粘到标题栏，点 ② 复制正文粘到正文区，等图片都显示出来再保存。
3. 有占位框的（找不到的图），在占位框位置插图后删掉占位框。照脚本输出列出清单。
4. 封面、摘要、公众号名片和原创声明在后台设置。
5. 用手机预览，看小节色块、橙色重点和图片。图清不清楚以手机预览为准：公众号发给读者的图最宽 1080 像素，还会再压一遍，手机上差不多一比一，电脑上看（Windows 的 1 倍屏缩小显示，Mac 的 2 倍屏放大 1.25 倍）都会比原图糊，所有公众号文章都这样。整窗截图缩到正文宽度后字只有原来的四成大，要读者看清字，就裁出局部再排。

预览页转给用 Windows 的同事也能用：提示里的快捷键按系统显示 Ctrl 或 Cmd；按钮复制失败时，正文会保持选中，直接按 Ctrl+C。不要让人自己全选整页，那样会把顶栏和预览标题一起复制进去。

第一次在后台粘贴后，问用户斜角、渐变底和嵌入的图片还在不在，把结果登记到样式规格的「粘贴验证记录」。

## Refusals

- **「顺便把这几句改顺一点」** → 拒绝在排版时改字。排版稿和原稿对不上，公理 1 的 diff 核对就失效了。先出 `*_改写版.md`，定稿后再排。
- **「直接用原文那两张模板图」** → 拒绝引用原文的壹伴模板图片。那是第三方的模板素材，挂在别人的素材库里。本 skill 用行内 CSS 重画了同样的形状。
- **「图先不打码，直接嵌进去发」** → 拒绝把带密钥、地址、邮箱这类信息的图嵌进正文。嵌进去就会随复制直接发出去，发布的人不会再逐张看。先打码，原图另存。

## 验证契约

- **自测**：`bash "$S/selftest.sh"`，52 项全过，含图片嵌入、宽图缩到 1440 且 PNG 不转 JPEG、按系统显示快捷键、`--no-embed`、预览页正文栏宽度和两侧底灰、卡片版式各组件、`--watch` 改稿后自动重排。
- **公众号怎么处理图片**（2026-10-22 至 23，旁证）：反查一篇已发布文章。正文图的 `/640` 规格返回 1080 宽；Mac 2 倍屏的网页版也加载这一档，显示 677px，放大 1.25 倍。浏览器里实际加载的是有损 WebP（1.4 MB 的 PNG 变成 116 KB），原图链接里 JPEG 约质量 80。所以嵌图不转 JPEG，免得多压一次。粘贴进后台的 base64 图是不是走同一条处理，还没在后台验证。
- **踩过的坑**（2026-10-23）：照公众号的 1080 把嵌图缩到 1080，预览页在 Mac 上放大 1.25 倍，用户反馈比原来糊，当天改回 1440。2 倍屏下截同一张图对比，1440 的字边明显更清楚。
- **卡片版式视觉对照**（2026-10-22）：390px 和 1440px 宽度下和参考文章对比。正文 15px、行高 1.85、段后 18px，小节标题、提示框、收尾卡的尺寸和颜色一致；长标题、长收尾句在手机宽度下只在标点处折行。
- **视觉对照**（2026-10-22）：390px 手机宽度下和原文截图并排对比。小节标题高 40px，与原文一致；正文字号、字距、行高、段距一致；长标题换行后色块不变形。
- **剪贴板**（2026-10-22，本机）：`--copy` 以后回读剪贴板，HTML 和纯文本两种类型都在，HTML 与片段一致；预览页按钮复制成功，没有脚本报错。
- **真实稿件**（2026-10-22，端侧一体平台公众号文章）：7 张截图嵌入后页面 1.9 MB，浏览器里 7 张都加载、宽 1280；复制出去的片段和页面正文逐字一致；两个复制按钮都成功。
- **没验证的**：在公众号后台真实粘贴后，哪些样式保留、嵌入的图片能不能收下、外链图片能不能转存。这三项没有声明已验证。
