# liang-transcript-mine：录音与抖音增量挖掘

本 Skill 把来源列队、去重和阅读记录交给脚本，逐篇提取交给新开的子代理，主线程只读摘要。默认每周提取、两周合并；实际运行频次由用户决定，本 Skill 不自动创建定时任务。

**公开版前提**：先按 [README.md](README.md) 配置自己的知识库、母版与处理契约。不包含私人语料、真实订阅配置和云端发布集成；缺配置时停止依赖步骤并说明缺项。脚本目录 `S` 取当前 `SKILL.md` 同目录下的 `scripts/`，不得猜测作者安装位置。下文命令写作 `python3 "$S/xxx.py"`。

## 上下文纪律（违反任何一条都会把 token 打回原形）

1. **母版不整份打开。** 母版较大时，只用 `card_locator.py` 的 `find`／`grep`／`get` 取一个模块或一条洞见；提取和校验时带 `--run <运行目录>`，按开轮快照定位。
2. **不读旧运行的脚本和长 JSON。** 需要的能力都在 `$S` 里；缺能力就补脚本，不去 `cat` 上一轮的 `publish_core.py` 之类。
3. **流水线状态只从 `run_init.py` 取**，不翻 Codex／Claude 的长期记忆找路径和规则。
4. **一个子代理任务只处理一篇长稿，或 `next` 合好的一批短稿。** 子代理必须是新开的空白上下文，不能分叉（fork）或继承主线程历史；最多 3 个并行；子代理只回一行。
5. **脚本输出只看摘要。** 明细都在运行目录的文件里，需要时按行号取片段。
6. **不看图片和视频帧。** 逐字稿缺内容按规则判待补或不入库，不靠截图补。
7. **每轮新开会话。** 不在上一轮的长线程里接着跑。

## 流水线

### 1. 开轮

```
python3 "$S/run_init.py"
```

输出运行目录、本轮模式、母版路径、契约路径、发布锁和返工指示，共十几行。母版的路径和哈希会记进 `运行状态.json`。返工流程可能在一轮中途换掉正式母版，这一轮的提取和校验仍按开轮快照定位，避免候选错位。

本轮模式由脚本按双周节奏决定，照它走：

- **候选模式（候选周）**：距上次发布不足 13 天。做第 1 到第 5 步，写本轮结果后结束；不改正式稿、不发布、不提交来源状态。
- **合并模式（发布周）**：距上次发布满 13 天。第 3 步会沿用本周期候选周的成果，做完第 5 步后按第 6 步合并发布。
- 全量返工尚未发布时一律是候选模式。只有用户明确要求本周就发布，才用 `run_init.py --mode 合并`。
- 发布锁被占用：照常取来源、出候选、更新案例库，不碰正式稿和飞书。

### 2. 取抖音新作（可选、只读）

仅在用户配置并授权 Get 笔记读取时执行；否则跳过，直接列队本地逐字稿。

```
python3 "$S/getnote_fetch.py" list
python3 "$S/getnote_fetch.py" fetch
```

`list` 按真实作品 ID 去重：已处理台账、历史清单和已落盘原文都会比对。「有历史清单无原文」的作品单独列出，要不要补取由你判断。接口失败就写「未完成」，不能写成「无新增」。只有 Get 笔记订阅拿不到时，才用 gstack browse 看账号主页，而且只读文字。

`fetch` 把原文和 AI 摘要写进 `语料库/<账号>/抖音研究/<日期>/逐字稿/`，下一步列队时它们以新来源进入队列；候选周取到的作品，发布周也还在队列里。

### 3. 列队

```
python3 "$S/source_queue.py" build            # 旧标准来源：长稿每轮 10 份、短稿 40 份，--stale-budget／--stale-short-budget 调整
python3 "$S/source_queue.py" next --n 3
```

`new`、`changed` 和抖音新作全部入队；`stale` 指旧标准处理过、需要按新标准重读的来源，按预算分批处理，其余顺延，并在报告里写明剩余数。`build` 同时做三件事，输出里各有一行：

- **同场去重**：对同一场录音的重复转写计算片段重合度。默认阈值 0.25 是需用本地数据校准的启发式参数；重合达到该值 的保留较长一份，另一份标 `duplicate_of`、不派提取，发布后随主稿一起提交。新稿明显更全时照常提取，只提示合并时避开已写过的部分。
- **短稿合批**：9000 字以内的来源一块就能读完，`next` 把它们按 15 篇、4 万字合成一个子代理任务，编号用逗号连起来。
- **沿用候选**（仅发布周）：本周期候选周已读完、文件和提取标准都没变的来源，直接拷入阅读记录和候选，不再重读。

### 4. 提取（子代理）

对 `next` 列出的每一行，开一个**新**子代理，只发下面这一行（换成实际的脚本目录、运行目录和编号；合批时编号是逗号连起来的一串）：

> 你是提取子代理。先运行 `python3 "<脚本目录>/source_queue.py" prompt --run "<运行目录>" --id Q003`，严格按它输出的指令完成，最后只回一行。

完整指令在 [references/extractor_prompt_脱敏版.md](references/extractor_prompt_脱敏版.md)，由子代理自己取出（变量已填好）。主线程不贴这段两千多字的指令：每派一个子代理就贴一次，这些字会一直留在主线程上下文里重发。

- Claude Code：用 Agent 工具开 general-purpose 子代理，它默认就是新上下文。
- Codex：开子代理时选择不 fork、不带历史的方式；只传上面这一行。

子代理读完全文（短稿用 `read_source.py --ids … --pack` 一次读几篇），阅读记录会自动写成全文阅读凭证。读完后用一次 `probe` 查完所有案例，再用一次 `getmany` 取出要对照的模块，调用预算是「读取次数加 8 次」。不要每个案例单独查母版：全文一直留在子代理的上下文里，多查一次就多重发一遍全文。候选写到 `候选/<QID>.jsonl`，子代理自己先校验，再回一行摘要（含调用次数）。主线程收到后跑：

```
python3 "$S/source_queue.py" status
```

没读完的来源留在队列，不标完成。直到 `next` 没有剩余，或本轮预算用完。

### 5. 校验、分组、更新案例库

```
python3 "$S/candidates.py" validate
python3 "$S/candidates.py" group
python3 "$S/case_bank.py" build
```

`group` 生成 `工作清单.md`，按打法卡和模块、洞见、方法节分组。抽查一条最复杂的候选：用 `read_source.py --lines` 回看原文，确认谁、问题、建议、为什么都对，卡号和模块也放对了。字段定义见 [references/candidate_schema_脱敏版.md](references/candidate_schema_脱敏版.md)。

`case_bank.py build` 把配置起始日期以来各轮的完整案例重建进 `直播录音资料/案例库/`（打法、洞见、方法与其他三份），每条标明和三库的关系。候选周的新案例显示「待发布周裁定」。

候选周到这里结束，跳到第 7 步。

### 6. 裁定、合并与发布（仅发布周）

- **裁定**：子代理判「已覆盖」的先采信为候选判断并抽查对应来源；不能把历史准确率当作当前保证；「值得补充」「新内容」「待补材料」逐条裁定。结果写 `<运行目录>/裁定/<QID>.json`，格式见 candidate_schema 的「主线程裁定」。裁定后再跑一次 `case_bank.py build`，案例库的状态随之更新。
- 正文写法只认 `运行状态.json` 里 `contracts.正文写法` 指向的现行契约。来源、发布和状态提交按 `contracts.来源与发布` 执行。本 Skill 不重复契约内容，契约更新后自动跟随。
- 合并时逐个目标位置处理。先 `card_locator.py get --id N` 读 SOURCE_OF_TRUTH 当前母版里的整张卡或整条洞见（合并写进当前母版的新版本，所以这里不带 `--run`），再把新材料融进去，不在末尾贴段；同一模块里说明同一要点的案例只留最有用的一个，其余留在案例库。`candidates.py group` 如果提示开轮后母版已换版，或沿用候选来自母版快照不同的候选周，就按编号在新版重新核对每条候选的去向。写进新的日期版本文件，旧版保留。改完跑 `card_locator.py verify --kind <k> --file <新稿>`，确认编号、模块和洞见标签完整。
- 本公开版不包含私有 `reader_gate.py`；以 `candidates.py validate` 的提示和项目正文契约核对实际改动。新读者验收按 [references/reader_prompt_脱敏版.md](references/reader_prompt_脱敏版.md)。
- 云端写入只在已有授权范围内由单一发布者执行，自动审批拒绝时不换工具绕过。本公开版不提供发布适配器；缺集成时交付本地候选并明确云端发布未完成，不查找作者的历史脚本。
- 来源状态（`processed_source_hashes.tsv`、`douyin_processed_aweme_ids.tsv`）只在正文和飞书双端验收通过后才提交：本轮读完且没有待补的来源、沿用的来源、同场重复的那一份都一起提交；抖音作品同时写哈希基线和作品台账。不运行旧的 `rebuild_source_baseline.py`。

### 7. 收尾

```
python3 "$S/source_queue.py" status
python3 "$S/token_report.py" --since <今天日期>
```

在运行目录写 `本轮结果_改写版.md`，内容包括：本轮模式（候选周／发布周）；读完多少篇、各篇读到哪里、顺延多少篇；同场重复拦下几份、短稿合了几批、沿用几份；候选统计、工作清单路径和案例库新增条数；失败与待重试项；本轮 token 用量（主线程和子代理分开写）。状态没变、也没有需要处理的结果时保持安静；有实质更新、失败或需要用户操作时才通知。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `run_init.py` | 开轮：建运行目录，按双周节奏定模式，汇总母版、契约、返工状态和发布锁；`--status` 只看不建，`--mode` 仅在用户要求时覆盖 |
| `getnote_fetch.py` | Get 笔记只读获取用户配置账号的新作原文，原文和 AI 摘要分开存进语料库账号目录 |
| `check_source_increment.py` | 只读扫描配置的原文，输出与已提交基线的差异，不提交状态 |
| `source_queue.py` | 来源队列：`build`（含同场去重、沿用候选）／`next`（长稿一篇一个、短稿合批）／`status`，不输出正文；`prompt` 给子代理输出填好变量的提取指令 |
| `read_source.py` | 分块读来源，自动记全文阅读凭证；`--ids … --pack` 一次读几篇短稿；`--lines` 回看片段 |
| `card_locator.py` | 母版按卡、模块、洞见（含标签）、方法节读取；`probe` 一次查多组关键词，`getmany` 一次取多个位置；`--run` 用开轮快照；`verify` 核结构 |
| `candidates.py` | 校验候选（含双重限定、作者禁令提醒），按目标分组成工作清单 |
| `case_bank.py` | 从各轮候选和裁定重建本地案例库 |
| `token_report.py` | 按运行统计 Codex 和 Claude Code 的 token，用于前后对比；`--detail` 逐个列子代理，起步上下文很大就是分叉了 |
