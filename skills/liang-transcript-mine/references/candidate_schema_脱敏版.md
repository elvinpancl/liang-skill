# 候选字段

子代理把每篇来源的结果写成 `<运行目录>/候选/<Q编号>.jsonl`，一行一个 JSON 对象，一个对象对应一段**完整**问答或案例，不按句拆。短稿合批时，每篇来源各写一个文件。整篇没有可用内容时，文件里写一行 `target_kind: "none"`、`disposition: "不入库"` 或 `"已覆盖"` 的记录说明原因，不留空文件。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `<Q编号>-<两位序号>`，如 `Q004-01` |
| `source` | 是 | 来源相对路径，与队列里的 `path` 一致 |
| `lines` | 是 | `[起, 止]`，`read_source.py` 输出的原始行号，覆盖整段问答 |
| `who` | 是 | 谁来问、做什么生意、在什么阶段（一句） |
| `problem` | 是 | 遇到什么问题，补充了什么情况 |
| `advice` | 是 | 讲者最后怎么建议；中途改口的，写最后的建议并在 `ledger_note` 记改口 |
| `why` | 是 | 讲者给的理由 |
| `quote` | 否 | 最有用的一句原话，120 字以内 |
| `nature` | 是 | `连麦建议`／`讲者观点`／`讲者自述`／`他述案例`／`实测结果`／`方法演示` |
| `target_kind` | 是 | `tactics` 打法／`insights` 洞见／`method` 方法／`none` 无处安放 |
| `target_id` | 视情况 | 卡号、洞见号或方法节号（整数）；材料足够撑起七模块的新交易才写 `"new"` |
| `target_sub` | 视情况 | 打法必填模块号 1–7；洞见可填 `判断`／`逻辑`／`边界`／`动作`／`怎么讲`；方法留空 |
| `new_title` | `new` 时必填 | 拟定的卡名或洞见标题 |
| `disposition` | 是 | `已覆盖`／`值得补充`／`新内容`／`不入库`／`待补材料` |
| `covered_by` | `已覆盖` 时必填 | 同一案例或同类判断已经写在哪里，如 `卡1·模块7`、`洞见1·逻辑`；`值得补充` 的案例如果别处已写过，也要填，防止重复写入 |
| `missing` | `待补材料` 时必填 | 缺什么、可能从哪里补（如「转写在第 812 行断开，下一场开头接着讲」）；写不出补充途径的，不判待补 |
| `draft` | `值得补充`／`新内容` 时必填 | 按现行「正文写法」契约写好的正文段，三五句讲清谁、问题、建议、为什么；段末可带一个短证据标记如「〔连麦建议，未回访〕」，有了标记就不再加「不能据此……」 |
| `reason` | 是 | 为什么放这里（或为什么已覆盖、为什么不入库、为什么待补），一句 |
| `ledger_note` | 否 | 只进台账的内容：改口、失效数字、转写疑点、核查过程 |
| `carried_from` | 脚本写 | 发布周沿用候选周成果时由 `source_queue.py build` 写入，子代理不填 |

模块放置提示（摘自契约）：多数案例放模块 4 或 5；接咨询的放模块 6；验证和停手的放模块 7。只有几句话的新来源挂到最相关的现有卡当例子，不新建卡。

`candidates.py validate` 按本表校验；`draft` 里出现「原转写」「本次改写」「不补造」「不冒充」「未知」「待问」等写作者提醒、段末有标记又写「不能／不等于／不代表」、或出现「不能把 X 写成 Y」这类写给作者的禁令，都会给提醒。

## 主线程裁定

发布周由主线程裁定，结果写 `<运行目录>/裁定/<Q编号>.json`：一个数组，每项是该候选的原字段，加两项：

| 字段 | 说明 |
|---|---|
| `decision` | `采用`／`已覆盖`／`不入库`／`重复来源`／`待补材料` |
| `decision_reason` | 一句理由；采用的写清放进哪个位置、补了什么 |

子代理判 `已覆盖` 的直接采信，抽查一两条即可；`值得补充`、`新内容`、`待补材料` 逐条裁定。`case_bank.py build` 按这份文件给案例库标「已写入／同类已有／缺材料／未入三库」，格式不对案例库就只能显示「待裁定」。
