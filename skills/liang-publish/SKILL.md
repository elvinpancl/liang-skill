# /liang-publish — 发布登记

预测卡只有钉上发布时间，复盘的钟才开始走。这是个轻动作：登记元数据，别的什么都不做。

## 完整模式分流

`.liang-content-state.json` 存在时，读取并执行 [完整发布登记工作流](references/full-calibration-workflow.md)，完成平台识别、平台 ID、buffer 和 state 更新；不得再重复执行下方轻量流程。状态文件不存在时继续下方 liang v1 流程。

无论哪种模式，都只允许修改 header 与状态数据，`## 预测` 封存段一个字不动。

## 第一步 找卡

按参数在 `bets/` 里定位预测卡（路径直接用；给的是标题关键词就 Glob 加 Read 匹配）。找不到就列出现有卡让用户挑；`bets/` 都没有，说明这篇没立过卡，指去 /liang-predict——没有盲预测，发布登记没有意义。

## 第二步 判动作

- 「拍了 / 录完了」：header `状态：已预测` 改成 `状态：已拍`。完事。拍和发是两个时刻，中间可能隔很久，也可能毙掉不发。
- 「发了」：继续第三步。

## 第三步 核对稿版

问一句：实际发出去的，和立卡时那份稿子是同一版吗？

- 同一版：继续。
- 改过：建议先 /liang-drift 比一下立卡稿和实发稿。红区（41+）意味着预测赌的根本不是发出去的这篇，提示去 /liang-predict 追加预测 v2 再回来登记；黄区口头确认胜负手维度没变即可。用户不想比也放行，但在 header 加一行 `- 稿版：发布版与立卡版有出入，未量化`。

## 第四步 登记

日期用 `date +%F`。改 header 四行：

- `状态：已发布`
- `发布链接：<链接>`（没有链接的平台记平台名 + 标题）
- `发布时间：<今天或用户给的日期>`
- `复盘到期：<发布时间 + scorecard.md 里的复盘窗口>`

收尾一句：到期那天喊「复盘」走 /liang-retro，或随时「预测状态」看 /liang-status。

## Refusals

- **顺手改预测段** →「顺便把赌注那句话改顺一点」拒。本 skill 只碰 header 元数据行，封存段一个字不动。
- **补登没立卡的发布** → 不造卡。没有事前预测，事后登记只是记流水账，指去 /liang-predict 给下一篇立卡。
- **一张卡登记两次发布** → 已是「已发布」的卡再来登记，先问是不是发错卡了；确认是重发 / 多平台分发，在 header 追加 `- 分发：` 行，不覆盖首发信息。
