# liang-persona：结构性人群洞察

## 目标

把「谁可能感兴趣」收敛为「谁正被什么处境推到行动临界点」，再解释他为什么会借这个产品获得现实进步、心理回报或身份变化。

核心世界观：

> 分析人在特定环境和购买决定中表现出的心理结构，不给整类人判定永久性格。

具体人群结论一律接受反证。理论负责提出问题，客户证据负责回答问题。

## 适用范围与路由

- 处理：目标付费人群、购买处境、决策张力、深层购买任务、产品支点、目标身份与一句话画像。
- 不处理：账号现有观众由谁构成、哪些评论人群反复出现。此类任务走 `/liang-content-persona`。
- 不处理：市场规模、媒介偏好、人口统计抽样、临床人格诊断。
- 可服务内容定位、产品设计、销售访谈与交付边界判断，但不替这些工作流直接做最终决策。

缺少「具体卖什么」或「希望谁采取什么行动」时暂停，只问一个最小问题：

> 你具体卖什么，谁付钱或做决定，交付后希望他发生什么变化？

用户明确要求先给初步判断时，可以带假设继续，但必须标 `[待验证]`，并列出最可能推翻判断的信息。

## 理论底座

按一条链路使用四个成熟视角：

1. **场域**：先看人和环境的关系，不从行业、年龄或身份标签直接推导性格。
2. **进步任务**：找到什么事件让旧办法失效，以及用户此刻想取得什么进展。
3. **价值阶梯**：沿「产品属性 → 功能结果 → 心理或社会结果」追问，停止在证据能支持的层级。
4. **可能身份**：判断用户想摆脱哪种当前状态、成为谁，以及最怕成为谁。

需要解释理论来源、出现多角色购买、或初稿仍然空泛时，读取 [analysis-philosophy.md](references/analysis-philosophy.md)。需要跨行业校准与反例时，读取 [calibration-cases.md](references/calibration-cases.md)。

## 证据纪律

### 证据等级

| 等级 | 可以确认 | 不可以确认 |
|---|---|---|
| `[结果已验证]` | 某人实际购买、拒绝、续费、流失、使用或说过某句话 | 该动机导致了购买，或所有同类人都如此 |
| `[相关性待验证]` | 多个案例反复出现同一触发、替代方案、异议或行为组合 | 已证明因果，或可直接推广到全行业 |
| `[待验证]` | 单个案例、创始人判断、竞品文案或理论推演形成的假设 | 把推断写成目标人群的内心事实 |

让语气匹配等级：

- `[结果已验证]`：写「已观察到某个行为发生」，仍不把动机写成已证明因果。
- `[相关性待验证]`：写「多个案例反复出现」「当前观察到同向关系」。
- `[待验证]`：写「当前更可能」「最值得验证的假设」。不写「真正、必然、一定、都、从不、归零」等绝对判断。

### 来源优先级

按以下顺序取证：

1. 真实购买、未购买、续费、退款、流失与使用行为。
2. 销售通话、客户访谈、客服记录和客户原话。
3. 已尝试方案、预算、时间表、场地、权限等行动证据。
4. 搜索、评论、社群讨论和行业观察。
5. 创始人直觉、竞品文案、人口标签。

低优先级来源可以生成假设，不能单独证明深层心理。

数字必须带来源和口径。用户或资料没有提供时，不擅自补价格、时长、频次、比例、概率和样本量，并把缺失数字列入待验证项。「小额、高价、很快、频繁、极少」同样需要比较基线，不能用模糊量词绕过数字纪律。

## 工作流

### Phase 0：锁定商业对象

钉子台词：「先把卖什么、谁付钱、为什么现在买钉住。」

- 输入：产品或服务、价格或投入门槛、购买者、使用者、交付终点、现有证据。
- 动作：区分付钱者、使用者、受益者、建议者与否决者；明确本次分析的是哪一个角色。
- 退出：得到一个具体产品、一个目标行动和一个主要决策角色。
- 暂停：产品与目标行动均不明确时，只问最小问题，不生成画像。

### Phase 1：拆开伪同类人群

钉子台词：「同一个标签下，只要触发事件和购买任务不同，就不是同一种客户。」

- 输入：用户给出的行业标签、人群名单、客户样本与业务资料。
- 动作：按「触发事件＋硬约束＋旧办法＋想取得的进步」聚类，不按年龄、职业或地域直接聚类。
- 动作：优先选择问题阶段与交付能力相匹配，同时具备行动条件的群体；痛苦强烈但无购买能力、决策权或交付适配度的人不自动成为核心客户。
- 退出：得到一个核心因果群体，或两个至三个互不兼容的候选群体。
- 暂停：候选群体的购买任务明显冲突且用户只要一个答案时，展示分歧并请用户选择分析对象。

### Phase 2：还原结构性处境

钉子台词：「处境要能解释为什么偏偏现在行动。」

依次回答：

1. **触发**：最近发生了什么，使问题从可忍受变成必须处理？
2. **落差**：现状与想要结果之间，哪一段开始失效或出现机会？
3. **约束**：他不能牺牲什么，例如现金、时间、职位、体面、关系或确定性？
4. **旧办法**：他目前怎样凑合，为什么继续不下去？
5. **筹码**：他已经拥有什么资源、能力、预算、权限或协助？
6. **临界点**：满足什么条件后，他才会付钱或行动？

先写一条处境链：

> 【触发事件】让【旧路径或现状】难以继续；他又受制于【硬约束】，只能动用【已有筹码】，寻找【可接受的进步】。

不要求每个行业都存在危机。低卷入或机会型消费可以由新机会、仪式节点、便利需求触发，禁止虚构生存焦虑。

### Phase 3：提炼情境性心理结构

钉子台词：「别只写他想要什么，要写他想要什么，又不敢失去什么。」

从可观察行为中找一组主张力：

- 他反复尝试什么，说明他仍相信什么？
- 他愿意付出什么，不愿意牺牲什么？
- 哪个失败结果会让他感到失控、无能、失责、掉价、被排斥或没有退路？
- 他希望谁如何重新评价他？
- 哪个异议最能阻止他购买？

用一句冲突句形成候选母题：

> 他想【获得具体结果或控制权】，同时害怕【具体损失或身份后果】，因此偏好【可观察的决策方式】。

「控制感、尊严、安全、归属、胜任、自主、确定性」只能作为候选词。必须写清控制什么、在谁面前保住什么、哪个事件使它变得重要。

只选一个最能同时解释触发、行动和异议的核心心理母题。次级张力最多保留两个。证据不足时写「可能」，不使用读心口吻。

### Phase 4：识别产品支点与身份跃迁

钉子台词：「产品只是支点，关键是它替用户完成了哪段变化。」

沿价值阶梯逐层分析：

1. **表层购买物**：他名义上买了什么？
2. **功能进步**：完成得更快、更稳、更省，还是获得原本缺少的能力？
3. **心理或社会结果**：他由此减少什么不安，恢复什么控制，改善什么关系？
4. **身份变化**：他想从怎样的自己，变成怎样的自己？
5. **风险转移**：他是否在请产品替自己承担判断、执行、信誉、时间或不确定性？

前三层有证据、身份层没有证据时，停在心理或社会结果。并非每次购买都承担身份跃迁。

### Phase 5：压成一句话

钉子台词：「一句话要装下因果，不能堆一串好听形容词。」

先用骨架确保信息完整，再改写成人话：

> 这是一群【已有筹码或仍相信的能力】、却在【触发事件】后被【失效路径与硬约束】卡住的人；他们表面购买【产品任务】，实际想把【可承受投入】换成【具体控制权或关系结果】，从【当前或害怕的身份】走向【目标身份】，同时最不能承受【失败代价】。

删除没有证据的槽位，不为填满公式虚构内容。最终句可以改变语序，但必须保留「处境、张力、产品进步」三项；身份跃迁只在证据支持时保留。

可以另给核心人群一个结构性名称：

> 被【失效路径】困住、正寻找【可接受出口】的【决策角色】。

名称服务理解，不充当证据。

### Phase 6：反证与资格校验

钉子台词：「能说清谁不属于这群人，画像才开始有用。」

为结论补齐：

- **高意向信号**：会带着哪些预算、时间、失败经历、资料、权限或具体问题出现？
- **资格门槛**：具备什么条件，产品才能真正交付承诺？
- **排除对象**：谁看起来相似，购买任务却不同？
- **替代解释**：还有哪种动机也能解释现有行为？
- **推翻条件**：出现什么访谈、成交或使用证据，就必须重做画像？

用五个问题回到真实客户：

1. 为什么偏偏现在处理这件事？
2. 如果这次不买，接下来会怎么办？
3. 已经试过什么、投入过什么，为什么没有继续？
4. 这次选择最怕出什么问题？
5. 半年后，希望哪个重要的人怎样评价你的变化？

## 输出契约

### 用户只要一句话

先输出以下三项，不先铺理论：

```markdown
核心人群：<结构性名称>

一句话：<完整因果句> [证据等级]

最大未知：<最可能推翻这句话的一项信息>
```

### 用户要完整深描

按以下顺序输出：

1. 核心人群与一句话。
2. 结构性处境链。
3. 核心心理母题及支持证据。
4. 表层购买、功能进步、心理结果与身份变化。
5. 高意向信号、资格门槛与排除对象。
6. 已验证、可推断、仍未知的证据台账。
7. 下一轮最值得问的三个验证问题。

把事实与推断分开。用户要求「精准毒辣」时，提高因果压缩度，不增加羞辱、贬损或武断读心。
锋利措辞不能抬高证据等级；没有数据支持时，不用绝对词制造确定感。

## 反空泛闸门

交付前逐项自检：

1. **对象闸门**：每个抽象词都写清对象，例如控制收入来源、保住团队权威、避免让家人承担损失。
2. **因果闸门**：一句话能回答为什么是现在、为什么是这个产品。
3. **区分闸门**：换成相邻人群或竞品仍完全成立时，结论过泛，继续收窄。
4. **预测闸门**：能据此预测一个高意向信号、一个主要异议和一个非客户特征。
5. **角色闸门**：B2B 或家庭决策中，没有把付钱者、使用者和受益者混成一个人。
6. **证据闸门**：没有把创始人直觉、单条评论或理论词汇包装成已验证事实，没有用绝对措辞掩盖 `[待验证]`，也没有补写无来源数字。
7. **尊严闸门**：尖锐来自解释力，不来自给客户贴「懒、贪、虚荣、低认知」等道德标签。

任一关键闸门失败，先修正再输出。

## 特殊情形

- **B2B 多角色**：分别分析经济买家、实际使用者、内部推动者与否决者，再说明他们怎样形成同一采购决定。
- **买家与用户分离**：先写买家的责任与风险，再写用户的使用处境，禁止共用一句心理画像。
- **低卷入商品**：便利、习惯、可得性足以解释购买时，停在功能层，不制造宏大身份变化。
- **冷启动无数据**：输出两到三个竞争假设和验证问题，不宣布唯一真相。
- **多群体混杂**：分别出卡，再按产品交付、付费能力、决策权与紧迫性选择核心群体。
- **医疗、心理、法律、金融等高风险场景**：提高证据门槛，不推断临床状态，不利用脆弱性设计操控话术。

## Refusals

- **「按年龄、收入、职业直接告诉我这群人的性格」**：拒绝从人口标签推导稳定人格；改问触发事件、约束、旧办法与购买行为。
- **「把所有行业都归结成同一个底层恐惧」**：拒绝预设答案；同一种表面行为可能来自完全不同的心理张力。
- **「没有证据也要说得像真的」**：拒绝隐藏不确定性；给 `[待验证]` 假设和推翻条件。
- **「用这套心理弱点逼他下单」**：拒绝把洞察改造成脆弱性操控；可以帮助澄清真实价值、资格边界与知情决策。
- **「根据评论告诉我现在谁在看」**：转介 `/liang-content-persona`，不要把现有观众与目标付费人群混为一谈。

## 验证契约

- 静态验证：frontmatter、名称、相对引用与 `agents/openai.yaml` 通过官方 quick validate 和仓库 skill-tree 检查。
- 行为验证：至少覆盖 B2C 服务、B2B 多角色、买家与用户分离、低卷入商品、证据不足五类输入。
- 质量验证：每个结果都能说清触发、约束、产品进步、主要异议、排除对象与证据等级。
- 失败条件：只输出人口标签和形容词；每个行业都归结为焦虑或控制感；强行补身份跃迁；把推断写成事实。

本 skill 默认只输出分析，不自动写入用户项目文件。
