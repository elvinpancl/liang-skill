# liang-promo-jianying：剪映可编辑工程

AI 出底片和工程，人在剪映里收尾。能用剪映原生做的就不烧进视频。 `[待验证]`

公开版提供计划文件、品牌包到剪映可编辑草稿的通用构建流程。客户工程、品牌资产、历史返修和私人反馈未纳入发布；记录格式见 [references/校准记录_脱敏版.md](references/校准记录_脱敏版.md)。

## 适用范围

- 处理：
  - 新生成剪映草稿：主画面、画中画、边框、字幕底衬、章节、说明、BGM 七条轨。
  - 录屏打码切片，从整片底片里切烘焙段。
  - 回读校验、布局预览、安装前检查、安装。
- 不处理：
  - 改已经被剪映打开过的草稿。那些是加密的，改坏了打不开。
  - 剪映里的精剪、音效、选配音，这些由人做。
  - 3D 动效、片头动画本身怎么做：卡点片走 liang-promo-beat，片头走 liang-promo-motion。
  - 录屏取证走 liang-promo-footage，粗剪台本和旁白走 liang-promo-edit。
- 缺品牌包：先问「品牌包在哪」。确实没有时，从 `assets/brand.example.json` 复制一份，填好颜色和字体再开始，并在交付说明里写明是临时值。
- 缺草稿库位置：先查项目的 SOURCE_OF_TRUTH.md。查不到就用剪映默认位置，并在交付时说明。

## 依赖与脚本位置

- Python 3.10 以上，装 `pyjianyingdraft==0.3.1` 和 `pillow`。装依赖要先征得同意；项目里已有 venv 就用它。
- ffmpeg 要能用 lavfi，自测和冒烟靠它合成素材。没有 ffprobe 时，脚本改用 ffmpeg 完整解码计帧。
- 只支持 macOS 上的剪映专业版。草稿库可以放外置盘，注册表固定在本机用户目录。

脚本在本 SKILL.md 所在目录的 `scripts/` 下，下文写作 `$S`；路径里有空格，记得加引号。

## 公理

### 公理 1：新草稿可以写，旧草稿不碰 `[待验证]`

- 方法依据：技术边界：新草稿可由 pyJianYingDraft 生成，再由 mac_draft 适配；已有草稿可能被剪映升级并加密，应先用冒烟草稿验证当前版本。
- 做法：
  - 每个版本用新草稿名生成、安装。
  - 用户在剪映里改过的版本，不用脚本覆盖。
  - 要改就出新版本，旧版本留着。
- 复核：剪映大版本升级后，先跑 `smoke.sh` 并安装一次。

### 公理 2：能原生的不烘焙 `[待验证]`

- 方法依据：交付原则：需要逐镜头修改的内容尽量保持为剪映原生图层。
- 做法：
  - 录屏放原素材，运镜写成剪映关键帧，转场用剪映自带的。
  - 章节和说明是剪映文字，生成视频走画中画，方便以后整体「替换素材」。
  - 只有剪映做不出来的才烘焙，例如 3D 场景、开场品牌动画、片尾 logo 动画。
  - 敏感区打码烧进素材，因为打码不能留给人去记。
- 反例：用户只要一条成片、明确说不改，就直接渲染 MP4，不必走剪映。

### 公理 3：样式只认品牌包 `[待验证]`

- 方法依据：配置原则：品牌只从当前项目的品牌包读取。
- 做法：
  - 说明、章节、底衬、边框、字体全部读 `brand.json`。
  - 计划文件里不写颜色和字号。
  - 用户在剪映里手调了样式，把参数回填品牌包，下次生成就是新样式。

### 公理 4：先冒烟，再正式；装前查、装后读 `[待验证]`

- 方法依据：核验原则：先用小草稿验证关键能力，安装前检查、安装后回读。
- 做法：
  - 新机器、剪映升级、品牌包换了字体，都先跑 `smoke.sh --install`，让人在剪映里看一遍。
  - 正式安装前跑 `jy_install.py --check`，装完回读草稿目录和素材数。

### 公理 5：数学检查不能代替人看 `[待验证]`

- 方法依据：核验原则：数学检查只能覆盖已标注的目标框，仍需人工检查可读性与遮挡。
- 做法：`verify_draft.py` 查结构和几何；`preview_layout.py` 出图，必须有人逐张看「说明有没有盖住它要讲的东西」。

## 上下文纪律

1. 读 `build_manifest.json` 和 `verify_report.json` 的摘要，不要把 draft_content.json 整个读进来（几十万字符）。
2. 看预览先看 `总览.jpg`，有问题再打开单张。
3. 计划文件改动用 Edit，不要每次整份重写。

## Phase 0：盘点

钉子台词：「先分清哪些段剪映能做，哪些段只能烧进视频。」

- 输入：故事板或剪辑台本、录屏和取证结果（`shots.json`）、底片（如果有）、品牌包、BGM。
- 动作：
  1. 列出每个镜头是「录屏原生」「烘焙段」还是「画中画」。
  2. 确认草稿库位置（`diskutil info <卷 UUID>` 核对外置盘），以及剪映版本。
  3. 外置盘没挂载时，先做不依赖它的部分。
- 退出：有一张镜头分类表。
- 暂停：缺品牌包或缺录屏目录时问一句，其余不暂停。

## Phase 1：素材

钉子台词：「打码烧进素材，余量留给人微调。」

- 动作：
  1. 写 `clips.json`，运行 `"$PY" "$S/sanitize_clips.py" clips.json`。默认两头各留 1 秒余量，草稿只用计划区间，不够时末帧定格。
  2. 运行 `"$PY" "$S/mask_sheet.py" 素材/sanitize_manifest.json`，逐张看 `打码抽检.jpg`：字完全认不出、框没有因为页面滚动盖偏。
  3. 有底片时运行 `"$PY" "$S/cut_segments.py" --plate 底片.mp4 --seg 名字:起:止 ... --total <总帧数>`。用旧成片当替身做流程自测时加 `--surrogate`，这样的草稿装不进去。
  4. 用了 AI 生成视频的，先按 liang-promo-beat 的筛查做完再进草稿。
- 退出：两份清单都在，帧数核对通过，打码抽检图看过。

## Phase 2：计划与构建

钉子台词：「计划只写这条片子的事，样式交给品牌包。」

- 动作：
  1. 按 [references/draft_plan_脱敏版.md](references/draft_plan_脱敏版.md) 写 `draft_plan.json`。运镜的换算见 [references/剪映换算.md](references/剪映换算.md)，说明的规则见 [references/说明样式_脱敏版.md](references/说明样式_脱敏版.md)。
  2. 运行 `"$PY" "$S/build_draft.py" draft_plan.json`。
  3. 运行 `"$PY" "$S/verify_draft.py" staging/<草稿名>`，退出码必须是 0。
  4. 运行 `"$PY" "$S/preview_layout.py" staging/<草稿名>`，看总览图，有相交的逐张看。
- 退出：校验通过；相交和避让例外都已人工判断过，并写进交付说明。
- 暂停：不暂停。

## Phase 3：安装

钉子台词：「新名字装进去，旧的一个不动。」

- 动作：
  1. 运行 `"$PY" "$S/jy_install.py" --staging staging/<草稿名> --draft-root <草稿库> --check`。
  2. 请用户完全退出剪映（Cmd+Q），得到确认后去掉 `--check` 正式安装。这一步要用户点头，因为会写剪映的注册表。
  3. 在项目的 SOURCE_OF_TRUTH.md 里记录草稿名、位置，以及草稿引用的本机素材（这些素材不能挪）。
- 退出：回读到草稿目录和素材数，注册表备份路径已告诉用户。

## Phase 4：回收

钉子台词：「用户手调过的参数，下次就是默认值。」

- 动作：
  1. 问用户在剪映里改了什么。样式参数回填品牌包，内容改动记进本 skill 的 [references/校准记录_脱敏版.md](references/校准记录_脱敏版.md)。
  2. 用户给了生成视频原片时，在剪映里用「替换素材」；比例变了要重新生成一版。
- 退出：校准记录追加一行。

## 交付说明要写的

1. 草稿名和位置。
2. 哪些可以改，哪些是烘焙段、要回源工程重渲。
3. 简化了哪些动作，以及时间上的微调。
4. 避让例外和人工判断的结果。
5. 草稿加密单向、含设备标识不要外发、引用的素材不要挪。

## Refusals

- **「直接改一下剪映里那个草稿的 JSON」** → 拒绝。被剪映打开过的草稿是加密的，改坏了打不开。要改就按计划生成一个新名字的版本。
- **「同名覆盖吧，省得剪映里一堆版本」** → 拒绝。用户可能已经在旧版本里手调过，覆盖就丢了。旧草稿由用户自己在剪映里删。
- **「剪映开着也没事，直接装」** → 拒绝。剪映运行时会回写注册表，新草稿可能不出现，注册表也可能损坏。
- **「打码先不做，到剪映里再盖个色块」** → 拒绝。剪映里的遮挡能被人挪开，导出时也容易漏掉。打码要烧进素材，交付前看打码抽检图。
- **「把草稿文件夹发给同事」** → 拒绝。草稿里有本机设备标识。要么发成片，要么在对方电脑上重新生成。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `sanitize_clips.py` | 按计划切录屏、打码烧进去、留余量；可裁切放大画中画素材 |
| `mask_sheet.py` | 每个打码区抽一帧裁出来拼图，交付前人工核看 |
| `cut_segments.py` | 从底片按帧号切烘焙段，完整解码核对帧数 |
| `build_draft.py` | 读计划和品牌包，生成明文草稿和 build_manifest.json |
| `verify_draft.py` | 回读草稿逐项核对计划和品牌包，逐帧检查说明是否压住目标 |
| `preview_layout.py` | 按真实关键帧离线合成说明出现时的画面，标目标框，出总览 |
| `jy_install.py` | 安装前检查和安装：新名字、剪映未运行、备份注册表 |
| `jy_camera.py` | 运镜换算和运镜操作（set、ease、hold、punch、pop），以及说明避让 |
| `jy_readback.py` | 回读草稿：关键帧插值、素材投影 |
| `jy_fonts.py` | 把文字字体指向系统字体文件 |
| `jy_common.py` | 帧和微秒换算、ffmpeg、计帧、找系统字体、草稿库路径 |
| `make_fixture.py` | 合成测试素材和计划 |
| `selftest.sh` | 自测，不碰剪映 |
| `smoke.sh` | 剪映实机冒烟，可选安装 |
| `vendor/mac_draft.py` | video-shotcraft 的 Mac 版草稿补齐和安装（Apache-2.0，原样） |

## 验证契约

- **自测**：`PYTHON=<venv>/bin/python bash "$S/selftest.sh"`；按当前环境运行并报告结果。覆盖换算公式（含 k≠1）、打码切片和抽检拼图、烘焙段、构建、回读、篡改后能查出、布局预览、同名和替身拒绝安装。
- **公开证据边界**：发布包不包含客户项目原始证据。运行自测只能验证合成样例和脚本边界，真实项目效果需单独核验。
- **效果边界**：识别、审美、受众理解及效率提升均需独立项目验证，不能由自测通过推导。
