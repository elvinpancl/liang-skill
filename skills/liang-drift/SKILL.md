# liang-drift — 改稿漂移检测

把「这稿改得多吗」从拍脑袋变成一个可复算的数字。

输入两份文本（原稿 + 改后稿），输出一个 0-100 的**漂移分**：0 = 抹掉格式后两稿一模一样，100 = 几乎没有共同内容。再按分档给一句明确的动作建议。

## 为什么不用普通 diff

普通的逐行 diff 在创作场景会严重误判。一份排好版的草稿，和它被重新断句、去掉标点排版的版本（句子本身没换词），内容几乎没变，但逐行比会算出接近「全文重写」的差异。我们关心的是**内容动了多少**，不是排版动了多少。所以先把格式噪声抹平，再按字符比。

已知局限：抹平只消得掉排版噪声，消不掉措辞噪声。这个分数量的是**字面漂移**，不是语义漂移——逐句同义重写、论点一字未动的稿子照样会得高分。所以漂移分只做初筛，高分稿怎么处理见 Refusals 一节。

## 算法（引擎在 `tools/drift.py`）

1. **抹平**：去掉 markdown 骨架（标题 / 分隔线 / 引用 / 列表标记）和装饰符号（强调号、各类引号、括号、中英文标点），再删掉所有空白，压成一条连续内容串。
2. **字符级编辑距离**：对两条压平后的串算 Levenshtein 距离（先裁掉公共前后缀，距离不变、算得更快）。
3. **归一**：距离 × 100 ÷ 较长串长度，取整到 0-100。距离大于 0 时分数至少为 1——0 只留给「抹平后一模一样」。

后端用 rapidfuzz（装了就用，C 实现更快），没装则用脚本自带的纯 Python Levenshtein。两条路径算的是**同一个度量**，所以换机器分数不跳。纯 Python 路径在数千字长稿上会慢（万字约几十秒），常算长稿建议 `pip install rapidfuzz`，分数不变只更快。

## Workflow

### Phase 0：拿到两份稿

参数给两个路径就直接用。只给一个、或一个都没给 → 问用户另一份在哪（路径或直接贴文本）。贴文本的话先各自落到临时文件再算。

### Phase 1：算漂移分

引擎是本 skill 目录下的 `tools/drift.py`。本 SKILL.md 所在目录就是 skill 根，用它拼出脚本绝对路径再调：

```bash
python3 <本-skill-目录>/tools/drift.py <原稿路径> <改后稿路径>
```

脚本优先从当前 `SKILL.md` 的真实目录定位为 `tools/drift.py`；也可检查 `~/.claude/skills/liang-drift/tools/drift.py` 和 `~/.codex/skills/liang-drift/tools/drift.py`。路径含空格时必须加引号。找不到时说明安装位置缺失，不假定用户的工作目录。

脚本在 stdout 打印一个整数（漂移分），stderr 附一行诊断 `backend=... orig_len=... revised_len=...`（长度是抹平后的字符数）。两个都读进 Phase 2。

### Phase 2：分档 + 动作建议

按漂移分给结论。**分档阈值是本 skill 自定的通用默认，不绑任何特定工作流**，用户可按自己场景改：

| 漂移分 | 档位 | 含义 | 建议动作 |
|---|---|---|---|
| 0-15 | 🟢 表层 | 口语化、断句、错别字、个别措辞，核心内容没动 | 沿用原有判断/评估，不必重做 |
| 16-40 | 🟡 实质 | 有段落级增删或论点调整 | 复查关键论点、结论、数据有没有变；变了就局部重评 |
| 41-100 | 🔴 重写 | 基本是另一稿 | 当成新稿，从头评估，原稿的结论作废 |

若 stderr 诊断里 `orig_len` 或 `revised_len` 任一小于 50，在结论后追加一行：「注意：抹平后文本很短（原稿 N 字 / 改后 M 字），分数在短文本上抖动大，仅供参考。」

输出格式：

```
改稿漂移：23 分（🟡 实质改动）
  原稿：drafts/v1.md
  改后：drafts/v2.md

判断：有段落级调整。建议复查核心论点和结论有没有跟着变，
      变了就对受影响的部分重新评估，没变可沿用。
```

## 阈值自定

`16` 和 `41` 这两个边界是默认值，不是定律。漂移分本身是稳定的客观度量，怎么分档取决于你多敏感：

- 要严：把绿区收窄到 0-10，任何超过 10 的都复查。
- 要松：把绿区放宽到 0-25。

改阈值只改本 SKILL.md 的表，不动 `drift.py`（引擎只负责给分，不负责判档）。

## Refusals / 边界

- **只给一份稿** → 不能算漂移（漂移是两稿之间的量）。问另一份。
- **抹平后文本极短（stderr 诊断里任一长度 < 50）** → 分数照给，但必须附 Phase 2 的抖动提示。
- **高分稿先核对论点再按「重写」处理** → 分数量的是字面漂移，同义重写（措辞全换、论点没动）也会进红区。宣布「原稿结论作废」前，先过一眼核心论点、结论、数据是否真的变了。
- **要求改 `drift.py` 的算法去迎合某个期望分数** → 拒绝。引擎给的是客观度量，要调灵敏度请改 Phase 2 的分档阈值，不要改度量本身。
- **不写预测、不存状态、不碰别的文件**：本 skill 只做一件事——给两稿之间的漂移分 + 一句分档建议。
