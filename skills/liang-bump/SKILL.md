# /liang-bump — 评分卡升级

评分卡是工作台，不是祖训，该改就改。但改公式是整个闭环里风险最高的动作：改对了预测变准，改错了之前攒的手感全废。所以这里流程最重。

## 跨宿主执行能力

以下适配只用于本文件原生轻量流程，不改写所引用的第三方完整工作流。Task、Agent、Read、AskUserQuestion 在本轻量流程中是能力名称，不要求某一宿主的同名工具。Claude Code 使用可用的 Task/Agent；Codex 使用可用的子代理接口，例如 `collaboration.spawn_agent`。盲评分必须创建不继承父对话的干净上下文（该接口显式设 `fork_turns="none"`），只传本文件规定的白名单材料；默认继承当前模型，不擅自降级或指定其他模型。等价工具可用时照常完成，不因缺少名为 Task 的工具中止。只有所有可用接口都无法满足干净上下文和输入隔离时，才按原有降级规则处理，绝不把受污染的主对话评分写进校准池。

路径或参数已在本任务上下文中明确时直接使用并核验，不重复询问。已授权目标持续有效；依赖用户裁定的部分暂停时，继续完成不依赖该裁定的准备与验证。

## 完整模式分流

`.liang-content-state.json` 存在时，读取并执行 [完整规则升级与 bucket 重校工作流](references/full-calibration-workflow.md)，包括 blind 全量重打、排序一致性、跨模型审核、cleanup 与 state 更新；完成后不再重复执行下方轻量流程。状态文件不存在时继续下方 liang v1 流程。

完整模式不得把含实绩的升级证据写进 `scorecard.md`；证据 Memo 只能进入 `ledger.md`。

## 第一步 验资格

- 数 `bets/` 里「已复盘」的卡，不够 scorecard.md 的升级门槛（默认 5 张）就拒，说清还差几张。样本不够时的公式调整是过拟合。
- 读 ledger.md「观察」段。没有任何观察支撑的改动要多问一句：这次是数据驱动，还是手感驱动？手感驱动的建议先攒复盘。

## 第二步 拟提案

基于观察给出改动提案，一次一个方向，不打包大改：

- 调权重：哪个维度从 1 调到几，依据是哪几条观察
- 加维度：新维度问什么、怎么打 0-5，哪几张卡的复盘暴露了这个盲区
- 减维度：哪个维度和结果基本无关，证据是什么
- 重定义：哪个维度的打分规则含糊，怎么改得可执行

用户已明确给出改动或授权模型提出并落地有效改动时，直接以提案进入第三步验证，不重复确认。用户只要求提案、未授权修改，或提案超出原授权范围时，先完成可审阅提案与验证结果，再就具体差异确认一次；验证本身不等待批准。

## 第三步 全量重打（不可跳过，重打不在本对话做）

「重打只看稿子」这句话在主对话说不到做到：验资格时观察已经进了上下文，翻卡找原稿时复盘段就在同一个文件里。看过答案再重考，80% 门槛形同虚设。所以重打交给一个干净上下文的子代理。

1. 列清单：从每张「已复盘」的卡抽两样东西——原稿路径给子代理，实际数据量级自己留着第 3 步用，不进子代理。
2. 子代理重打：用 Task 工具起一个子代理，prompt 里只放三样：原稿路径清单、新公式的完整维度定义与权重（用通用语言写全，不让子代理去读 scorecard.md）、输出格式（每篇每维 0-5 整数分配一句理由，附加权综合分）。明确告诉它：只许 Read 清单里的原稿，禁止读 bets/、ledger.md、scorecard.md 和项目里任何其他文件，禁止提问。发出前把 prompt 自查一遍，不许含任何播放量、档位、爆或哑火这类实绩字样。
3. 对账：拿回子代理的分，主对话排两列——新综合分从高到低，实际数据从高到低。
4. 一致性判定：任取两张卡，新分高的那张实际数据也更高，算一对「顺序对」。顺序对占比 ≥ 80% 放行；不到就拒，说明新公式对历史的解释力还不如现状。

丑话说在前头：子代理和主对话是同一个模型，隔离掉的是本次会话里的实绩记忆，隔离不掉模型自带的偏好，这是轻量工具的上限。只有没有任何可满足上述隔离条件的子代理接口时，才停止本次落地，保留已完成的提案与验证准备并说明阻塞；不接受退回受污染的主对话重打。

## 第四步 落地

放行才落地：

- scorecard.md：版本号 +1，在「升级记录」段加一行：`vN（YYYY-MM-DD）：<改了什么> ← <依据的观察>，重打一致性 X/Y 对`；应用新权重 / 新维度 / 新定义。
- ledger.md：清观察段——被这次升级吸收的观察删掉，被数据推翻的也删掉，只留还没处理的。git 是档案，账本不开博物馆。

已封存的旧预测卡不回改——它们记录的是当时用当时的卡做的判断，历史就是历史。

## Refusals

- **跳过重打** →「就调一个权重，别费劲重打了」拒。改动多小都重打，这条没有例外。
- **嫌子代理麻烦** →「别起子代理了，你直接重打」拒。主对话重打是看过答案重考，分数不作数。同名 Task 不可用时使用等价隔离接口；任何隔离接口均不可用才停止落地，没有用受污染评分替代的路径。
- **降门槛放行本次** →「80% 差一点点，这次先过吧」拒。想改一致性门槛或升级门槛本身，先说服为什么，单独作为一次提案走完整流程。
- **样本不够硬要 bump** → 拒，去发内容攒复盘。
- **一次打包五个改动** → 拆开。多个改动一起过，重打结果说不清是哪个改动的功劳。
