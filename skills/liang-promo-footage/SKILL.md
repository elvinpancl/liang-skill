# liang-promo-footage：录屏取证

文案里每一句能力描述，都要能指到某段原片的某一秒。 `[待验证]`

公开版提供按画面变化抽帧、文字识别、实录对照与配图核验的通用流程。应重点查找未出现的页面、失败或报错的操作、空数据、不可见的结果，以及自动抽帧遗漏。具体项目的原片与取证记录由使用者私有保存。

## 适用范围

- 处理：产品演示的录屏原片（mp4、mov 等），录完以后、写口播或文章以前的核对；按时间点导出配图；配图的打码清单。
- 不处理：
  - 拍前规划和录屏清单，走 liang-promo-plan。
  - 写文章，走 liang-promo-article。
  - 内容闭环里登记已拍的短视频，走 liang-content-shoot。
  - 剪辑台本、粗剪、配音字幕稿和成片发布前检查，走 liang-promo-edit；精剪本身在剪辑软件里做。
- 缺原片位置：暂停，只问「原片在哪个目录」。
- 缺录屏清单：照常取证。实录对照只写实际画面，不做清单比对，并在交付时说明。

## 依赖与脚本位置

- ffmpeg：抽帧、导出配图。时长和分辨率从 `ffmpeg -i` 的输出里读，不需要 ffprobe。
- 文字识别只在 macOS 上跑：osascript 调系统 Vision 框架，识别中英文。其他系统上抽帧和导出照常，识别这一步跳过并说明，改成分批看图。

脚本在本 SKILL.md 所在目录的 `scripts/` 下，用本文件的路径拼出脚本目录。不确定装在哪时，查 `~/.claude/skills/liang-promo-footage/scripts/`。下文把脚本目录写作 `$S`，路径里有空格时记得加引号。

## 上下文纪律

1. **读识别文字，不整批看图。** 长会话可能丢失较早的图像上下文，具体限制依宿主而定。只在三种情况下看图：画面信息不在文字里（图表、布局、颜色状态）；核对打码扫描标出来的图；最终挑配图。每次不超过 20 张。
2. **先读新增文字。** `新增文字.txt` 只列每帧新出现的文字；需要整帧上下文时，再回识别原文按帧名取。
3. **抽帧会漏画面。** 自动抽帧按画面变化和间隔取样，一屏只停留几秒的结论可能落在两帧之间 `[待验证]`。文案要用的结论在新增文字里找不到时，回原片按时间点补导一帧核对，不凭印象写。
4. **产物位置。** 抽帧、识别文字放项目的 `制作过程/录屏取证/`，配图和配图说明放 `制作过程/配图/`。实录对照写回录屏清单，没有清单就在项目顶层写 `实录对照.md`。

## Phase 1：盘点

钉子台词：「先数清有多少段、每段多长，再谈哪段能用。」

- 输入：原片目录。
- 动作：`python3 "$S/extract_frames.py" <原片目录>... --list`，得到每段的时长和分辨率。分辨率不一致的段落记下来，导出配图时要统一裁切。
- 退出：原片清单齐全。
- 暂停：不暂停。

## Phase 2：抽帧与识别

钉子台词：「看文字，不看几百张图。」

- 输入：原片目录。
- 动作：
  1. `python3 "$S/extract_frames.py" <原片目录>... --out 制作过程/录屏取证/frames`。默认参数如下，首尾帧总是保留：
     - 画面变化阈值 0.08。
     - 变化后延 1 秒取帧，等界面加载完。
     - 相邻两帧至少隔 6 秒。
     - 超过 15 秒没变化就补帧。
  2. `python3 "$S/ocr_frames.py" 制作过程/录屏取证/frames`。每段原片一份识别文字，放在 `frames/ocr/`，可以断点续跑。
  3. `python3 "$S/novel_lines.py" 制作过程/录屏取证/frames/ocr > 制作过程/录屏取证/新增文字.txt`。
     - 多段原片里反复出现的菜单、侧边栏、浏览器标签，会被自动认成界面文字去掉，去掉了什么写在输出开头。
     - 去多了就用 `--chrome-ratio` 调高门槛，漏了就用 `--noise` 补词表。
- 退出：每段原片都有识别文字，`新增文字.txt` 生成。
- 暂停：不暂停。识别失败的批次记在 `frames/ocr/识别失败.txt`，对应段落在实录对照里标「未识别」。

## Phase 3：实录对照

钉子台词：「清单写的是打算拍什么，实录对照写的是真拍到了什么。」

- 输入：`新增文字.txt`、录屏清单（有的话）。
- 动作：按 [references/实录对照模板.md](references/实录对照模板.md)，每段原片写一行，列为原片、身份、实际画面、能不能用、关键原文和时间点。
  - **身份**：多身份产品（例如租户管理员和平台管理员）每段都写，按页眉、侧边栏、账号名判断。判断不出来的段落攒起来，一次问用户。
  - **能不能用**：失败（报错、答非所问、没用上已有资料）、看不到结果、空数据，一律标不可用，并写原因。
  - **关键原文**：AI 的回答、提示语、报错和数字照抄，写上时间点，后面写文案时直接引用。
  - **比对清单**：标出未录、录了但看不到结果、和清单不符、清单里有但产品里没有。只从界面文案、语言包或接口推出来、原片里没出现的页面，一律标「原片未出现」，不能写成能力。
  - **写回清单**：在每集末尾追加带日期的「实录对照」段，不改原计划行。原计划确实错了的，在原行加删除线，并注明「事后修订」。
- 退出：每段原片都有一行，不可用的都写了原因。
- 暂停：身份不明的段落需要用户确认时，暂停一次。

## Phase 4：配图导出（按需）

钉子台词：「配图也是证据，导出来先核对再交。」

- 输入：文章或口播挑好的时间点清单。格式见模板，每行是「名称|原片相对路径|时间|期望关键词」。
- 动作：
  1. `python3 "$S/export_stills.py" <清单> --src <原片根目录> --out 制作过程/配图`。导出原尺寸整帧，对每张图做文字识别，核对期望关键词。没对上的会列出来，前后挪一两秒重导。
  2. `python3 "$S/scan_sensitive.py" 制作过程/配图/stills_ocr.txt --out 制作过程/配图/打码清单.md`。
     - 必须打码：API 密钥、邮箱、手机号、身份证号、本机用户路径。
     - 可选打码：编号（UUID）、网址。
     - 输出里敏感值只露前 4 位。
  3. 打开被标出的图逐张确认，再写配图说明：每张图写身份、原片、时间点、画面。开头放打码清单，并提醒整屏截图在手机上看不清，发布前把关键区域裁出来。
- 退出：每张图的关键词都对上，配图说明和打码清单写好。
- 暂停：不暂停。扫描只是线索，识别可能漏字，没被标出的图发布前也要整体过一眼。

## Phase 5：交接

把下面这段交给 liang-promo-edit（剪片）或 liang-promo-article（写文章）：

```yaml
liang_handoff:
  from: liang-promo-footage
  fact_base: <实录对照所在文件>
  ocr_dir: <识别文字目录>
  novel_lines: <新增文字.txt>
  stills: <配图说明路径，没导出就写无>
  roles: [<身份 1>, <身份 2>]
  unusable: [<不可用的原片和原因>]
  evidence_level: 结果已验证
  next: liang-promo-edit 或 liang-promo-article
```

两边只消费这些字段。识别原文里的邮箱、手机号这类个人信息不往下传。

## Refusals

- **「这段回答失败了，剪掉错的部分，当成功的写」** → 拒绝把失败画面写成能力。品宣内容是对外的，一句对不上画面的话就是事故。要展示就重录，重录前先把原片标成不可用。
- **「点了创建，结果看不到也写上吧」** → 拒绝把看不到结果的操作写成已完成。只写到画面里出现的最后一步，需要结果就补录。
- **「把几百张帧都给我过一遍」** → 拒绝整批看图。上下文装不下，早先的图会被剥离，结论反而不可靠。按上下文纪律读识别文字，必要时分批看。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `extract_frames.py` | 盘点（`--list`）和按画面变化抽帧，写 `index.json`；ffmpeg 关闭标准输入，放进循环也不会错位 |
| `ocr.js` | JXA 调 Vision 识别中英文，同一行的文字块用「 \| 」连接 |
| `ocr_frames.py` | 按 `index.json` 每 25 张一批识别，每段原片一份结果，可断点续跑 |
| `novel_lines.py` | 自动去掉界面固定文字，每帧只留新出现的行 |
| `export_stills.py` | 按清单导出配图，识别核对期望关键词，写 `stills_ocr.txt` |
| `scan_sensitive.py` | 扫打码项，输出按图分组、只露前 4 位的打码清单 |
| `selftest.sh` | 自测：抽帧（合成视频）、新增文字去重、打码扫描 |

## 验证契约

- **自测**：`bash "$S/selftest.sh"`；按当前环境运行并报告通过、失败与跳过项。没有 ffmpeg 时跳过抽帧那几项。
- **公开证据边界**：发布包不包含客户项目原始证据。运行自测只能验证合成样例和脚本边界，真实项目效果需单独核验。
- **效果边界**：识别、审美、受众理解及效率提升均需独立项目验证，不能由自测通过推导。
