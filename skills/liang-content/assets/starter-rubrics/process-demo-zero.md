# Starter Rubric：过程实录 / 实测挑战（process-demo）— v0 cold-start 占位

> **这个形态是什么**：一步一步展示「当场做成一个结果」的内容——限时挑战（"挑战 X 分钟用 AI 做出 Y"）、手把手实操、开账号实测、build-in-public 过程记录。
> **和教程（tutorial-builder）的分界**：教程答"怎么做"，读者拿着照做，价值在知识完整性；过程实录的张力在**结果未知**——观众看的是"他到底能不能当场做成"。如果你的内容主体是知识讲解、操作只是配图，用 `tutorial-builder-zero.md`。

**这是给完全没数据的新作者用的占位 rubric。**它会打错。**前 5 篇预测精度大概 ±50%——这是 cold-start 的数学事实，不是 rubric 失败**。

跑完 5 篇（每篇都走完 `/liang-predict` → 发布 → `/liang-retro` 闭环）之后，你会有第一份个人校准数据，可以提议第一次 `/liang-bump` 升级到 v1。

---

## v0 综合分公式（**等权占位**）

```
composite = (ER + HP + QL + NA + AB + SR + SAT) / 7 × 2.0
```

每个维度 0-5 整数分。综合分范围 0-10。

**为什么等权**：你没有数据支持任何特定权重。等权能让你在数据出来之前对每个维度都给"中立的关注"。第 5 篇之后你的复盘数据会告诉你哪些维度真的预测了你的过程内容的传播。

---

## 7 个维度

### ER — Emotional Resonance（代理掌控感）
*观众跟着过程走，能不能产生"我也能做到"的掌控感？*

过程实录的情感共鸣不是催泪——是**代理体验**：受阻时观众替他捏汗，修复成功时观众跟着爽。全程旁观无代入 = 没有共鸣。

- **0** — 纯操作旁观；观众只是看别人用软件
- **3** — 有代入但平缓；观众觉得"有点意思"但不紧张
- **5** — 全程代入；受阻处观众替作者着急，做成时观众有"这我也想试"的冲动

### HP — Hook Potential（挑战承诺）
*开头一句能不能给出"时限 + 具体可验证的产出"？*

过程实录的钩子 = 一个当场可兑现或当场翻车的承诺。承诺越具体、越可验证，观众越想留下来看结果。

- **0** — 直接开始操作，没有承诺；观众不知道在等什么结果
- **3** — 有目标但没有时限或赌注（"今天我们来做一个 X"）
- **5** — 时限 + 具体产出 + 利益攸关一句说清（"挑战 N 分钟做出一张能直接商用的 X"）

### QL — Quotable Lines（可复刻步骤密度）
*观众看完能不能照着一步一步做出同样的结果？*

过程实录的"金句"就是可复刻的操作路径——工具名、入口、提示词、操作顺序完整可抄，是观众收藏转发的核心原因。

- **0** — 跳步、只给结果；观众看完复刻不出来
- **3** — 主干步骤全但细节缺（工具提了名字但没给入口 / 提示词一闪而过）
- **5** — 每步工具 + 动作 + 判断依据齐全，观众暂停截图就能照做

### NA — Narrativity（受阻-修复弧线）
*过程里有没有真实的失败和当场修复？*

这是过程实录区别于产品演示的核心：零波折的流水线演示没有故事，真实受阻 + 当场修复 + 结尾与开头承诺对账才是完整弧线。

- **0** — 零波折流水线；一路顺滑像官方宣传片
- **3** — 有一次小调整或返工，但轻描淡写带过
- **5** — 至少一次真实失败 + 当场分析原因 + 修复重试，结尾明确对账（成了还是没成，如实说）

### AB — Audience Breadth（成果需求广度）
*多少人想要这个成果本身？*

观众留下来不是为了看操作，是为了那个成果。成果越接近普世刚需场景，盘子越大。

- **0** — 极小众工具流；成果只有同行在意
- **3** — 特定职业 / 特定场景的常见需求
- **5** — 普世刚需场景——几乎每个目标观众都遇到过"我也需要做出这个东西"的时刻

### SR — Social Resonance（痛点绑定）
*这个过程解决的是公认的现实痛点，还是纯工具尝鲜？*

新工具实测如果只回答"这工具行不行"，观众没有停留理由；绑定到"谁的什么痛点从此省多少事"，过程才有社会性重量。

- **0** — 为演示而演示；纯尝鲜、纯跑分
- **3** — 提到了应用场景但没点名人群和代价
- **5** — 点名具体人群的具体痛点，并给出省钱 / 省时的量级对比

### SAT — Satire Depth（在场真实感）
*过程是"正在发生"还是"排练过的成品剪辑"？*

过程实录的风格深度 = 在场感：第一视角、口语转折（"诶，这次好多了"）、保留犹豫和意外。剪得太干净反而杀死这个形态的魅力。

- **0** — 成品剪辑广告感；每一步都"恰好"成功
- **3** — 录屏 + 配音，节奏真实但情绪平
- **5** — 第一视角实时感——犹豫、自言自语、意外和惊喜都在，观众像站在作者身后看

## Bucket 预测：比率桶方案

> ⚠️ **新人的 bucket 不能用绝对数字**——不同平台、不同垂类的基线差异极大。

### 第 1 篇：平台通用默认

用最保守的分位数先验（核心指标按你的平台定：推荐流内容通常是观看数）：

| Bucket | 范围（核心指标）| 先验概率 |
|---|---|---|
| 底部 | < 平台新号 P25 | 30% |
| 基础盘 | P25 - P50 | 40% |
| 命中 | P50 - P90 | 20% |
| 小爆 | P90 - P99 | 8% |
| 大爆 | > P99 | 2% |

### 第 2 篇起：用比率桶

`baseline = 上一篇复盘窗口结束时的核心指标`（或最近 3 篇中位数）。

| Bucket | 倍数范围 | 含义 |
|---|---|---|
| 退步 | < 0.3 × baseline | 明显下滑 |
| 持平 | 0.3 - 1 × baseline | 同档 |
| 命中 | 1 - 3 × baseline | 中度突破 |
| 小爆 | 3 - 10 × baseline | 显著破圈 |
| 大爆 | > 10 × baseline | 量级跃迁 |

第 5 篇后跑 `/liang-bump --bucket-only` 重新校准边界。

> 过程实录多走短视频推荐流，流量生命周期短——复盘窗口建议 T+7；若你的平台以搜索分发为主（长视频 / 图文站），再拉长窗口。

## Cold-start 战略（简版）

前 5 篇的"预测"不是预测——是**数据采集**。

1. **建立纪律**：发布前写下盲判断
2. **记录 7 维评分**：复盘后每条样本变成 (打分, 成绩) 配对
3. **取样策略**：主动选维度组合差异最大的过程内容——1 条极限时限挑战（HP 主导）、1 条受阻修复剧情强（NA 主导）、1 条普世成果（AB 主导）、1 条痛点绑定强（SR 主导）、1 条综合中等

| 校准样本 | 你能相信什么 |
|---|---|
| N=0-2 | 啥都别信 |
| N=3-5 | 相信"哪个维度可能重要"的方向 |
| N=5-10 | 相信 bucket 排序 |
| N=10-20 | 中枢可信 ±30% |
| N≥20 | rubric 真正成为"作弊器" |

## 重要警告

- cold-start 期 composite 的置信度低——**不要基于 v0 分数决定要不要发某条内容**
- 同一系列、同一结构的两条过程内容，成绩可以差一个量级——差异往往在 NA（有没有真实受阻）和 SR（成果绑没绑定痛点），复盘时优先核对这两维
- 前 5 篇**每篇必须走完整闭环**（predict → 发布 → retro），跳过任何一篇复盘 = 整个校准失败
- 第 5 篇后**必须**跑 `/liang-bump` 升级

---

## 最重要的一句话

**前 5 篇你不是在做决策，你是在收集数据。** 过程实录的诱惑是把过程剪得完美——但这个形态卖的恰恰是不完美的真实。先如实记录，让数据告诉你观众要什么。
