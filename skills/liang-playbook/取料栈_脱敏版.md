# liang-playbook 取料栈（脱敏版）

本公开版保留检索协议，移除了私有知识库路径、日期快照、源编号和真实业务案例。它不附带行业语料，不将作者历史样本作为用户现有证据。

## 一、配置与真源解析

先设置 `PLAYBOOK_KB_ROOT` 为用户自己的知识库目录。也可显式复用已有 `LIANG_KB_ROOT`：

```bash
PLAYBOOK_KB_ROOT="${PLAYBOOK_KB_ROOT:-${LIANG_KB_ROOT:-}}"
test -n "$PLAYBOOK_KB_ROOT" || { echo '缺少 PLAYBOOK_KB_ROOT，请先按 README.md 配置自己的知识库。' >&2; exit 2; }
test -d "$PLAYBOOK_KB_ROOT" || { echo '知识库目录不存在。' >&2; exit 2; }
test -f "$PLAYBOOK_KB_ROOT/SOURCE_OF_TRUTH.md" || { echo '缺少知识库 SOURCE_OF_TRUTH.md。' >&2; exit 2; }
```

读取知识库根目录的 `SOURCE_OF_TRUTH.md`，按 README 的角色表定位当前正式母版、源索引、完整覆盖底表、覆盖审计、逐卡回源表和原始语料目录。相对路径以知识库根目录解析，逐项验证存在。没有对应材料时明确报告缺项，不回退到作者目录，不宣称穷尽检索。缺少专属行业源可以进入 B／C 分支；缺少索引体系时先准备索引或交付采集任务，不能伪造完整流程成功。

记录各输入的版本日期或哈希。以权威索引指向的当前文件为准，不把示例或历史日期写死为永久真源。源索引只用于定位；应同时扫描完整覆盖底表和所有日期的原始语料，防止索引漏列。

## 二、来源层级

以下是分类规则，不是实际数量统计。每轮从用户知识库重新计数。

| 层级 | 内容 | 用途 |
|---|---|---|
| L1-A | 音频完整转写 | 全文阅读，保留问答与上下文 |
| L1-B | 用户获准使用的订阅原文 | 没有时间码时只作转述 |
| L1-C | 独立链接笔记原文 | 记录原文来源与抓取日期 |
| L1-D | 可访问的公开页正文 | 记录访问日期和正文范围 |
| L2 | 平台章节摘要 | 保留章节与时间点，不能自动证明行业数据 |
| L3 | 逐条拆解 | 只作索引和骨架确认 |
| L4 | 逐卡回源表 | 从卡片定位源编号，不代替读源 |

## 三、固定取料顺序

```text
回源表、覆盖底表、覆盖审计确定候选源编号
→ 有 L1-A 则全文读
→ 没有 L1-A 时依次检查 L1-C、L1-D、L1-B
→ 逐章读完 L2，记录章节和时间点
→ L3 只确认骨架和补检索词
```

### 第 1 步：从行业映射到交易分支

依次查询当前正式母版、覆盖审计的分支等级、完整覆盖底表、逐卡回源表、源索引与增量源目录。审计与回源表只提供起始集合，不构成允许源白名单。继续使用行业同义词、交易动作、交付对象和风险词扫描全部获准语料。

独立命中的材料必须回读全文，并在 `01_取料记录.md` 标「审计未列、独立检索补得」。索引漏列不能被误记为「已经穷尽」。不要读取不在用户授权范围内的目录或跟随指向无关资料的软链。

### 第 2 步：全文阅读

使用本轮实际源编号定位原始材料。长稿可分块读，但必须完整读到末尾，不能只看检索命中行。分别记下问题、补充条件、建议、理由、改口、反例和失效边界。账号名、日期和时间码只从实际材料读取，不补写。

### 第 3 步：生成研究问题前复核

只有已检查的本地材料确实没有答案，问题才进入 `03_采集清单.md`。已存在的商户操作数据进入 `07_商户执行前核验清单.md`，不能混作行业研究缺口。只读 L3 不能证明原文无答案。

回归模式下，生成者只读允许源、被测卡标题和源编号，不读取目标卡正文、预期答案、答案定位或评审结果。已知回归不能包装成独立盲测。

## 四、取料记录

`01_取料记录.md` 使用：

| 源编号 | 层级 | 路径 | 完整阅读 | 章节／时间点 | 可支持判断 | 不可支持判断 |
|---|---|---|---|---|---|---|

每个核心判断附实际证据位置：

```text
判断：<一句话>
来源：<本轮真实源编号和层级>
定位：<路径＋章节／时间点／行号>
边界：<这份源不能证明什么>
```

「取料完整性」由独立评审在产稿后计算，分母来自生成者不可见的评审清单。生成阶段不猜清单、不自报命中率；评审另行记录有源但未进入草案或成卡的项目及排除原因。
