# liang-playbook 校验闸门

闸门 1、2、3A、4、5、6 全部通过，`industry_card_status` 才能记为 `READY` 并创建 `04_成卡_v1.md`。闸门 3B 只计算 `merchant_readiness`，商户尚未校准不阻断行业卡。机器检查负责发现确定性残留，人工检查负责语义替换、来源是否真正支持结论和反例是否有效；两类结果都写入 `06_校验报告.md`。

## 一、运行变量

先替换为本轮真实路径：

```bash
PLAYBOOK_RUN_DIR="/absolute/path/to/挖掘_行业_YYYY-MM-DD"
PLAYBOOK_SKILL_DIR="/absolute/path/to/liang-playbook"
PLAYBOOK_DRAFT_FILE="$PLAYBOOK_RUN_DIR/02_草案_v1.md"
PLAYBOOK_CARD_FILE="$PLAYBOOK_RUN_DIR/04_成卡_v1.md"
PLAYBOOK_SOURCE_FILE="$PLAYBOOK_RUN_DIR/05_源出处表.md"
PLAYBOOK_REPORT_FILE="$PLAYBOOK_RUN_DIR/06_校验报告.md"
PLAYBOOK_MERCHANT_FILE="$PLAYBOOK_RUN_DIR/07_商户执行前核验清单.md"
PLAYBOOK_V3_FILE="/absolute/path/from/SOURCE_OF_TRUTH.md"
PLAYBOOK_V3_COMPARE_FILE="$PLAYBOOK_V3_FILE"
PLAYBOOK_INDUSTRY_PATTERN='行业专有词1|行业专有词2|交易专有词'

if test -f "$PLAYBOOK_CARD_FILE"; then
  PLAYBOOK_CHECK_FILE="$PLAYBOOK_CARD_FILE"
else
  PLAYBOOK_CHECK_FILE="$PLAYBOOK_DRAFT_FILE"
fi
```

成卡尚未生成时，`PLAYBOOK_CHECK_FILE` 自动指向草案；先执行闸门 1、2、3A、4、5，全部修完后再生成成卡，重新运行变量块并对成卡重跑。盲测回归时，`PLAYBOOK_V3_COMPARE_FILE` 必须由独立评审预先排除被测目标卡正文，生成者不得借过滤动作读取答案。

确定性检查统一交给 Node 校验器，避免 macOS `awk` 的字节长度与 locale 差异：

```bash
node "$PLAYBOOK_SKILL_DIR/scripts/check-run.mjs" "$PLAYBOOK_RUN_DIR"
```

标准输出只含 JSON。退出码 `0` 表示机械检查通过，`1` 表示存在机械失败，`2` 表示调用或文件错误。报告必须原样记录 JSON 中的运行 locale，以及顶层 `industry_card_status`、`merchant_readiness`、`errors` 和 `warnings`；不要用另一套临时正则改写结果。

`00_分级与源清单.md`、`05_源出处表.md`、`06_校验报告.md` 必须各自出现以下契约标识；旧产物只在本次被触及时迁移，不做批量回写：

```text
evidence_schema: v3.1-layered
legacy_policy: forward-only-touch-to-migrate
```

## 闸门 1：模板句检测

目标：候选卡内部没有重复的实质整行，也不逐行复制当前 V3 其他卡的正文。结构标题、表头、代码围栏标记和纯标点行不参与比较；围栏内部若承载正式正文，仍参与重复、数字与占位检查。

### 1A. 卡内重复

读取 Node JSON 的 `checks.duplicate_lines`。校验器按 Unicode 码点规范化实质行，忽略结构标题、表头、代码围栏标记和纯标点行，表格正文与围栏内正文照常检查；机器只报告规范化后不少于 20 个码点的重复整行，较短句由人工抽验，避免把「不适用」等结构短语当成模板复制。不再用 `awk length()` 或字节数近似字符数。

预期：没有未经裁定的重复。任何实质整行出现 2 次及以上，回到对应模块重写。

### 1B. 与当前 V3 整行重合

Node 校验器不读取 V3，也不执行这一步。由独立评审在生成完成后，使用预先排除目标卡正文的 `PLAYBOOK_V3_COMPARE_FILE` 做外部比对；生成者不能自己制作排除文件，也不能读取比对结果后反向贴近答案。真实定义或法规名称若必须逐字保留，在报告中写明来源与保留理由；普通经营句不得因「行业都一样」直接复制。

## 闸门 2：跨行业替换测试

目标：模块 5 的每条选题和开头句必须依赖当前行业的用户、过程、证据或限制。把行业名替换为餐饮、留学、殡葬等另一行业后仍成立，就判失败。

先筛出没有明显行业词的开头：

```bash
rg -n '开头句[：:]' "$PLAYBOOK_CHECK_FILE" | rg -v "$PLAYBOOK_INDUSTRY_PATTERN"
```

机器无命中不等于通过。人工逐条填写：

| 选题 | 原句中的行业专有事实 | 替换行业 | 替换后是否仍成立 | 结论 |
|---|---|---|---|---|
| 1 |  | 餐饮单店 | 是／否 | 通过／重写 |

判据：专有事实不能只是行业名。至少落在用户原话、真实流程、专业对象、履约证据或风险边界之一。

## 闸门 3A：行业卡证据

目标：模块 1 至 7 的行业结构都有可定位证据。3A 阻断 `04_成卡_v1.md`；任一模块失败，`industry_card_status=NOT_READY`。

`05_源出处表.md` 仍使用固定 9 列，不新增「F」「E」等级：

- `等级` 只写 `L1-A／L1-B／L1-C／L1-D／L2／L3／U／W／R`。
- `用途=框架规则` 时，校验器内部映射为 `F`；它表示结构框架，不是来源等级。
- `用途=执行建议` 时，校验器内部映射为 `E`；它表示带成立条件的候选动作，不是来源等级。实验设计记设计日期；涉及平台功能、政策、价格或资格等时效事实时，另记当期核验日期。

旧的 8 列源表不能直接重跑 3A。只有本次任务触及该旧产物时，才先补齐「用途」并迁移为 9 列，同时写入 `evidence_schema` 与 `legacy_policy`；未触及的历史产物不批量改写。

每个模块可由以下任一路径放行：

### 路径 A：目标行业直接证据

同一行同时满足：

1. 来源直接描述目标行业、交易或交付分支。
2. `等级` 为 L1-A／B／C／D 或 L2。
3. `用途` 为 `行业判断` 或 `操作依据`。
4. 源编号／主体、路径／链接、章节／时间点均可定位。

### 路径 B：框架规则加行业事实

同一模块同时存在两行：

1. 一行 `用途=框架规则`，说明该模块采用的结构或判别方法，并给出可定位来源。
2. 一行目标行业 L1／L2，`用途=行业判断` 或 `失效边界`，给出该行业的主体、对象、限制或反例。

`F` 单独不放行，也不能证明当期平台组件可用、行业容量瓶颈、任何数字或某个商户的当前状态。路径 B 只是允许框架承载行业事实，不能把通用方法冒充行业结论。

`E` 不计入路径 A 或 B。执行建议只能写成带条件的候选动作或实验设计，并标明成立条件与停止条件；实验设计记设计日期，涉及时效事实时另记当期核验日期。它不能证明当期平台能力、行业瓶颈、数字或商户现状。

逐条有源的变量不能自动合成为有源关系。若来源只分别提到人员、库存、房态、清洁、用品或服务过程，却没有直接说明它们共同构成容量公式、必须同时闭合或任一项触发停止，则该组合关系必须写成 `E`，不能继续用 `行业判断`／`操作依据` 冒充直接行业事实。

即使旧 L1／L2 直接提到某个平台组件，也只证明源发布时的说法，不自动证明当前仍可用。此类内容若保留，只能降为 `E` 并另做当期核验；行业结构应写组件承担的任务、责任和合规边界。

运行 Node 校验器后读取 `checks.source_table`，再人工确认每个候选行业行确实描述目标行业，而不是只在源名里出现行业词。7 个模块全部通过，3A 才通过。

## 闸门 3B：商户落地准备度

3B 不阻断行业卡，只计算 `merchant_readiness`。具体账号入口、平台权限、响应人、排班、席位、经营基线和具体阈值没有当前商户证据时，不留在成卡里当缺口，统一写入 `07_商户执行前核验清单.md`。

`07_商户执行前核验清单.md` 固定契约：

```markdown
# 商户执行前核验清单

商户落地状态（merchant_readiness）：NOT_CALIBRATED

- 核验主体：
- 核验日期：

## 核验项

- [ ] `M01_ENTRY_PERMISSION` 实际唯一入口及当期平台权限已回读。
  - 当前值／证据路径／核验日期／责任人：
- [ ] `M02_RESPONSE_OWNERSHIP` 首次响应责任人、响应时限与升级路径已确认。
  - 当前值／证据路径／核验日期／责任人：
- [ ] `M03_CAPACITY_BOTTLENECK` 当前容量、已占用量与首个容量瓶颈已由台账确认。
  - 当前值／证据路径／核验日期／责任人：
- [ ] `M04_BASELINE_ATTRIBUTION` 经营基线、归因窗口与数据口径已留存。

```

5 个稳定 ID 是机器契约，中文说明可按行业具体化，但不得增删、重复或改名。5 项全部勾选时必须记为 `merchant_readiness=READY`；存在任一未勾选项时必须记为 `NOT_CALIBRATED`。Node 检查固定 ID、checkbox 数量、双向状态一致性；人工负责确认每项中文说明与证据确实覆盖当前行业的入口、责任、容量、基线和停止条件。`06_校验报告.md` 与 `07_商户执行前核验清单.md` 的状态必须一致。`merchant_readiness=NOT_CALIBRATED` 不改变已经通过 3A 的 `industry_card_status`，也不阻断 `04_成卡_v1.md`。

## 闸门 4：反例或失效边界

目标：至少 1 条反例或失效边界能具体限制主打法，不是泛泛写「因人而异」。

```bash
rg -n '反例|失效边界|不适用|不成立|停止线|停止条件' "$PLAYBOOK_CHECK_FILE" "$PLAYBOOK_SOURCE_FILE"
```

预期：至少 1 条命中，且能回答：什么条件出现、哪个判断失效、应该停止或改走什么。只有「注意风险」「具体情况具体分析」不算。

## 闸门 5：数字属性覆盖

目标：正文中的数量、金额、周期、比例、容量和阈值 100% 带五类数字属性之一；模块编号、标题编号和表格序号不参与。

读取 Node JSON 的 `checks.digits`。校验器只把半角 `[0-9]` 当正文数字；全角 `０１２３４５６７８９` 单独判为格式错误，不使用跨 locale 的多字节字符范围。

预期：没有未标属性的半角数字，也没有全角数字。无法确定单位、主体、时间、地区或分母的数字不能靠补一个标签放行，应回到源记录标「待确认」并从成卡删除。

同一数字如果跨行出现，属性标签放在数字所在行。文件名和源编号只允许出现在审计表，不进入正式卡正文。正式卡中的 `E` 若是实验设计，设计日期可以进入正文；若引用平台功能、政策、价格或资格等时效事实，核验日期可以进入正文。两类日期都必须使用半角数字，并在同一行标为 `[数字属性：执行建议值]`，同时在 `05_源出处表.md` 留下成立条件与可定位来源。

## 闸门 6：缺口话术零容忍

目标：`04_成卡_v1.md` 不含草案占位、过程性审计语言和旧模板句。

读取 Node JSON 的 `checks.placeholders`。草案允许保留结构化缺口，但正式卡出现任一过程占位即失败。商户本地待填值只能留在 `07_商户执行前核验清单.md`，不能改写成委婉占位继续放进成卡。

## 二、成卡结构检查

读取 Node JSON 的 `checks.card_structure`。固定 7 个模块标题必须各出现 1 次；草案与成卡使用同一标题契约。

## 四、盲测回归协议

回归模式只给生成者行业名，不给 V3 成卡正文、预期答案、答案定位、评审夹具或失败猜测。生成者可查标题、覆盖等级、源编号和原始 L1／L2，但不得读取被测卡在当前 V3 或带源工作稿中的正文。独立评审不得先读候选稿：先从目标卡与允许源建立隐藏清单并保存，再读取候选稿评分。生成者与评审不得由同一上下文先后兼任。

### A 类校准组

由独立评审从用户自己的证据充分行业中选择校准样本。已参与规则修订或已暴露答案的样本标为 `KNOWN_REGRESSION`；此前未暴露答案的新样本才可标为 `CLEAN_BLIND`。记录实际分布并分栏报告暴露状态，不把已知回归包装成独立盲测。

每张记录：

- **取料完整性：** 独立评审逐项确认 `01_取料记录.md` 是否读到对应 L1／L2、给出具体位置并正确转述。它不判断项目是否进入正文。
- **内容召回：** 独立评审先从当前 V3 目标卡提取行业专有语义事实，并在读取候选稿前标出会改变交易、分支、证据、承接或停止边界的关键事实；随后分别报告关键事实召回和整体内容召回，不按关键词出现次数计分。
- **评估文件命名：** 有 `04_成卡_v1.md` 才报告「成卡内容召回」，否则只报告「草案内容召回」。
- **有源未入稿：** 每项记录源位置、没有进入评估文件的原因，以及属于合理排除、漏写还是越界源。
- **提问质量：** 本地已有答案数目标为 0。
- **闸门与回源：** 分别记录 1、2、3A、3B、4、5、6 的结果，以及每条放行结论的具体来源位置。

阈值先测后锁：前三次运行的 `regression_threshold_status=OBSERVATION_ONLY`，只记录分布，不启用通过线，也不得据此宣称回归达标。关键事实召回保留 `100%` 作为唯一候选目标，但观察期内它不是硬闸门；若实测低于该目标，先检查事实定义、取料与生成链，不得把目标降成 `5／7` 或用删减关键项来过线。三次都完成独立评审后，关键事实候选目标最多标为 `PROVISIONAL`，取料完整性与整体内容召回的候选值再按实际分布提出。只要存在已知回归样本，就仍需更多 `CLEAN_BLIND` 样本与反例，才能另行决定是否正式锁定任何阈值。本阶段不采用 `5／7`、`7／9` 或其他预设比例作为当前通过线。

任何隐藏清单都不得从本文件或其他生成者必读参考文件链接，也不得由生成者主动查找。若答案曾进入生成上下文，该轮必须标记为泄漏并从校准样本剔除。

### B 类新行业实测

合成边界示例：若某服务类别只有通用命名材料，而没有工艺、收送、定价和责任的专属源，应测试系统能否诚实保留 B／C 差异。该例不是实际行业结论。

通过标准：

- 诚实保留 B／C 分支差异。
- 不写无源的服务流程、价格、效果或赔付规则。
- 输出 `02_草案_v1.md` 与 `03_采集清单.md`。

## 五、Skill 本体静态验收

在 `liang-skill` 仓库根目录运行：

```bash
node scripts/validate-skill-tree.mjs
git diff --check -- README.md skills/liang/SKILL.md scripts/validate-skill-tree.mjs
for PLAYBOOK_NEW_FILE in skills/liang-playbook/*.md; do
  PLAYBOOK_CHECK_OUTPUT="$(git diff --no-index --check /dev/null "$PLAYBOOK_NEW_FILE" 2>&1)"
  PLAYBOOK_CHECK_STATUS=$?
  test "$PLAYBOOK_CHECK_STATUS" -eq 1
  test -z "$PLAYBOOK_CHECK_OUTPUT"
done
bash scripts/install-local.sh
```

`git diff --no-index` 对合法的新文件也因「存在差异」返回 1，上面的循环把 1 作为预期，只在出现空白错误或其他状态时失败。

仓库官方 `quick_validate.py` 不接受现有项目使用的 `argument-hint`，不能把它的该项失败误判为 Skill 正文失败；本仓库以 `scripts/validate-skill-tree.mjs` 为 frontmatter 与资源结构主闸门。
