# liang-playbook 提问模板

问题不是自由生成的访谈提纲，而是 7 模块逐格扫描后的证据请求。先分清「研究缺口」与「落地填值」：研究缺口会改变行业结构，只有它可以阻断行业成卡；落地填值只补某家商户的当前入口、责任、容量与基线，缺少时只把商户落地状态标为未校准。

## 一、出题前检查

每个候选问题先过 5 项：

1. 先标类型为「研究缺口」或「落地填值」，不能一题同时承担两类任务。
2. 已读完相关 L1／L2，而不是只做关键词检索。
3. 当前 V3、覆盖审计、覆盖底表、回源表和增量源里没有对应层级的答案。
4. 研究缺口的回答会改变行业结构、分支、选题、承接逻辑或停止条件类别；落地填值只改变当前商户配置与放量准备度。
5. 能说清需要哪一种证据，不以「你怎么看」收尾。

任一项不成立就删题。

## 二、问题三件套

研究缺口写入 `03_采集清单.md`；落地填值写入 `07_商户执行前核验清单.md`。两类问题都使用下面的固定格式，但不能混算阻断项：

```markdown
### Q01｜研究必答｜一次真实咨询里的前三个原话问题

- 类型：研究缺口。
- 影响：模块 2「表层诉求与真实关切」与模块 5「引流获客类选题」。
- 已查：S001、S002、S003（合成格式示例） 的 L1／L2 全章；只找到行业框架，没有家属咨询原话。
- 需要：最近一次真实咨询中，对方最先问的前 3 个问题；按原话或脱敏转述逐条写，并注明咨询发生月份和对方角色。
- 可接受证据：脱敏聊天记录、咨询录音转写、当事人逐句回忆。
- 不接受：「客户都很在意服务」「大家主要问价格」一类概括。
- 成卡影响：进入正式语料层、保留完整上下文并回读为目标行业 `L1／L2` 后，可用于补行业结构；仅有 `U` 回答时仍阻断对应行业判断。
- 回答：
- 证据等级：待回填。
- 数字属性：无数字则写「不适用」。
- 日期类型：材料发生日期；若后续转为实验设计，另记设计日期。
```

三件套是：影响什么、已经查过哪里、需要什么证据形态。每题还必须写类型和成卡影响。题目本身再限定一件真实事件、一个角色和一个时间范围。

## 三、单轮预算与分级

单轮最多 12 题。少于 12 题不是缺陷，查得到的内容越多，问题应越少。

| 档位 | 定义 | 数量建议 | 用户不答的结果 |
|---|---|---:|---|
| 研究必答 | 缺少会让 7 模块中的行业结构无合法证据 | 1 至 6 | 保留草案，不生成 `04_成卡_v1.md` |
| 研究可选 | 能增加反例、分支或表达具体度，但不改变主交易链 | 0 至 4 | 标明未覆盖范围，不硬写 |
| 落地填值 | 补当前入口、责任人、容量、基线和具体阈值 | 0 至 6 | 不阻断行业成卡，只标商户落地未校准 |
| 观察任务 | 当前没有现成记录，需要用户或研究者去现场采集 | 0 至 4 | 按实际目的归入研究缺口或落地填值，不要求当场作答 |

数量是问题预算，不是必须凑满的配额。超过 12 题时先保留会阻断行业成卡的研究必答，再保留最影响落地安全的填值项。

## 四、把开放题改成两类事实题

### A. 研究缺口：问可形成行业证据的事实

| 禁止问法 | 改成 |
|---|---|
| 你怎么看这个行业？ | 请补 1 段目标交易的完整原始材料：用户在什么事件后进入购买，比较过什么，供应方承担什么责任，最终如何交付；保留上下文与来源位置。 |
| 目标用户是谁？ | 在目标行业已落盘材料中，哪几段直接出现使用者、付款者与拍板者？分别给原话、角色和反例；没有时新增一份完整访谈或交易记录。 |
| 客户最关心什么？ | 请补一份含咨询前 3 个原话问题及后续动作的完整材料，说明发生时间、提问者角色和是否进入报价或预约。 |
| 这个行业怎样承接？ | 请补一段能证明入口承担什么任务、由谁负责、最少收什么信息以及何时退出的目标行业流程记录。 |
| 容量怎样算？ | 请补一段目标交易在高峰或失败时的完整记录，指出哪类资源先到上限、出现什么后停止承接，并保留反例。 |

研究缺口只有两条放行路径：目标行业直接 `L1／L2`，或已验收框架规则 `F` 加至少 1 条目标行业 `L1／L2` 证明交易变量或特殊边界。`F` 单独不能回答平台当前能力、行业特有瓶颈、数字阈值或商户现状。新采访谈先标 `U`；只有完整落盘、保留上下文并回读后，才按正式语料层重新定级。

### B. 落地填值：问当前商户事实

| 禁止问法 | 改成 |
|---|---|
| 目标用户是谁？ | 最近 3 笔真实成交中，使用者、付款者、拍板者分别是谁？若不是同一人，按每笔列出。 |
| 什么内容效果好？ | 最近 1 条带来合格咨询的内容，用户从哪一句或哪个画面进入咨询？后续是否付款、退款或投诉？ |
| 入口是什么？ | 当前账号实际可用的唯一官方入口是什么？给页面回读、权限状态、表单字段、响应人与响应时限。 |
| 能接多少客户？ | 在当前交付窗口内，人员、工位、库存、设备和售后各自上限是多少？当前占用多少，哪一项最先成为瓶颈？ |
| 什么时候停？ | 当前可承受损失、容量、投诉退款与安全合规阈值分别是什么？给台账、责任人与关停动作。 |

落地填值不进入行业成卡的缺口计数。平台能力或政策作为当前事实时记录核验日期；首轮条数、观察窗口与保守阈值属于实验设计时记录设计日期、成立条件和调整条件。

## 五、四条补料通道

### 通道 A：新采逐字稿

适用：B／C 类缺少行业专属事实，需要新增公开内容或访谈材料。

给用户的任务必须包含：

```text
采集对象：<账号名／从业者角色>
建议数量：A 类补充 1 至 2 条；B 类 2 至 5 条；C 类 5 至 10 条
优先找：<交易过程／用户问题／失败案例／履约边界>
保存层级：原始音视频或原文 → 完整转写 → 章节摘要 → 逐条拆解
命名格式：<源编号>_<作品ID>_<层级后缀>
落盘位置：语料库/<账号>/抖音研究/<日期>/逐字稿/ 或 逐条拆解/
验收：原文非空、主体与时间明确、能指到完整段落，不只保存链接
```

新采材料只有在真实落盘并回读后才标 L1／L2。尚未采集的任务不算证据。

### 通道 B：一手观察或从业者访谈

每个问题给 3 列：

| 主问题 | 对方答不上来时改问具体事实 | 答不上来本身说明什么 |
|---|---|---|
| 最近一次客户为什么现在来？ | 那天先发生了什么，对方在联系你前试过什么？ | 成交触发尚未被业务记录，模块 3 不能定稿 |
| 客户真正怕什么？ | 最近一次退款、犹豫或流失时，对方原话是什么？ | 只有正向销售说法，缺反例与失效边界 |
| 你们能接多少？ | 上一次忙不过来时，先卡在人员、时段、设备、库存还是售后？ | 容量上限没有经过真实高峰验证 |
| 用户为什么选你？ | 最近一位成交客户具体比较过谁、看了什么证据、在哪一步付款？ | 所谓优势可能只是经营者自述 |

访谈回来统一标 `U`。有录音或聊天记录也不自动变 L1；只有进入正式语料层、保留完整上下文并回读后，才按新采材料重新定级。

### 通道 C：Agent 联网

联网只走 gstack `/browse`。先写检索任务，再执行：

```text
核验对象：<平台功能／政策／价格／资格／院校／公开案例>
截止日期：<YYYY-MM-DD>
地区与平台：<明确范围>
优先来源：官方规则、监管部门、机构原始页面、当事方公开记录
需要返回：结论、直接链接、发布日期或更新时间、适用范围、相互冲突的来源
禁止返回：搜索摘要拼接、无日期转载、把单案例变成行业规律
```

结果标 `W`。只有核验当期平台能力或政策事实时附核验日期；单个网页不能独立支撑模块 4 至 7 的长期操作规则，也不能替代目标行业 `L1／L2`。实验条数、观察窗口和保守阈值不写核验日期，改记设计日期、成立条件与调整条件。

### 通道 D：其他 Agent 深度研究

研究任务书可直接复制：

```text
研究主题：<具体行业＋具体交易>
要回答的唯一问题：<会改变哪个模块的判断>
已知材料：<本地已读源与已有结论>
证据要求：每条结论必须指到具体来源、日期和原文位置；区分官方事实、当事人主张、研究者推断
反证要求：至少寻找 1 个反例、失败案例或不适用条件
禁止：只给框架、只列搜索结果、引用无法打开的二手摘要
返回格式：结论｜来源｜日期｜证据等级｜适用边界｜反例
```

结果标 `R`。指不到具体来源的只作假设；即使多个 Agent 得到同一句话，也不能把相互抄写当独立交叉验证。

## 六、按模块分别扫描研究缺口与落地填值

| 模块 | 研究缺口，缺少可阻断行业成卡 | 落地填值，不阻断行业成卡 |
|---|---|---|
| 1 行业与交易 | 交易对象、责任、交付、核心存量、成立要素与行业瓶颈 | 当前主推产品、合同边界、库存、排班与实际容量 |
| 2 用户分析 | 有源的用户处境、常见角色关系、真实关切、反例与排除边界 | 最近成交的实际付款者、拍板者、心理账户与比例 |
| 3 购买因果 | 目标交易的触发、旧办法、购买结果与付款前证据链 | 当前商户最近一次从触发到付款的时间线与基线 |
| 4 分情况 | 源中真实存在的交易、载体、用户或交付分支及差异证据 | 当前商户实际经营哪个分支、可交付到哪里 |
| 5 选题 | 行业原话、真实过程、可拍证据与具体反例 | 当前可拍素材、授权状态、内容存量与历史效果 |
| 6 承接 | 入口职责、责任主体、最少信息、置顶职责、容量变量与瓶颈判法 | 当前入口、权限、表单、响应人、时限、排班与占用 |
| 7 验证 | 首轮验证对象、业务指标链、停止条件类别与风险边界 | 当前基线、发布频率、窗口、具体阈值、最大损失与关停责任人 |

## 七、回答回填格式

每个回答保留原始层与判断层：

```markdown
#### 用户原始回答

<原文，不润色>

#### 证据判定

- 类型：<研究缺口／落地填值>
- 字段层：<行业结构／执行建议／商户现状>
- 用途：<行业判断／操作依据／框架规则／执行建议／案例背景／失效边界>
- 来源等级：U
- 主体与日期：<谁／何时>
- 支持：<只写能证明的判断>
- 不支持：<不能外推的判断>
- 数字属性：<五分类之一／不适用／待确认>
- 日期类型：<材料发生日期／核验日期／设计日期／不适用>
- 是否阻断行业成卡：<是／否；原因>
- 需要交叉验证：<是／否；缺什么>

#### 回填位置

- 模块：<1 至 7>
- 处理：<写入草案／仅进案例背景／进入商户落地清单／仍保留研究缺口>
```

## 八、问题质量验收

出题后逐题核对：

- 本地已有答案数必须为 0。
- 研究缺口数与落地填值数分开统计；只有研究缺口可以阻断行业成卡。
- 每条行业结构的预期放行路径必须写成 `A：目标行业直接 L1／L2`，或 `B：F + 目标行业 L1／L2`；只有 `F` 时问题仍未关闭。
- `F`、`E` 只对应「用途」中的框架规则、执行建议；来源等级仍按真实材料填写，不能写成 `F` 或 `E`。
- 每题只影响一个主要判断；同时影响多个模块时写主模块与连带影响。
- 每题都能在用户回复后判定「够／不够」，没有无限追问口。
- 不暗示答案，不把模型假设塞进问题前提。
- 用户已选择某条通道后，不再用另一种问法重复索取同一事实。
- 超过 12 题时，先按「是否阻止行业成卡」排序，再按商户落地风险排序，移除后半部分，不拆成多轮偷渡。
- 新建候选卡采用新口径；存量卡不批量补问，只有该卡因明确任务被修改时才随改随迁。
