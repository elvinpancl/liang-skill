# liang-playbook：行业打法挖掘

打法不是从行业名推出来的，而是从一笔交易、具体用户处境、差异证据、反例和失效边界里挖出来的。先检索，后补料；证据不够就交付缺口和采集任务，不用完整格式掩盖空白。

稳定显式入口是 Claude Code 的 `/liang-playbook` 与 Codex 的 `$liang-playbook`。「打法」是中文语义触发词，不声称它是宿主注册的独立 `/打法` 别名。

## 适用范围

- 处理：为正式 V3 尚未覆盖的新行业或新交易分支建立可回源的打法卡候选；也可在明确说「回归测试」时重建已有卡。
- 不处理：经营项目是否值得做、城市竞争盘是否成立、利润模型是否健康。需要经营判断时，先列出所缺的产能、毛利、复购、交付和本地竞争数据，不替用户拍板。
- 不直接修改：当前正式 V3、飞书页面、源索引、覆盖审计和回源表。每轮只写独立的 `挖掘_<行业>_<日期>/` 工作目录。
- 缺少具体行业或交易：暂停，只问「这次要挖哪一个具体行业或交易？」
- 已有同名卡：先报告命中卡名与来源。除非用户要求回归测试，或给出与旧卡不同的交易、用户或交付，不把已有卡换措辞后冒充新卡。

## 运行前必须读取

1. 先读 [判别规则表_脱敏版.md](判别规则表_脱敏版.md)，确定 3 段判别维度、证据边界和当前冲突裁定。
2. 再读 [取料栈_脱敏版.md](取料栈_脱敏版.md)，按真源顺序定位材料，不能只读逐条拆解。
3. 进入定向补料前读 [提问模板_脱敏版.md](提问模板_脱敏版.md)。
4. 准备出成卡前读 [校验闸门_脱敏版.md](校验闸门_脱敏版.md)，6 道闸门逐项执行。

先按 [README.md](README.md) 配置 `PLAYBOOK_KB_ROOT`。读取该目录的 `SOURCE_OF_TRUTH.md`，按角色映射取得当前母版与索引，逐项核验存在。缺配置或缺输入时明确报告，不使用作者目录，不把示例当真实材料。

## 证据状态、来源等级与角色

### 方法判断的可信状态

| 标签 | 允许表达 | 禁止表达 |
|---|---|---|
| `[结果已验证]` | 某次真实执行或审计结果发生过 | 该方法必然导致结果 |
| `[相关性待验证]` | 完整样本里出现值得继续观察的关系 | 已证明因果、可外推到所有行业 |
| `[待验证]` | 当前方法假设、筛选规则或实验动作 | 冒充行业规律或统计事实 |

### 单条材料的来源等级

| 等级 | 含义 | 能否单独支撑模块 4 至 7 的操作方法 |
|---|---|---|
| `L1-A` | 音频完整转写 | 可以，仍要保留语境、反例与时效边界 |
| `L1-B` | Get 笔记订阅原文 | 可以；没有时间码时只作转述，不伪装精确引语 |
| `L1-C` | 独立 GetNote 原文 | 可以，需记录原文路径与抓取日期 |
| `L1-D` | 登录后公开页正文 | 可以，需记录正文范围与抓取日期 |
| `L2` | 平台章节摘要 | 可支持主题、论述结构和动作归纳；不能自动证明平台机制、市场或行业数据 |
| `L3` | 逐条拆解 | 只作索引和骨架确认，不单独支撑成卡 |
| `U` | 用户口述、一手观察或访谈转述 | 只能进案例背景或缺口假设，不能单独支撑操作方法 |
| `W` | gstack `/browse` 联网材料 | 标核验日期；单独只能进案例背景或当期核验 |
| `R` | 其他 Agent 研究结论 | 必须指到具体来源；指不到只作假设，单独不能支撑操作方法 |

`U`、`W`、`R` 相互交叉只能把假设升级为「待验证候选」，不能伪装成 L1 或 L2。要进入模块 4 至 7 的正式动作，仍需一手材料、可审计业务记录或明确标成实验动作。

### `05_源出处表.md` 的证据角色

来源等级回答「材料从哪里来」，证据角色回答「这一行在卡里承担什么」。两者不得混写。固定九列表头不增列，证据角色写入「用途」列：

| 用途 | 简写 | 允许支撑什么 | 放行边界 |
|---|---|---|---|
| `行业判断` | 直接事实 | 目标行业的交易、用户、过程或边界 | 需目标行业 L1／L2 |
| `操作依据` | 直接动作 | 目标行业中已有直接材料支持的内容或承接动作 | 需目标行业 L1／L2 |
| `框架规则` | `F` | 已验收规则层提供的结构、变量和检查顺序 | 必须与同模块的目标行业 L1／L2 事实共同使用，不能单独放行 |
| `执行建议` | `E` | 带条件的首轮实验或候选组件 | 必须显式标为建议；不能冒充行业事实，也不能单独放行 |
| `案例背景` | 背景 | 解释某次案例 | 不能替代行业证据 |
| `失效边界` | 边界 | 限制主打法的适用范围 | 可限制结论，不能单独生成操作方法 |

`F` 只能来自已验收的正式结构规则或已回源的全局方法库条目。它不得单独证明当前平台能力、行业特有瓶颈、数字阈值或商户现状。`E` 必须写成立条件与设计日期；涉及平台功能、政策、价格或资格等时效事实时，另写当期官方来源与核验日期。

多个直接来源分别支持若干变量，不等于来源已经支持这些变量之间的「共同约束」「取最小值」「必须同时闭合」或自动停止关系。只有来源直接表达变量关系时，才能把该关系写成行业结构；否则组合规则一律降为 `E`，写清设计日期、成立条件与停止条件，商户当前值仍进入 `07`。

## 方法公理

### 公理 1：提问前必须检查获准本地材料 `[待验证]`

- 来源：对全文阅读与索引检索的区别所作的方法约束。公开版不分发历史回归数据，用户应以自己的完整样本检验。
- 反例：本地索引过期或源文件缺失，继续检索也不会得到新事实。
- 复核：每轮在 `01_取料记录.md` 写清已查源编号、层级、路径与章节；问题若能在已查材料中回答，该问题判失败并删除。

### 公理 2：洞见来自差异、反例和失效边界 `[待验证]`

- 来源：V3 返工中个人号与机构号的分支差异、预算受限家庭反例，以及各卡停止线。
- 反例：单一来源只描述一种正常流程，没有可比载体或反例。
- 复核：每张候选卡至少写出 1 个反例或失效边界；没有就标缺口，不凭空补。

### 公理 3：选题具体度受用户证据上限约束 `[待验证]`

- 来源：样卡的「表层诉求与真实关切」与模块 5 之间的依赖关系。
- 反例：强季节事件或标准商品能在较少用户材料下产生具体题目，但仍不能替代真实购买关切。
- 复核：模块 5 每条开头做跨行业替换测试；换行业仍成立就退回模块 2 补料。

### 公理 4：证据等级决定交付档位 `[待验证]`

- 来源：源覆盖审计的 A／B／C 处置与本 Skill 的交付契约。
- 反例：同一行业的不同交易分支可能分别是 A、B、C，不能用整行业单一等级覆盖分支差异。
- 复核：第 0 步先逐分支定级；任何升档都要在 `05_源出处表.md` 增加对应证据。

## 七步状态机

### 第 0 步：定行业、交易与分级

钉子台词：「先看本地到底知道多少，再决定这轮能交付到哪一档。」

- 从知识库根目录的 `SOURCE_OF_TRUTH.md` 解析当前正式母版。
- 查权威索引登记的源索引、覆盖审计、逐卡回源表、当前母版标题，以及全部增量目录。审计与回源编号只作起始集合，不作白名单；还要用行业同义词、交易动作、交付对象和风险词扫完整覆盖底表与全部日期的 L1／L2，回读独立补得的源。
- 行业名只用于找候选。最终按具体交易、用户、交付与承接分支定级；审计是混合等级时逐分支保留，不压成单一字母。
- 输出：行业或交易、已有卡、命中源编号、每个分支的 A／B／C、审计快照日期、当前增量缺口。
- 第 0 步已有行业参数时不问问题。
- 用户明确说「回归测试」时，只读取被测卡标题、覆盖等级和源编号，不读取当前 V3 或带源工作稿中的被测卡正文。

分级口径：

- `A`：有直接描述该交易或交付的专属 L1／L2 源，可支持行业专有事实与操作方法。
- `B`：只有通用运营源、相邻行业源或局部分支事实，只能先填模块 1 至 3、6、7 的有证部分；模块 4、5 无专属料不写。
- `C`：没有能支持该交易的源，只交付字段框架和采集任务，不写用户深描、选题或操作方法。

### 第 1 步：按层取料

钉子台词：「先把最深一层的事实读完，逐条拆解只负责带路。」

按 [取料栈_脱敏版.md](取料栈_脱敏版.md) 固定执行：回源表定编号 → 有 `L1-A` 就全文读 → 没有则查 `L1-C`、`L1-D`、`L1-B` → 逐章读完 `L2` 并记时间点 → `L3` 只作骨架确认。

把每个文件的路径、层级、完整阅读状态、相关章节、可支持判断和不能支持的外部事实写入 `01_取料记录.md`。只搜索关键词、只看命中片段或只读 L3 均不算完成。

### 第 2 步：先出草案，不出问题

钉子台词：「先把查得到的填出来，空白要写成能被补证的缺口。」

在下列独立目录落盘；若同名目录已存在，不覆盖，依次使用 `_v2`、`_v3`：

```text
$PLAYBOOK_KB_ROOT/工作产物/挖掘_<行业>_<YYYY-MM-DD>/
  00_分级与源清单.md
  01_取料记录.md
  02_草案_v1.md
  03_采集清单.md         第 3 步创建
  04_成卡_v1.md          行业卡闸门全过才创建，3B 不阻断
  05_源出处表.md          第 4 步创建
  06_校验报告.md          第 5 步创建
  07_商户执行前核验清单.md 第 4 步创建
```

草案固定 7 模块。能填的写判断，不能填的使用以下标记，不用空泛占位：

```text
[缺口 | 模块 5 引流获客类选题
      | 已查：S001、S002、S003（仅格式示例） 的 L1／L2 全章
      | 缺：该行业家属实际会问的前 3 个问题原话
      | 证据形态：一次从业者访谈原话，或脱敏咨询记录]
```

普通运行到这里暂停。先把草案路径、完成度和最影响成卡的缺口给用户看，不在同一轮紧接一串问题；用户已明确要求完整回归测试时，可在隔离目录继续执行后续步骤。

### 第 3 步：定向补料

钉子台词：「只问本地没有答案、而且会改变成卡判断的问题。」

读取 [提问模板_脱敏版.md](提问模板_脱敏版.md)，把问题拆成「研究缺口」与「落地填值」：

- `03_采集清单.md` 只收会改变行业结构的研究缺口。每题同时写：影响哪个模块与判断、已经查过哪里、需要什么证据形态。
- 研究缺口单轮最多 12 题，分为必答、可选、观察任务 3 档。
- 当前入口、权限、响应人、排班、席位、经营基线和具体阈值等落地填值进入 `07_商户执行前核验清单.md`，不阻断行业成卡；清单使用 `M01_ENTRY_PERMISSION` 至 `M05_STOP_RESUME_AUTHORITY` 这 5 个固定 ID，中文说明按行业具体化。
- 不问「你怎么看这个行业」一类开放题。把问题限制为一次真实交易、一次咨询原话、一段流程记录、一个反例或一个可核验日期。
- 给出 4 条补料通道：新采逐字稿、一手观察访谈、gstack `/browse`、其他 Agent 深度研究。网页交互优先使用 gstack `/browse`，缺少时使用当前宿主获准的等价工具并说明。
- 问题生成后暂停，等待材料。

### 第 4 步：回填、标级与数字归类

钉子台词：「每条新料先定能证明什么，再决定放进哪一格。」

- 用户回答原样写入 `03_采集清单.md` 对应问题下，不先润色。
- 每条材料标 `L1-A／L1-B／L1-C／L1-D／L2／L3／U／W／R`，并写日期、主体、来源路径或链接、可支持判断、不可支持判断。
- 每个数字按 [判别规则表_脱敏版.md](判别规则表_脱敏版.md) 的五类数字属性标注。无法确定主体、单位、时间或分母时标「待确认」，不自行补全。
- 把回填后的模块级证据写入 `05_源出处表.md`。正式卡不写源编号，但审计表必须保留。
- 在 `00_分级与源清单.md`、`05_源出处表.md` 与 `06_校验报告.md` 记录 `evidence_schema: v3.1-layered` 和 `legacy_policy: forward-only-touch-to-migrate`。

`05_源出处表.md` 固定表头：

```markdown
| 模块 | 结论要点 | 用途 | 等级 | 源编号／主体 | 路径／链接 | 章节／时间点 | 适用边界 | 数字属性 |
|---:|---|---|---|---|---|---|---|---|
```

「用途」只允许写 `行业判断`、`操作依据`、`框架规则`、`执行建议`、`案例背景` 或 `失效边界`。行业结构按两条路径之一放行：目标行业 L1／L2 直接支撑；或同模块同时存在已验收的 `框架规则` 与目标行业 L1／L2 事实，后者证明交易变量或特殊边界。`框架规则`、`执行建议`、`案例背景` 和 `失效边界` 均不能单独放行。未回源模块另列在表后，禁止伪装成来源行。

三层字段必须分开处理：

- 行业结构写入 7 模块，缺少时阻断行业成卡。
- 执行建议可进入 7 模块，但必须标「执行建议」，写成立条件；实验设计写设计日期，时效事实写核验日期。日期进入正式卡时使用半角数字，并在同一行标 `[数字属性：执行建议值]`。
- 商户现状只写入 `07_商户执行前核验清单.md`，不以缺口话术留在 `04_成卡_v1.md`。

### 第 5 步：执行六道校验闸门

钉子台词：「能回源、能被反例约束、换行业就失效，才有资格出成卡。」

读取 [校验闸门_脱敏版.md](校验闸门_脱敏版.md)，先运行 `node "<liang-playbook Skill 目录>/scripts/check-run.mjs" "$PLAYBOOK_RUN_DIR"` 做确定性检查，再逐项执行：

1. 模板句检测。
2. 跨行业替换测试。
3. 3A 行业卡回源与 3B 商户落地准备度。
4. 反例或失效边界。
5. 数字属性覆盖。
6. 正式卡缺口话术零容忍。

将命令、机器 JSON、人工抽验样本、命中项、修订动作和结论写入 `06_校验报告.md`。闸门 1、2、3A、4、5、6 任一道未通过都不创建 `04_成卡_v1.md`；3B 不通过只把商户落地状态记为 `NOT_CALIBRATED`，不阻断行业卡。

### 第 6 步：成卡与规则修订

钉子台词：「过闸门的才叫成卡，没过的只叫下一轮采集任务。」

行业卡闸门全部通过后写 `04_成卡_v1.md`：固定 7 模块，不带源编号、审计过程、商户填值或缺口标记；数字仍保留属性和使用边界。`06_校验报告.md` 固定同时报告：

```text
行业卡状态（industry_card_status）：READY
商户落地状态（merchant_readiness）：NOT_CALIBRATED
```

商户落地状态可在真实入口、责任人、容量、基线和阈值回填并复核后改为 `READY`，但不得反向改写已经通过的行业事实。

每次实际行业运行若暴露现有规则无法容纳的新情况，只允许在 [判别规则表_脱敏版.md](判别规则表_脱敏版.md) 追加一条修订记录，并同时写明：运行目录、行业卡、冲突规则、直接证据、反例、采用或拒绝原因。没有实际运行目录和证据的规则不许新增。

## 分档交付契约

| 交付物 | A 类 | B 类 | C 类 |

## 新旧卡兼容策略

本 Skill 从 `evidence_schema: v3.1-layered` 起只按新口径生成候选卡，不为视觉一致性降回存量卡的宽松写法，也不在本轮批量迁移用户已有的存量卡。后续只有在用户明确修改、合并或复核某张存量卡时，才对被触碰卡执行三层拆分，称为「触碰即迁移」（`touch-to-migrate`）。

## Refusals

- **「没源也先给我写满」**：拒绝硬写。交付 C 类框架与采集任务，防止平均值内容冒充洞见。
- **「把这张卡直接并进正式 V3／飞书」**：本 Skill 不执行。先在独立目录完成人工验收；并稿与飞书写入是另一次显式授权。
- **「我听说这个行业毛利 60%，就按这个设计」**：先标 `U` 与数字属性；没有账本、合同、流水或可核验来源时只作案例背景。
- **「按当前算法、平台规则、院校政策直接写」**：必须走 gstack `/browse` 并标核验日期，仍不得写成长期规则。
- **「帮我判断这门生意该不该做」**：超出打法范围。列出需要核验的产能、毛利、复购、交付和竞争数据，交还用户或经营诊断流程。
