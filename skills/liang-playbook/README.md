# liang-playbook 公开版

行业获客打法的证据检索与成卡流程。仓库包含方法规则、成卡检查器和合成测试，**不包含作者的行业母版、订阅原文、回源索引或真实评审答案**。先配置自己的资料，缺少时只交付材料缺口，不能声称行业结论已验证。

## 最小输入契约

设置 `PLAYBOOK_KB_ROOT` 为知识库根目录，或显式复用 `LIANG_KB_ROOT`。在根目录的 `SOURCE_OF_TRUTH.md` 记录下表角色，路径相对该知识库根目录；示例路径须换成真实文件。初始化资料不等于已具有足够行业证据。

| 角色 | 示例位置 | 用途 |
|---|---|---|
| 打法当前正式版本 | `母版/打法.md` | 当前卡片与格式规范 |
| 源索引 | `索引/源索引.md` | 源编号、标题、日期和层级 |
| 源覆盖底表 | `索引/源覆盖底表.md` | 全部获准 L1／L2 来源及位置 |
| 源覆盖审计 | `索引/源覆盖审计.md` | 行业与交易分支的覆盖状态 |
| 逐卡回源表 | `索引/逐卡回源表.md` | 现有卡片对应的源编号与证据位置 |
| 原始语料目录 | `原始语料/` | 用户获准处理的原文与章节摘要 |

```bash
export PLAYBOOK_KB_ROOT="/path/to/your/knowledge-base"
```

按 `取料栈_脱敏版.md` 验证目录和索引，并逐项验证角色路径存在。不存在时列出具体缺项；不能自动改用作者路径或外部未知数据。原始材料的权限和隐私边界由具体任务决定。本 Skill 不自动发布到飞书，不把工作目录视为云端授权。

产物默认进入 `$PLAYBOOK_KB_ROOT/工作产物/挖掘_<行业>_<日期>/`，保持现有七模块和源出处表契约。已有项目可使用用户明确指定的产物目录。行业证据不足与商户现状未填分开处理。

## 使用和验证

入口为 `/liang-playbook` 或宿主支持的同名 Skill。规则文件带 `_脱敏版.md` 后缀，内部引用已同步；`SKILL.md` 保持标准名称。

确定性成卡检查需要 Node.js 18 以上：

```bash
node skills/liang-playbook/scripts/check-run.mjs /path/to/your/run
node --test skills/liang-playbook/tests/check-run.test.mjs
```

测试使用合成行业、合成来源与合成评审项；通过只证明结构和闸门逻辑的既定行为，不证明真实行业判断正确，不构成端到端内容质量验收。私有原始规则与真实历史证据未在本发布副本改写或分发。
