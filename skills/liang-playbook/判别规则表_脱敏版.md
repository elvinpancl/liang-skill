# liang-playbook 判别规则表

本表是 Skill 的规则层，不是新的行业事实库。它保存内容判断和证据分层的方法，应用时需结合用户自己的母版规范与直接材料核验。行业结论必须回到当轮源材料，不能仅引用本表。

## 真源与版本裁定

本文件是公开脱敏后的方法规则，不附带原始私有证据和校准历史。每轮先读取用户配置的 `$PLAYBOOK_KB_ROOT/SOURCE_OF_TRUTH.md`，按其角色映射定位当前正式母版、回源索引和实际语料，具体见 README.md。

母版与格式规范规定当前口径；带源工作稿只作回源；覆盖审计是有日期的快照；通用方法库只提供结构与检查方向。私有资料中的历史数量、编号与回归答案不随本公开版分发。所有行业事实、数字和经营判断必须由使用者的实际来源重新支持。

## 冲突裁定

### 1. 内容线名称

正式输出只使用：流量曝光类、引流获客类、IP人设类、品宣成交类。全局方法库的「精准／潜在 × 流量型／转化型／人设型」是人群与内容任务的交叉检查，不与四类内容线并列，也不替换其名称。

### 2. 成交触发类型

判据只取当前正式 V3 的心智唤起型、事件触发型、重大决策型、圈层认同型。其他理论深读材料是辅助参考，只能帮助理解，不得覆盖 V3。

### 3. 全局方法库的事实边界

平台章节摘要能支持主题、论述结构和动作归纳，不能自动证明算法、平台规则、用户规模、价格、收入、效果或行业均值。只有把当期平台能力、平台规则或政策写成事实时，才另走 gstack `/browse` 并标核验日期；实验设计改记设计日期，二者都与规则层隔离。

### 4. 交易属性第 1 维

本公开版采用「成交触发类型」，其余 8 维保持本表约定；用户项目有不同规范时先对齐字段，不默默混用。

### 5. 模块 2 的 11／12 歧义

模块 2 按 11 个维度验收，第 11 维「决策角色与排除对象」包含 2 个必写子字段：

- 消费决策中的角色。
- 非客户群体。

因此原子字段数是 12，维度数仍是 11。任何校验器必须同时说明采用哪一种计数。

### 6. 数字五分类

当前 V3 使用方法没有数字五分类原文。计划要求的五分类来自 V3 前代正式体系。本 Skill 保留它，只作为取料、草案和成卡的数字使用边界；来源必须写成「前代正式体系继承规则」，不得写成「当前 V3 第 8 条」。

### 7. 方法库的角色分开统计

内容论述结构、呈现与转化策略、实验步骤分别统计，逐项核对是否有直接来源。不能把执行建议或短期实验计划算作有证据支持的论述结构；总量必须从用户当前方法库计算，不沿用作者历史规模。

## 第一段：行业本质，这是什么生意

### 1. 先锁定一笔交易

同一个行业若同时卖商品、到店服务、方案、培训、加盟或影响力，应拆成不同交易。成交触发、证据、入口、履约与结果不同，就不能共用一张卡。

先写清：

```text
卖什么 → 谁使用 → 谁付款 → 谁拍板 → 何时触发 → 如何交付 → 如何验收 → 如何退出
```

### 2. 交易属性 9 维

| 维度 | 必答问题 | 不合格写法 |
|---|---|---|
| 成交触发类型 | 用户为什么在这个时点进入购买，主类型和次类型是什么 | 用行业名或复购节奏代替触发 |
| 成交半径 | 本地到店、同城上门、全国远程还是组织采购 | 只写「线上可做」 |
| 产品形态 | 标品、非标服务、方案、培训、结果交付或组合 | 把多种产品混成「服务」 |
| 客单水平 | 该交易相对高低及真实在售口径 | 无来源地写固定金额 |
| 决策周期 | 从触发到付款按分钟、天、周或销售周期记录 | 只写「长」或「短」 |
| 购买风险与比较成本 | 用户会比什么，选错损失落在哪里 | 只写「风险高」 |
| 结果可验证性 | 何时、由谁、用什么证据确认结果 | 把曝光或口碑当交付结果 |
| 复购与转介依赖 | 该交易是否靠重复购买、续费或关系转介 | 一次性交易写「复购顾客」 |
| 放量履约能力 | 人员、工位、库存、时段、设备、材料、售后中哪个先到上限 | 写「有上限」但不给计算口径 |

### 3. 四种成交触发

| 类型 | 进入购买的原因 | 内容先完成什么 | 常见下一步 |
|---|---|---|---|
| 心智唤起型 | 原本无明确计划，被场景、感受或结果唤起 | 把模糊欲望对应到具体消费场景 | 到店、商品页、查看当期方案 |
| 事件触发型 | 问题、任务或时间节点已发生 | 判断紧急程度、可做与不可做、响应边界 | 检查、预约、正式咨询 |
| 重大决策型 | 金额、失败代价、周期或参与角色多 | 证明适配、完整成本、责任和退出 | 评估、会议、试样、报价 |
| 圈层认同型 | 同时在判断是否属于这里、是否认同标准 | 展示持续行为、成员回应、规则和真实参与 | 活动、小额参与、持续观察 |

一条内容只承担一个主触发任务。补货、保养、复购、续费和维护属于成交后节奏；只有用完、到期、换季或经营节点真实发生时，才可归入事件触发型。

### 4. 核心存量、生意成立要素与放量前提

- 核心存量必须可清点：人、记录、资产或关系。拿掉后，交易链应明显失去成立条件。
- 一次性交易禁止用复购人数充当核心存量。
- 生意成立要素只列 3 至 5 项，必须是本行业和该交易专有的成立条件。
- 放量前提必须指向当前履约容量与可同步的官方入口，不写「模块 7 通过后才放量」。
- 尚未投产、开业或形成交付记录时，只能展示筹备、打样、调试和仍待验证事项，不把规划当成现有能力。

#### 本地即时消费的时点、半径与实时状态

本地到店且决策时间短的交易，取料时必须同时查 3 件事：用户在什么时点开始选、实际可达半径、当时能否交付。这些字段必须从目标交易的直接来源核验，不能替门店填写城市、菜单、价格、剩余量、等位或售罄状态。

反例：景区目的地店、预约宴请、跨城专程消费和长周期服务不服从「附近、现在就来」；遇到这些交易，改查预约窗口、计划半径与提前决策证据。该规则修改的是交易属性中的「成交半径」与「放量履约能力」：二者必须与触发时点连起来，不能各写一句静态描述。

#### 容量先分结构、建议与现状

行业结构层先从目标交易的直接材料中找出可能限制交付的资源，以及判断「哪一项最先到上限」的逻辑；商户现状层再用排班、工位、库存、设备、材料、时段、服务责任与当前占用填入真实值。不得在没有直接来源时把多项资源取最小值写成所有交易的固定公式，也不能替目标门店填写当前上限。

反例：纯外带店没有座位瓶颈，共享厨房、预约制服务、外包配送和单岗位服务的限制项不同。新卡可以写有源的容量变量、瓶颈判法与停止条件类别；为首轮验证补出的公式、样本或保守阈值属于执行建议，必须写成立条件与设计日期；实际资源数、当前占用、关停阈值和责任人属于商户现状，不阻断行业成卡，只阻断商户直接执行。

### 5. 是否适合公域获客

先看最终决策者是个人还是组织。个人决策可在内容中直接完成一部分认知与信任变化；组织、招标体系或极小众圈层通常还需销售、采购、审批和线下关系。这个判断只决定公域内容承担哪一段，不等于判断生意值不值得做。

## 第二段：用户决策，谁掏钱、为什么掏

### 1. 模块 2 的 11 个维度

| 维度 | 写清什么 |
|---|---|
| 人生阶段 | 当前阶段会做什么决定，不会做什么决定 |
| 收入结构 | 工资、经营、资产、租金或其他；是否掌握生产资料；这笔支出属于哪个心理账户 |
| 信息来源 | 平时从哪里获得判断，因此适合什么论证和语言 |
| 消费决策 | 跟什么比、看什么信号、怕什么、多久决定 |
| 当前用户处境 | 此刻发生了什么，为什么现在必须行动 |
| 现实约束 | 家庭、工作、时间、现金流、圈层、风险和周围人意见如何限制选择 |
| 表层诉求与真实关切 | 用户说出口的 X 与真正牵动他的 Y 有什么落差 |
| 服化道与拍摄场景 | 从收入结构、圈层与任务推出可信的出镜环境，不借用别人的身份 |
| 说话方式 | 从信息来源推出论证风格、案例密度和术语水平 |
| 潜在人群 | 尚未进入任务的人在什么条件下转入，处于哪一层意识 |
| 决策角色与排除对象 | 分开写使用者、付款者、决策者，以及具体不适合的人 |

收入结构不得把整个行业概括成同一阶层。例如，某来源只说明决策角色时，不能据此补出付款角色或占比。行业卡可保留有直接证据的常见角色与反例；某家商户的实际付款者、拍板者和比例由真实交易记录确认，缺少这些商户现状不阻断行业成卡。

### 2. 四行购买因果链

固定为 4 行，不再加节点：

```text
触发
→ 旧办法为什么不够
→ 他买的到底是什么结果
→ 什么证据出现才付款
```

每一行必须含行业专有事实。模块 1 的生意成立要素不能搬来替代「客户为什么会买」。

### 3. 客户意识五层

| 意识层 | 内容任务 |
|---|---|
| 未意识问题 | 用真实后果或场景让用户发现问题，不虚构恐惧 |
| 问题意识 | 帮助诊断原因，建立判断标准 |
| 方案意识 | 比较路径的成本、限制与适配条件 |
| 产品意识 | 解释为什么选这一类产品或服务，再给差异证据 |
| 购买意识 | 用过程、案例、规则、售后和风险披露消除最后顾虑 |

### 4. 差异、反例与失效边界

每张卡至少寻找 3 类信息中的 1 类：

- 同行业不同载体的对比，例如个人号与机构号。
- 能阻止整行业一刀切的反例，例如预算受限客户。
- 让打法停止成立的边界，例如履约容量、隐私、资质或不可验证结果。

找不到就进入采集清单，不由模型补一个看似合理的反例。

## 第三段：获客打法，怎么触达和转化

### 1. 模块 4 的分支轴

分支必须来自源中真实存在的交易、载体、用户或交付差异，不能按行业名称机械切词。每个分支写清：用户当下解决什么、主要怕什么、先证明什么、推向哪个动作。不同分支的核心优势必须不同。

同一交易出现多个候选分支轴时，按下面顺序裁定：

1. 若售卖对象、责任或验收不同，先拆成不同交易卡，不在模块 4 混写。
2. 对用户决策阶段、店型／载体、交付方式、新老阶段分别填写「当前任务、主要恐惧、所需证据、下一动作」。至少 2 格发生有源的实质变化，才构成主分支。
3. 用户决策任务与供应者形态都通过时，默认把用户当前任务作为主轴；只有供应者形态改变交易责任或交付证据时，才升为同级或另拆交易。
4. 新店／老店、创始人／团队等生命周期或人物差异通常是二级内容层，不得替代已经有直接源支持的用户任务或店型主分支。

证据边界：用户在不同决策阶段所需材料是否不同，必须回到对应行业的直接来源确认。反例是个人岗位与综合团队如果卖的是不同责任的服务，应在第 1 步先拆交易，不能强行按用户阶段合成一张卡。

### 2. 四类内容线

| 内容线 | 核心任务 | 主要证据 |
|---|---|---|
| 流量曝光类 | 用行业话题、场景、对比、新闻或可传播观察打开人群 | 真实事件、场景和可核验信息 |
| 引流获客类 | 回答正在解决的具体问题，说明适合谁、如何比较和怎样进入承接 | 过程、选择标准、成本、限制、下一步 |
| IP人设类 | 通过经历、判断、取舍和失败处理建立可信筛选 | 长期行为、经营判断、错误与修正 |
| 品宣成交类 | 展示产品、环境、过程、案例、价格条件、库存或交付状态 | 当前批次、现场、交付和售后 |

比例只用于首轮测试，四项相加为 100%。它不是平台规律或行业天然比例，发布后按合格咨询、成交、交付与复购校准。

### 3. 模块 5 至 7 的固定交付

- 模块 5：每个真实分支给 5 条选题，每条带可直接念的开头句；没有专属源时不写。
- 模块 6：唯一入口、承接选择、三条置顶内容、响应与容量。
- 模块 7：首轮动作、对标方式、风险边界，并把核心存量停止条件压成一行。
- 选题逐条做跨行业替换测试；换行业名仍成立就退回模块 2 补料。
- 只有把平台功能、平台规则或政策写成当期事实时，才必须另做核验并记录核验日期；首轮条数、观察窗口和保守阈值等实验设计记录设计日期，不伪装成已核验的外部事实。

#### 行业结构、执行建议与商户现状分层

新卡先判断字段属于哪一层，再决定能否进入正式行业卡。行业结构缺少合法证据时阻断 `04_成卡_v1.md`；执行建议可以进入行业卡，但必须写成立条件，当期平台能力、平台规则或政策事实记核验日期，实验设计记设计日期；商户现状不写成行业事实，缺少时只把商户落地状态标为未校准。

| 字段 | 行业结构 | 执行建议 | 商户现状 | 缺少时阻断什么 |
|---|---|---|---|---|
| 主人群、付款者、拍板者与心理账户 | 有源的常见角色关系、决策任务、反例与排除边界 | 需要优先验证的角色假设，写明适用条件与设计日期 | 最近真实交易中的使用者、付款者、拍板者及其比例 | 缺行业结构阻断行业成卡；缺商户值只阻断商户落地 |
| 唯一入口与平台能力 | 入口承担哪笔交易、责任主体、最少必要信息、单一路径与合规边界 | 候选平台组件或承接方式；写成条件式，涉及当期平台能力或政策时附核验日期 | 实际入口链接、当前权限、表单字段、响应人与响应时限 | 缺入口职责阻断行业成卡；缺当前配置只阻断商户落地 |
| 三条置顶与四类内容线 | 三条置顶各自承担的识别、证明与下一步职责；四类内容线服务的用户任务 | 首轮内容比例与排序，写成立条件和设计日期 | 当前内容存量、合格咨询、成交与交付数据 | 缺内容职责阻断行业成卡；缺比例校准不阻断成卡 |
| 首轮动作、周期与归因窗口 | 锁定一笔交易、一个主产品／结果、可观察的业务指标链与停止条件类别 | 首轮条数、观察窗口、保守实验动作与调整条件，记录设计日期 | 当前发布频率、成交周期、样本基线与可承受损失 | 缺验证结构阻断行业成卡；缺当前基线只阻断商户落地 |
| 容量与停止阈值 | 目标交易的容量变量、最先到顶的瓶颈判法、风险与停止条件类别 | 有证变量上的计算口径或保守阈值，写成立条件和设计日期 | 排班、资源占用、当前容量、责任人、关停动作与具体阈值 | 缺容量变量或停止类别阻断行业成卡；缺实际数字只阻断商户落地 |

行业结构层只有两条合法证据路径：

- `A`：目标行业或交易的直接 `L1／L2` 支持该判断。
- `B`：已验收框架规则 `F` 支持通用结构，同时至少 1 条目标行业或交易的 `L1／L2` 证明交易变量或特殊边界。

`F` 与 `E` 是用途角色，不是来源等级：`F` 表示框架规则，`E` 表示执行建议或实验设计。`05_源出处表.md` 继续使用既有 9 列，不新增 `F／E` 列；在「用途」中新增 `框架规则`、`执行建议` 两个取值，内部才分别映射为 `F`、`E`。「等级」仍填写该行真实的 `L1-A／B／C／D`、`L2`、`L3`、`U`、`W` 或 `R` 等来源等级，禁止把 `F`、`E` 写进「等级」。框架规则行要回指其验收所用的真实来源等级，不能把正式 V3 本身伪装成新的来源等级。路径 `B` 必须由「用途＝框架规则」的已验收规则行与至少 1 条目标行业 `L1／L2` 行共同成立，不能用一行 `等级＝F` 代替组合证据。

## 数字属性五分类

每个进入草案、成卡或实验的数字必须选 1 类，并保留主体、时间、地区、单位、分母与前置条件。

| 数字属性 | 含义 | 使用边界 |
|---|---|---|
| 明确动作数据 | 有明确场景、时长、条数、金额、周期或操作数量 | 保留前置条件，可作待验证动作，不能自动升级为行业标准 |
| 案例背景数据 | 某项目当时的价格、投入、成交、粉丝或经营数据 | 只解释该案例，不能当自己的预算或行业均值 |
| 未经核验的转述数据 | 账号、客户或第三方声称的安装量、收入、增长和效果 | 只能当线索，不能当效果证据 |
| 执行建议值 | 为把「多条、持续、小额、跑一轮」变成实验而补出的样本量与周期 | 先按本业务盈亏平衡点、产能和现金流调整 |
| 不采用数据 | 修辞、口误、识别不清、无数据集支撑的比例或夸张类比 | 不进入行业事实、预算、预测和承诺 |

数量单位残缺、前后矛盾、说话主体不明或缺分母时标「待确认」，不自行补全。只有作为当期事实使用的平台能力、平台规则或政策另标核验日期；首轮条数、观察窗口和保守阈值等实验设计标设计日期、成立条件与调整条件。
