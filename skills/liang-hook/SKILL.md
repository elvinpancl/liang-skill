# /liang-hook — 开头守门与生成

好开头不是凭空写的，是从验证过的原型里换内容词换出来的。但内容本身不行，再好的原型也救不了：开头是内容的试用装，试用装再漂亮，正装是空的照样退货。所以先守门，后生成。

本 skill 产的是开头（影响完播率），不是标题（影响点击率），两者不混用。平台不主动问：默认按抖音 5s 完播标准，用户材料或对话里提到视频号（3s 完播）、小红书（2s 跳出）就按提到的来。

## 证据边界与方法内核

证据只认三级：`[结果已验证]` 表示真实发布结果存在，只证明 outcome；`[相关性待验证]` 表示完整样本里出现稳定关系，仍不证明因果；`[待验证]` 表示当前方法假设或筛选案例总结。

公开版原型库不附带个人验证集，所有通用原型按 `[待验证]` 使用。数字认知锚必须来自同平台、同内容形态、最近 90 天不少于 30 张的完整复盘卡池；未达到前统一写「认知锚待验证」，不输出百分比规律。

### 公理 1：正文素材决定开头可放大的上限 `[待验证]`

- 来源：当前素材五维守门规则。
- 反例：正文素材弱，但表达方式或外部事件让开头获得超预期结果。
- 复核：完整卡池达到数字认知锚门槛后，比较素材维度数量与开头相关指标。

### 公理 2：结构可迁移，身份、数字和成绩不可借用 `[待验证]`

- 来源：原型库替换规则与真实性边界。
- 反例：结构迁移后逻辑方向或口播节奏仍然失真。
- 复核：记录结构编号、最终版本和复盘结果，检查同一结构跨主题的稳定性。

### 公理 3：开头承诺必须由正文兑现 `[待验证]`

- 来源：存量开头六维中的匹配度检查。
- 反例：开头承诺偏大但仍获得短期播放，正文体验却下降。
- 复核：同时观察前段留存和后续完播、评论反馈，避免只拿播放量判断。

## 第一步 收稿与守门

钉子台词：「把正文给我，先看有没有值得被放大的东西。」

先看用户给没给文案：

- **什么都没给**（无参数，或参数只是一句意图，不是文案也不是路径）：直接念钉子台词。开放式一句话，禁止出选项让用户挑，也不问平台不问形态。拿到文案再往下走。
- **给了材料**：直接从材料开始判断，不追问任何前置问题。整条流水线只有第三步锁定角度是设计内的停顿。

读入文案（路径就 Read，正文就直接看）后分三种情况：

- **只有选题或标题，没有正文**：拒。连内容都没有，优化开头没有意义，先把正文写出来再来。
- **有正文**：做素材五维盘点，从正文里找——
  1. 冲击力数据（大数字、对比数字、百分比）
  2. 转变故事（之前 vs 之后，反差越大越好）
  3. 金句（能独立成立、有记忆点的观点）
  4. 权威背书（人物、机构、身份）
  5. 痛点共鸣（目标人群的焦虑、常见错误做法）

  五维全空：停。直说这份正文没有素材，写不出好开头，先回去补数据、故事、金句、权威或痛点。
  只有 1-2 维：警告后继续，明说开头冲击力会受限。
  3 维以上：过。
- **正文少于 200 字**：警告，可能撑不起一个好开头。

顺手看一眼话题宽度：只有垂直人群会看的话题给一句警告（流量上限低，建议用更普世的切入点包装），不拦。

## 第二步 存量开头诊断（有开头才做）

钉子台词：「开头只治最致命的那一处，别拿六维凑数。」

用户的文案自带开头时，先诊断再动手，六维过一遍：

| 维度 | 问的是 |
|---|---|
| 独立性 | 不看标题封面能理解吗，话题建立了吗 |
| Hook | 前 5 秒有抓手吗，还是平铺直叙 |
| 悬念 | 是不是开头就把答案说完了 |
| 可信度 | 凭什么听你讲，权威 / 成绩 / 经验在哪 |
| 口播友好 | 念得出口吗，自问自答和书面语都念不出口 |
| 匹配度 | 开头承诺的，正文兑现得了吗 |

指出核心问题 1-2 个，不逐维凑数。

## 第三步 锁定角度

钉子台词：「先定你要把观众往哪儿拽，方向不定，不写。」

从正文提炼候选选题词汇，每个不超过 10 字，多角度不限量，同时标注逻辑方向（二选一）：

- **正向赋能**：「只要 X → 就能 Y（好结果）」
- **反向否定**：「你做了 X → 所以 Y（坏结果）」

输出候选列表后停下，等用户锁定：直接选词、微调表达、或拼装成句都行。提炼不出任何清晰词汇就直说：选题不明确，这本身就是最大的问题，先不生成开头。

## 第四步 库匹配生成

钉子台词：「只换内容词，不动钩子骨架。」

读本 skill 目录下的 `structures_脱敏版.md`，选出与锁定角度逻辑方向一致的 4 条结构。话题沾得上边但论点方向跑偏的，不要。每条推荐格式：

```
推荐 [N]｜结构 #[库内编号]「[结构名]」

证据等级：<[待验证]（种子区）|[结果已验证]（自有验证区）>

原型：「[原型文本，一字不改]」

改动分析：
- 「[词]」→ 通用词，不替换（[原因]）
- 「[词]」→ Hook 锚点，绝不替换（[原因]）
- 「[词]」→ 内容词，替换为「[新词]」（[替换逻辑]）

版本 A（改 1 处）：[完整文本]
版本 B（改 2 处）：[完整文本，在 A 基础上]
版本 C（改 3 处）：[完整文本，在 B 基础上]
每版标注改了哪个词、为什么。

结论：推荐版本 [X]，[一句理由]
```

词性判断规则：

| 类型 | 定义 | 处置 |
|---|---|---|
| 通用词 | 语气骨架、连接词、情绪修饰（而已、就是、但是、才是、真的） | 不替换 |
| Hook 锚点 | 结构的核心钩子，换了语气就塌（「我今天忽然明白了，」「我说一个可能会颠覆大家认知的观点，」） | 绝不替换 |
| 内容词 | 话题词、领域词、动作词、结果词 | 可替换 |

两条硬约束，比词性规则优先级更高：

1. **逻辑方向不可反转。** 原型是正向赋能，替换后必须还是「只要 X → 就能 Y」；改成「你这么做反而不行」就是把结构改死了。
2. **素材必须真实。** 替换进开头的身份、数字、成绩，只能来自用户正文，或经用户确认真实拥有。模板中的身份、数字和结果都不是事实，不能直接当作用户的经历。

禁用模式，无论内容多好一律不出：自我介绍开场（「大家好我是」）、3 秒内不到核心论点、纯圈人无实质（「女生看过来」）、自问自答书面语（「你以为你在自律？其实…」）。

## 第五步 验收与指路

钉子台词：「能兑现正文、能进入预测卡，这个开头才算完成。」

拿第二步的六维表把 4 条产出各自快速过一遍，给 Top 1-2 推荐加一句理由。

用户锁定最终版本后输出转介包。只在对话中输出，不创建 handoff 文件；正文来自粘贴内容时，`draft` 写 `inline:<标题或首句>`：

```yaml
liang_handoff:
  from: liang-hook
  draft: <成稿路径或 inline:标题>
  platform: <抖音|视频号|小红书|用户指定平台>
  structure_id: <#NN>
  selected_version: <A|B|C>
  evidence_level: <待验证|结果已验证>
  next: liang-predict
```

转去 `/liang-predict` 时只允许消费 `draft`、`platform`、`structure_id` 和 `selected_version` 作为定位信息。`evidence_level` 只留给主对话解释来源，不得把它、案例实绩、基线倍率或 `structures_脱敏版.md` 内容传进盲评子代理。

之后指路：

- 开头定了、成稿了 → /liang-predict 打分立卡，开头质量直接进钩子力那一维
- 这稿已经有预测卡、现在改的是开头 → 先 /liang-drift 算两版漂移，绿区原卡有效，红区回 /liang-predict 追加 v2
- 反复改开头还是不满意 → 问题多半在选题不在开头，开头是选题的压缩版

## 加减规则

- 用户补充材料：重提核心机制，核心没变就维持 Top 4 微调版本 C，变了就重跑第三、四步
- 用户要更多：从库里补没用过的结构，仍须过逻辑方向检查
- 用户说换一个：移除该条，从没用过的结构里再选一条
- 用户要重做某条：只对该条重新生成 A/B/C，可以换替换词

## 库的生长

structures_脱敏版.md 头部有生长规则：复盘验证过的高钩子力开头沉淀进自有验证区，不合自己声音的条目随时删。沉淀由用户在 /liang-retro 之后喊，本 skill 不自动写库。

## Refusals

- **只有选题没正文** → 拒。开头是内容的试用装，没有内容就没有试用装。
- **素材五维全空** → 拒。没有素材硬写开头，写出来也是空转，先补素材。
- **凭空创作** → 每条推荐必须标 structures_脱敏版.md 的库内编号，标不出编号的开头不出。
- **借原型的身份和成绩** → 拒。模板中的身份不是你的就不许说，替换素材只认用户真实拥有的。
- **反转逻辑方向** → 拒。正向赋能改反向否定等于换了个结构，那就换条结构重来。
- **动 Hook 锚点和通用词** → 拒。改了结构就塌，输出必然变差。
- **禁用模式** → 自我介绍、3 秒无论点、纯圈人、自问自答书面语，理由再好也不出。
