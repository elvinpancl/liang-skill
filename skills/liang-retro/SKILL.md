# /liang-retro — 对账复盘

立卡时赌得多痛快，复盘就要多诚实。这一步是整个闭环里唯一让评分卡变准的地方。

## 完整模式分流

`.liang-content-state.json` 存在时，读取并执行 [完整数据回收与复盘工作流](references/full-calibration-workflow.md)，按配置选择人工或 adapter 数据源，并同步 `ledger.md`、`script_patterns.md` 与 state；完成后不再重复执行下方轻量流程。状态文件不存在时继续下方 liang v1 流程。

完整模式只追加复盘内容，不得改写任何既有预测段。

## 第一步 取卡验时

定位预测卡（同 /liang-publish 的找卡方式）。检查两件事：

- 状态得是「已发布」。还是「已预测 / 已拍」就先去 /liang-publish 登记。
- 今天过没过「复盘到期」。没到：提醒还差几天——数据没走完窗口，复盘会把「慢热」误判成「哑火」。用户坚持就做，复盘段标注「提前复盘，数据未满窗口」。

把封存段的赌注原文引用出来，放在眼前对着看，不转述。

## 第二步 收数据

问用户要实际数据：核心量级（播放 / 阅读）必须有；完播率、点赞、评论数、转发有多少给多少。给了链接也一样让用户报数——本 skill 不假装能替所有平台抓数。

## 第三步 对账

1. 按 ledger.md 的基线算实际落在哪个档位（哑火 / 常规 / 出圈 / 爆款）。
2. 实际档位对赌注档位：赌对了，还是高估 / 低估了几档。
3. 对分布和中枢：实际档位在封存分布里的事前概率是多少，直接引用那一格。赌对了但事前只押 45%，和赌对了押 80%，是两种成色；赌错了但事前给过实际档位 30%，说明分布本身没瞎。再算偏差幅度：实际量级 ÷ 中枢，写成倍数或正负百分比。老卡没有分布或中枢就跳过这一项。
4. 复看封存段的维度分和一句话赌注：哪个维度的判断被数据支持，哪个看走眼。有评论数据就翻一眼，观众实际在反应什么，和打分时以为的卖点是不是一回事。
5. 对照反事实两行：赌偏了的，把封存段「若高一档 / 若低一档」里对应那行拎出来判定——当初点名的那个判断，真是这次翻车的原因吗？写对了是现成的观察，写错了本身也是观察（说明当时对风险源的判断有偏）。老卡没有这两行就跳过。
6. 对照赌注对账：封存段押了对照赌注的，拿本篇实际量级 ÷ 锚点卡的实际量级算出实际倍数，对押的倍数判输赢。两张综合分接近的卡实绩差出数倍，不论赢输，都是评分卡漏了维度的最强证据，直接写进观察。老卡没有这行就跳过。

在预测卡追加复盘段（不碰封存段任何字符）：

```markdown
## 复盘（YYYY-MM-DD）

- 实际数据：<量级 + 拿到的其他指标>
- 实际档位：<档位>（基线 <数字>）
- 对账：赌 <档位>，实际 <档位>，<对了 | 高估 N 档 | 低估 N 档>
- 事前概率：实际档位事前押了 X%（老卡无分布写「无（老卡）」）
- 偏差幅度：实际 ÷ 中枢 ≈ N 倍（<+X% | -X%>）（无中枢写「无（老卡）」）
- 反事实对照：<赌偏时引用对应那行并判定写对没写对；赌对了写「命中，未触发」；老卡写「无（老卡）」>
- 对照对账：赌 vs <卡名> N 倍，实际 M 倍，<赢|输|贴线>（老卡写「无（老卡）」）
- 看走眼的维度：<维度名 + 一句为什么>（没有就写「无」）
- 观察：<1-3 条，句式「<现象> → <对哪个维度 / 权重意味着什么>」>
```

Header `状态：已发布` 改成 `状态：已复盘`。

## 第四步 回写

- 把观察逐条追加进 `ledger.md` 的「观察」段，每条带日期和来源卡片名。已有同类观察就合并计数（「第 2 次出现」），不重复罗列。观察和基线只进账本，scorecard.md 是打分输入，一个实绩数字都不落。
- 用这篇的实际数据滚动更新 ledger.md 的基线（近 5-10 篇中位数）；「未定基线」攒到 3 篇就定初版基线。
- 数一下已复盘的卡：够 scorecard.md 里的升级门槛就提一句「校准池够了，观察也攒了几条，可以考虑 /liang-bump」。

## Refusals

- **改预测原文** →「当时那句赌注其实想说的是……」拒。引用只许原文，解释可以写进复盘段，但封存段一字不动。
- **只报「还行」不给数** → 没有数字就没法定档位，对账不了。等有数再来。
- **拿别人的稿复盘** → 校准池只收自己账号的卡。别人的爆款分析是另一回事，不进这条轨。
- **复盘完顺手改评分卡权重** → 观察只是证据，改权重是 /liang-bump 的事，那边有全量重打把关。
