# liang skill 制作模板

用于新增或重构 liang 家族 skill。按需删掉不适用的段落，不为凑模板制造无效字段。

## 1. Frontmatter

```yaml
---
name: liang-<动作>
description: <做什么、何时触发、关键边界、中文与英文触发词>
argument-hint: <用户输入>
allowed-tools: <完成任务所需的最小工具白名单>
---
```

- `name` 使用小写字母、数字和连字符，目录名与 `name` 一致。
- 把「何时使用」和触发词写进 `description`，不要埋在正文里。
- 只声明实际需要的工具。只读 skill 不给写权限。

## 2. 适用范围

先写清三件事：处理什么、不处理什么、缺少什么输入必须暂停。禁止用一句宽泛描述吞掉多个工作流。

```markdown
## 适用范围

- 处理：<任务>
- 不处理：<相邻但不同的任务，并给正确去向>
- 缺少 <关键输入>：暂停并只问 <最小问题>
```

## 3. 证据等级

所有世界观、公理、数字和案例必须标以下三级之一：

| 等级 | 允许的依据 | 能说什么 | 不能说什么 |
|---|---|---|---|
| `[结果已验证]` | 有真实发布或执行结果 | 该案例发生过，结果可对账 | 该方法导致了结果 |
| `[相关性待验证]` | 完整样本中反复出现同向关系 | 观察到稳定关系，值得继续押注 | 已证明因果、对所有平台都成立 |
| `[待验证]` | 方法假设、经验判断、筛选案例总结 | 当前默认怎么做、何时复核 | 冒充规律或统计事实 |

每条公理使用固定格式：

```markdown
### 公理 N：<一句可执行判断> `[证据等级]`

- 来源：<预测卡、账本观察、完整样本统计或方法假设>
- 反例：<什么情况会推翻或限制它>
- 复核：<积累到什么证据、何时重新判断>
```

真实结果是 outcome ground truth。除非有能排除平台分发、发布时间、账号状态和热点等混杂变量的设计，不写因果结论。

## 4. 世界观与认知锚

开篇先给一句有动作倾向的世界观，再立刻标证据等级。世界观用于约束默认姿态，不能靠无源数字制造权威。

数字认知锚只有同时满足以下条件才放行：

1. 来自同一平台、同一内容形态。
2. 覆盖最近 90 天内不少于 30 张完整复盘卡。
3. 样本包含符合口径的全部结果，不能只挑成功案例。
4. 同时写样本量、时间窗、平台、指标口径和基线定义。
5. 只描述分布或相关性，不把结果差异写成因果。

不满足时写「认知锚待验证」，保留案例观察，不输出命中率、失败率或稳定百分比。

## 5. Phase 状态机

每个 Phase 写清输入、动作、退出条件和一句能直接念出口的钉子台词。需要用户决定时强制暂停；不需要决定时不要制造多余问答。

```markdown
## Phase N：<阶段名>

钉子台词：「<一句话>」

- 输入：<本阶段只读什么>
- 动作：<检测或生成动作>
- 退出：<进入下一阶段的可观察条件>
- 暂停：<是否等待用户，以及用户需决定什么>
```

诊断类 Phase 优先给检测三件套：检测方法、正反示例、带占位符的可说话术。

## 6. 案例与渐进披露

把长案例放进同 skill 的 `references/` 或案例库文件，`SKILL.md` 只写何时读取。案例至少记录：

```markdown
- 案例 ID：<稳定 ID>
- 证据等级：<[结果已验证]|[相关性待验证]|[待验证]>
- 来源状态：<预测卡路径|历史回填且未关联卡|外部种子>
- 平台与时间窗：<已知则写；未知写未记录>
- 真实结果：<有则写>
- 基线与口径：<有则写>
- 可迁移机制：<只描述观察，不写因果>
```

筛选后的成功案例只能作为 few-shot 和机制候选，不能计算方法命中率。编号只增不改，删除后不复用。

## 7. State 与转介契约

列出本 skill 读取、写入和禁止读取的状态。涉及盲评时，把含实绩的状态与评分输入硬隔离。

转介优先输出结构化 handoff，不自动创建持久化文件：

```yaml
liang_handoff:
  from: liang-<source>
  <task_state>: <value>
  evidence_level: <level>
  next: liang-<target>
```

目标 skill 必须声明允许消费哪些字段、哪些字段不得继续传给子代理或评分器。handoff 缺字段时只补问缺失字段，不重跑已完成阶段。

## 8. Refusals

每条拒绝包含用户可能说的原话、拒绝理由和正确去向：

```markdown
- **「<触发原话>」** → 拒绝 <动作>。<为什么会污染、失真或越界>；改走 /liang-<skill>。
```

只拒绝会破坏工作流有效性的动作，不把个人偏好写成禁令。

## 9. 验证契约

为 skill 指定可重复验证：

- 静态验证：frontmatter、必需章节、引用文件、枚举和结构 ID。
- 行为场景：正常输入、缺输入、边界输入、拒绝路径和转介路径。
- 数据验证：对账窗口、评价指标、朴素基线和留出集。
- 防污染验证：确认实绩、档位、倍率和历史标签没有进入盲评输入。
- 推广闸门：试点真实任务通过后再复制到其他 skill，不用同一批历史样本同时调规则和报成绩。

最终只声明已被验证的维度。协议存在不等于每次执行成功，对账成立不等于因果成立。
